# 보존 자료와 호환 입력

현재 업무는 최신 조회와 통합 기록을 사용한다. 이 참고는 기존 연결·원칙 과거본·적용 snapshot을 읽거나 편집할 때만 사용한다. 호환 입력의 존재가 새 필수 관계나 과거 자료의 현재 승격을 뜻하지 않는다.

`entity_id`는 `entity_ids` 전환 전 단일 대상 입력·첫 대상 projection으로 유지한다. 새 요청은 배열을 사용한다. 둘을 동시에 보내면 일치해야 하며 충돌은 거부된다. 새 backend에서 단일 대상 수정의 null은 명시 해제다. 보존된 삭제 대상의 문맥은 현재 접근 권한으로 사용하지 않는다. source=legacy_backfill은 전환 시점의 현재 이름 캡처이며 당시 실제 이름을 보증하지 않는다.

현재 원칙 원문은 `get_current_principle`과 현재 ID의 `get_principle`로 확인한다. `list_principles(view=history|all)`과 `correct_principle`은 보존된 옛 독립 원칙 자료의 조회·표현 정정에 사용한다. 정정은 저장 시점·현재 여부를 바꾸지 않으며 이 legacy 정정의 별도 메모 계약을 따른다. `origin=legacy`와 `legacy_context`를 새 현재 문서의 일부였다고 재해석하지 않는다. 검색의 과거 원칙 view도 기존 보존 자료를 위한 호환 범위다. 새 원칙의 과거 판단은 통합 기록에서 찾는다.

기존 `applied_principle_ids`는 호환 입력이다. 정정에서 생략하면 기존 캡처를 유지하고 빈 배열은 삭제된 원칙의 캡처도 제거한다. 같은 저장본의 연결은 캡처를 유지한다. 반환된 `applied_principle_snapshots`는 당시 문맥이며 원칙 이후 변경·삭제가 이를 현재 값으로 교체하지 않는다. application은 기능 도입 후 연결 시점, migration은 이관 당시 캡처로 과거 실제 적용 원문을 보증하지 않는다. 신규 자료는 필요할 때 본문에서 원칙을 인용한다.

태그는 entity/activity 사전이 분리된다. 관련 태그로 조회할 때는 각 scope를 구분한다. 활동의 tag_ids 필터는 OR이며 페이지 분할 전에 적용된다. 원칙에는 새 태그·엔터티 연결을 만들지 않는다. 삭제 영향·버전·request_id는 실제 연결된 도구 계약을 따른다.
