[PR #288](https://github.com/kimyongin/agent-workspace-template/pull/288)은 열린 선행 [PR #275](https://github.com/kimyongin/agent-workspace-template/pull/275)의 branch를 base로 사용한다. main 반영이나 머지 완료가 아니다. 기존 통합 증거는 workspace-screens 전체 269 passed/0 failed/0 skipped/0 flaky를 5201c79에서 확인한 뒤 Collection/fixture 포맷의 AST·표시 JSX·주석 의미 동등성과 발견 목록 보존으로 재사용 판단한 것이다. 뒤의 boundary globalThis 금지 복원은 브라우저 동작에 영향이 없어 해당 E2E를 재사용했다. 다른 격리 suite와 실제 API/Pinecone E2E는 누적 변경의 호출 경로에 영향이 없어 생략했다.

기존 [f73ecf8 CI](https://github.com/kimyongin/agent-workspace-template/actions/runs/38034867327)의 check/integration 성공은 격리 DB/HTTP/MCP 증거이며 브라우저 검사 대신 사용하지 않았다. 기존 독립 Standards/Spec 리뷰의 구현 불일치 미해결 0과 관련 core47/adapter32/web91·build·scripts70pass+1skip은 이전 통합 변경의 증거다. 이번 평가 문서까지 포함한 최종 revision의 독립 리뷰·필수 CI·ready/merge 상태는 [PR #288 checks](https://github.com/kimyongin/agent-workspace-template/pull/288/checks)와 연결된 이슈 댓글이 소유한다. 이 보고서 작성 시 최종 리뷰/CI는 pending이며 이전 성공을 새 revision의 성공으로 표시하지 않는다. Closing refs는 머지 시 해당 이슈를 닫는 의미이며 문서 작성만으로 닫힘을 주장하지 않는다.

이번 T1/T10 산출물은 Markdown과 안전한 JSON 요약뿐이다. 제품 동작·DOM·이벤트·인증·API 호출 경로를 변경하지 않아 이 문서 commit 자체의 브라우저 E2E는 생략한다. 누적 구현 E2E 판단은 위 통합 증거를 따른다. 원본 tdd의 적용 대상은 test-first 기능·버그·integration test 작업이며, 이번 문서 측정 결과 기록에는 새 제품 테스트나 seam을 만들지 않았으므로 red/green 적용 대상이 아니다. Writing-for-agents 정본의 문맥·근거·완료 조건 구분을 적용했다. 문서 checker·JSON 구조/해시/24개 완결성 검사·diff 공백 검사로 산출물을 검증한다.

## 재현과 보존

원자료: `/private/tmp/agent-efficiency-20261010/paired-runs/<run>/`. 24개 events/result/environment/prompt/diff/status와 생성한 test/plan/harness/log/screenshot/trace는 외부에 보존했다. 실제 계정·비밀 환경·node_modules/cache는 보존 대상으로 넣지 않았다. 삭제된 임시 harness는 최종 사본 또는 harness.log 원문으로 보존했다. 기준 Git revision에 final.diff를 적용하고 created-files를 대응 경로에 복원하면 국소 결과와 검증 설정을 재구성할 수 있다. 일부 harness의 원래 위치 복사 조건은 해당 verification 문서에 있다. 개발 의존성과 브라우저 runtime은 별도 준비가 필요하며 node_modules를 artifact에 넣지 않는다.

실행별 원자료 파일·created-files-manifest와 공통 환경/환경 audit의 SHA-256을 summary에 남겼다. Runner hash와 observable 환경 일치 검토는 외부 paired-environment-audit.json에 있다. 모든 24개 환경 파일의 globalSnapshot pointer는 수집 후 provenance를 추가한 것으로 원시 events/result·최초 측정값을 바꾸지 않았다. 전체 주입 시작 문맥은 여전히 미관측이며 초기 두 snapshot의 시점 한계도 유지한다. 원시 로그·명령 전문·화면·trace는 저장소에 포함하지 않는다.
