**Finding 1 — Missing ownership check (Authorization bypass)**
- **File/line:** `review.mjs:3–5`
- **Defect:** There is no check that `actorId === task.ownerId`. Any authenticated actor can complete any task they know the `id` of.
- **Impact:** Broken access control — the contract "task access is owner-only" is entirely unenforced.
- **Test:** Call `completeTask(db, 'intruder', task.id, task.revision)` where `task.ownerId !== 'intruder'`; the function succeeds instead of throwing (e.g. `forbidden`).

---

**Finding 2 — Stale-revision check is before the guard, not atomic with the write**
- **File/line:** `review.mjs:5–6`
- **Defect:** `db.update` has no conditional version predicate (stated in the contract). The optimistic-concurrency check on line 5 is a plain in-memory comparison, and `db.update` on line 6 is an unconditional overwrite. Between the check and the write, a concurrent call can increment `task.revision` in the store. The stale check then passes (both callers read the same original revision), and the second writer silently overwrites the first.
- **Impact:** Lost-update / concurrent-write data race — a concurrent completion from another request is silently destroyed.
- **Test:** Concurrently call `completeTask` twice with the same `(id, expectedRevision)`. Both should throw; the second must get `conflict`. Instead both succeed and one update is lost.

---

**Finding 3 — `db.update` and `db.appendActivity` are not atomic**
- **File/line:** `review.mjs:6–7`
- **Defect:** `db.update` writes `status: 'done'` and increments the revision (line 6). If `db.appendActivity` then throws (line 7), the task is permanently marked done with no `completed` activity record. There is no rollback. The contract requires both commit or neither commits.
- **Impact:** Data inconsistency — task appears done but the audit trail is missing; any downstream logic that checks for a `completed` activity event will fail silently.
- **Test:** Make `db.appendActivity` reject (e.g. throw `Error('db_error')`). Verify that after the rejection the task's `status` in the store is still `'open'` (or original). Currently it will be `'done'` with no activity row.

---

**Finding 4 — Return value exposes the pre-update snapshot, not the persisted new revision**
- **File/line:** `review.mjs:8`
- **Defect:** `{ ...task, status: 'done' }` spreads the object fetched before the write. It returns `revision: task.revision` (the old value) rather than `task.revision + 1` (the value actually written to the store). The contract says "return the persisted new revision."
- **Impact:** The caller receives a stale revision. Any subsequent call using the returned revision as `expectedRevision` will immediately get `conflict`, breaking normal optimistic-concurrency retry flows.
- **Test:** Call `completeTask`; assert `result.revision === originalRevision + 1`. Currently `result.revision === originalRevision`.
