# ADR-0027: 항목 기반 식별자와 공간 범위 자료 키

- 상태: 채택. 구현·통합 검증은 [#543](https://github.com/kimyongin/agent-workspace-template/issues/543), 저장 키 전환은 [#551](https://github.com/kimyongin/agent-workspace-template/issues/551), 초기화 실행안은 [#557](https://github.com/kimyongin/agent-workspace-template/issues/557)에서 구분한다.
- 날짜: 2026-10-22
- 승인 근거: 식별자 항목·자료 식별자 지정에 대한 대화 합의, 공간 복합 PK 지시, 기존 자료 삭제 허용과 비백로그 티켓 전체 진행 지시.
- 대체 범위: [ADR-0021](0021-type-scoped-immutable-identity.md)의 일반 항목 밖 식별 정보·출처당 규칙 하나·출처 기반 자료 키, [ADR-0024](0024-entity-relations-and-data-model.md)의 종류별 독립 식별 설정 교환. 불변 정체성·명시 연결/복원·전체 모델의 원자적 확정은 유지한다.

여러 마켓의 상품·주문·판매자 번호를 같은 업무 구조로 관리한다. 같은 출처에서도 상품 번호와 주문 번호는 다른 식별자 종류다. 한 자료에는 이들 번호를 여러 항목에 담을 수 있고, 상품 그룹·주문품목의 의미는 명시 관계로 표현한다. [원래 사용 사례](../design/identifier-foundation-concept.md#1-목적-출처를-보존하면서-같은-업무로-관리한다)는 설계 변경을 평가하는 근거로 유지한다.

식별자 항목은 식별자 종류의 불변 ID와 원본 문자열 한 쌍을 담는 일반 입력 항목이다. 한 항목은 여러 종류를 허용할 수 있다. 각 자료 종류는 그중 정확히 하나의 필수·활성·null 불가 항목을 자료 식별자로 지정한다. 선택한 항목의 값은 등록 후 불변이며, 다른 식별자 항목은 편집과 중복을 허용한다. 삭제된 자료도 정체성을 점유하고 서버 조회로 반환한 키·버전의 명시 복원으로 다시 사용한다. 같은 번호라는 이유만으로 자료를 연결하거나 병합하지 않는다.

자료 값의 정본은 `properties`, 항목 정책의 정본은 버전 JSON Schema의 `x-identifier`와 `x-identity-property`다. 독립 종류별 식별 설정·중복 구성 컬럼을 두지 않는다. 자료 참조 키는 `자료 종류 ID:식별자 종류 ID:원본 값`으로 파생하며 별도 자료 UUID를 추가하지 않는다. 원본의 앞자리 0·대소문자·구분자·Unicode를 보존한다. 자동 발급은 명시 의도로 요청하고 선택하지 않은 일반 항목에는 값을 발급하지 않는다.

독립 공통 식별 정보를 두던 결정은 단순한 스키마 변경과 불변 키를 분리하려는 선택이었다. 이번에는 여러 보조 식별자의 정책과 전체 모델 교환을 한 정의에서 다루기 위해 항목 안으로 통합한다. 그 대가로 선택 항목의 삭제·타입/값 변경·복구 우회와 사용 중인 종류 제거를 서버·DB 경계에서 막고, 검토 뒤 자료·규칙이 바뀌는 경쟁도 다시 확인한다. 자료가 없는 종류만 선택 항목을 바꿀 수 있으며 삭제된 자료도 이 판단에 포함한다.

전체 모델은 항목 정책과 선택 포인터를 함께 교환하고 필요한 출처·종류 정의를 의존 자료로 포함한다. 종류별 별도 식별 설정은 교환하지 않는다. 복사는 종류·속성·식별자 종류·관계·제목 참조를 함께 대응하고 시스템 앱 번호 종류를 재사용한다. 파일에서 빠진 정의를 삭제 지시로 해석하지 않는다.

자료 행의 실제 기본 키는 `(workspace_id, id)`이며 공간 소속은 필수다. 관련 자료 모델의 FK도 같은 공간 경계를 가진다. 정체성과 업무 권한을 과거 작성자 한 명이나 전역 자료 키의 유일성에 의존하지 않는다.

최초 전환은 명시한 기존 자료·호환 불가 정의와 관련 참조·작업·검색을 한 계획으로 정리한다. 계정·인증·개인 설정·공간·참여·권한·호환 번호 정의와 무관한 업무 이력은 보존한다. 보존할 권한이 가리키는 정의의 삭제 등 충돌은 계획 단계에서 거절한다. 자동 초기화와 자료 보존 이관 엔진을 도입하지 않으며, 실제 운영 적용·배포는 이 결정이나 구현 완료와 별도다.
