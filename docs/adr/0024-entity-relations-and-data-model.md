# ADR-0024: 역할이 있는 자료 관계와 전체 자료 모델 교환

- 상태: 채택, 구현·검증은 [스펙 #482](https://github.com/kimyongin/agent-workspace-template/issues/482)
- 날짜: 2026-10-17
- 승인 근거: 범용 Workspace 활용성 검토에서 관계 의미·개수, 별도 관계 설정, 작성하고 연결, 전체 모델 교환과 개발 진행을 합의했다.

자료 종류별 JSON Schema만으로는 주문품목의 소속 주문과 SKU의 마켓 판매옵션처럼 연결의 역할과 개수를 설명할 수 없다. 관계 정의는 종류 하나의 속성이 아니라 두 종류 사이의 약속이므로 별도 자료 관계 설정에서 관리한다. 독립 공간·멀티 테넌시와 필수 관계는 추가하지 않는다.

관계 정의는 불변 ID·독립 버전과 양쪽 자료 종류·표시 이름·단일/복수·보관 상태를 가진다. 단일은 0~1, 복수는 0개 이상이며 역할은 양쪽에서 명시적으로 구분한다. 같은 종류끼리도 다른 역할을 표현하며 같은 두 종류 사이의 다른 의미를 하나로 합치지 않는다. 실제 연결은 정의 ID와 역할별 자료를 참조하고 양쪽 단일 조건을 서버에서 함께 보장한다. 자료↔자료 연결은 명시적으로 설정한 관계를 통해서만 허용한다. 이 결정은 ADR-0020의 일반 연결 방침을 대체한다.

2026-10-17 추가 지시로 기존 일반 연결을 함께 제공하던 초기안을 폐기했다. 일반 연결 화면·API·MCP와 미사용 호출자는 제거하고 과거 일반 연결 원본·변경 기록·당시 문맥은 보존한다. 기존 연결에 의미를 자동 배정하지 않는다. 할 일·기록에서 자료를 업무 대상으로 지정하는 계약은 이 자료↔자료 관계와 구분한다.

자료 상세는 단일 값과 복수 목록을 구분하고 기존 자료 연결·단일 교체·해제와 새 자료 작성 후 연결을 제공한다. 작성하고 연결은 자료 생성·연결·필요한 교체·변경 기록을 한 업무 쓰기로 확정한다. 연결되지 않은 자료 생성과 마지막 연결 해제도 허용한다. 삭제·보관 상대의 기존 연결은 유지하고 단일 자리를 점유하며 명시 해제·교체로 정리한다.

교환 단위는 전체 자료 종류 정의·관계 정의와 필요한 식별자 의존 설정을 담은 자료 모델 하나다. 기존 종류의 JSON Schema 원문을 보존하는 JSON 묶음을 사용하고 그 묶음도 JSON Schema로 검증한다. SHACL/RDF나 별도 모델링 언어로 종류 정의를 재작성하지 않는다. ADR-0023의 단일 종류 가져오기 단위는 이 전체 모델 경계로 대체하되 종류별 편집과 불변 게시·키·변환/복구 보장은 유지한다.

가져오기는 기존 모델 반영과 새 종류·관계 복사를 구분한다. 불변 ID·파일 내 참조를 대응하며 이름만으로 다른 정의를 합치지 않는다. 복사는 새 종류·속성·관계·필요한 번호 정의의 참조를 함께 다시 연결하고 시스템 앱 정의를 재사용한다. 파일 원본 버전은 대상 덮어쓰기 권한이 아니며 빠진 정의를 삭제 지시로 해석하지 않는다. 실제 업무 자료·개별 연결·활동 기록의 이식은 모델 교환 범위가 아니다.

여러 종류의 변경을 검토·준비한 뒤 일관된 전체 모델로 확정한다. 긴 값 변환은 영속 준비 작업을 사용하며 종류별 작업을 차례대로 확정해 부분 적용을 전체 성공으로 표시하지 않는다. 실패·경쟁·응답 불명은 같은 변경안과 원래 입력으로 확인한다. HTTP와 MCP는 동일한 core 경계·소유권·요청 재현·원자적 기록을 사용한다.

자료당 일반 연결 100개 상한 제거를 다루던 [#481](https://github.com/kimyongin/agent-workspace-template/issues/481)은 일반 연결 폐기로 대체한다. 정의된 복수 관계에는 저장 총수 상한을 추가하지 않으며 기존 페이지 조회를 유지한다. 이 결정의 채택과 개발 승인은 운영 DB 초기화·운영 적용·배포 승인을 뜻하지 않는다.
