# ADR-0012: 최신 상태와 메모 기반 통합 기록

- 상태: 채택
- 날짜: 2026-10-05
- 승인 근거: [백엔드 명세 #110](https://github.com/kimyongin/agent-workspace-template/issues/110)과 [프론트엔드 명세 #111](https://github.com/kimyongin/agent-workspace-template/issues/111)의 설계 대화. 사용자는 마지막에 일반 기록 무로그 편집과 로그성 기록의 메모 편집에 동의했다.

## 배경

사용자는 모든 도메인이 최신 값을 관리하고, 이력을 기록에 통합해 에이전트에게 RAG으로 전달하기를 원한다. 기존 활동 화면의 할 일/기록 묶음, 원칙 과거 저장본 및 적용 snapshot, 모든 기록 편집의 추가 로그는 이 의도와 차이가 있다. 설계 중 제안한 불변 로그와 정정 연결도 메모 오류를 고치는 용도에 비해 복잡했다.

## 결정

- 엔터티·할 일·원칙은 최신 상태의 정본이다. 업무 자료·수행 결과와 도메인 변경 메모는 통합 기록에 남긴다. 일반 기록도 최신 내용은 편집할 수 있다.
- 기록은 본문 하나로 작성한다. 전체 내용과 변경점 중 어느 정도를 남길지는 메모 내용으로 표현하며 별도의 snapshot/diff 모드를 강제하지 않는다. 기록이 담지 않은 과거 전체 상태의 복원을 보장하지 않는다.
- 일반 기록 편집은 추가 로그를 생성하지 않는다. 로그성 기록의 메모도 편집할 수 있으며 그 편집의 추가 로그를 생성하지 않는다. 발생 시각·대상·행동 등 사건 식별정보는 보존한다. 별도 정정 기록·정정 체인과 불변 메모는 요구하지 않는다.
- 업무 변경의 기본 메모는 저장 전에 확인 가능한 사실로 자동 완성하고 사용자/에이전트가 보충·수정한다. 최종 메모와 업무 변경은 함께 확정하고 동일 요청 재시도는 중복 기록을 만들지 않는다. 기록 내용 편집은 색인을 최신화한다.
- 서술은 본문으로 남긴다. 필요한 원칙 참고도 본문 설명으로 충분하며 의무 입력·원칙 적용 연관키를 요구하지 않는다. 정확 조회와 수행 회차 판정에 쓰이는 식별정보만 구조화한다. 식별정보 보존은 FK/관계 테이블 도입과 별개다.
- 할 일·일반 기록은 엔터티 여러 개에 선택적으로 연결할 수 있다. 참고 자료는 기본적으로 본문 인용/링크로 표현하고 수행 결과 관계와 구분한다. 대상 삭제 뒤에도 과거 기록의 문맥을 보존한다.
- 최신 상태는 해당 도메인 조회로 확인하고, 과거 내용과 근거는 통합 기록 RAG으로 회수한다. 원칙은 현재 문서 0~1개를 관리하고, 과거 변경은 기록에서 확인한다. 삭제 후 과거 원칙을 자동 승격시키지 않는다.
- 상위 탐색은 [ADR-0020](0020-typed-entity-schema.md)과 #343의 프로필+사용자 지정 자료/업무 바로가기 합의로 대체한다. 기존 2026-10-06 #156의 고정 네 탭 결정은 과거 근거다. 기록과 활동은 같은 화면이며 화면 명칭은 기록으로 통일한다. 일반 기록 작성/편집은 같은 탭의 폼/모달에서 진행한다. 기록 화면에는 업무 사건을 모으며 조회·검색·화면 이동 로그는 포함하지 않는다.

## 결과

에이전트가 과거 근거를 회수하는 경로가 하나가 되고, 현재 상태와 기록의 책임이 명확해진다. 기록은 편집 가능한 지식 자료이므로 최초 메모의 불변 보존이나 모든 과거 상태 재구성을 제공하지 않는다. 기존 원칙 저장본·적용 자료와 단일 엔터티 관계의 이관, API 및 화면 전환이 필요하다.

이 ADR은 목표 계약이며 앱 구현 완료를 뜻하지 않는다. 기존 자료를 버리지 않고 기록으로 보존하는 이관안을 검증한 뒤 구현한다. 헥사고날 구조·사용자 격리·공통 HTTP/MCP 업무 기능·트랜잭션과 큐·내용 입력과 검색은 [ADR-0014](0014-minimal-content-model.md)가 대체한다. 할 일·원칙은 제목·본문, 기록은 본문 하나이며 입력 변경 메모 또는 빈 메모의 기본 설명을 한 번에 저장한다. 기록 본문을 구간별로 임베딩하고 최신 업무 값은 별도 조회한다. 물리적 저장·API·이관 실행은 구현 티켓과 검증 근거로 관리한다.
