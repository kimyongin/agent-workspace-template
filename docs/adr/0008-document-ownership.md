# ADR-0008: 문서 소유권 — 사람은 PRD·ADR, 에이전트는 나머지

- 상태: 채택 (티켓 위치·승인·이탈 확인은 [ADR-0011](0011-matt-skills-and-github-workflow.md), 기존 머지 절은 [ADR-0010](0010-merge-authority.md)으로 대체)
- 날짜: 2026-10-01

## 배경

이 템플릿은 초보자도 에이전트와 함께 앱을 만들 수 있어야 한다. 모든 변경을 사람이 확인하면 느리고, 반대로 에이전트가 방향까지 바꾸면 잘못된 방향으로 오래 진행한 뒤 되돌리게 된다. 사람이 확인할 대상을 "무엇을, 왜 만드는가"로 좁힌다.

## 결정

### 소유권

> 티켓의 위치와 이미 합의한 결정의 문서 반영은 [ADR-0011](0011-matt-skills-and-github-workflow.md)을 따른다. PRD·ADR의 사람 소유권은 유지한다.

| 문서 | 소유자 | 위치 |
| --- | --- | --- |
| PRD(제품 요구사항) | 사람 | `docs/product/` |
| ADR(아키텍처 결정) | 사람 | `docs/adr/` |
| 티켓·구현·테스트·리뷰 | 에이전트 | `docs/tickets/`, 코드 |
| 가이드(디자인·구조·개발·보안 세부·배포·운영)·스킬 | 에이전트 | `docs/` 나머지, `.agents/`, `plugins/` |

소유권은 결정 권한이다. 에이전트는 PRD·ADR 초안을 쓸 수 있지만 채택·변경은 사람이 승인한다. 가이드는 에이전트가 일관되게 작업하기 위한 수단이며, PRD·ADR을 벗어나지 않는 범위에서 에이전트가 PR로 변경한다.

### 분류 기준

어떤 내용이 어느 문서에 속하는지 애매하면 다음 순서로 판단한다.

| 질문 | 예이면 |
| --- | --- |
| 사용자에게 보이는 제품의 의미·범위가 바뀌는가? | PRD |
| 바꾸면 되돌리기 비싼 구조·기술·보안 경계가 바뀌는가? | ADR |
| 같은 결과를 더 일관되거나 효율적으로 만드는 방법인가? | 가이드 |

### 이탈 확인

> 승인된 합의의 문서 반영과 새 이탈의 승인 구분은 [ADR-0011](0011-matt-skills-and-github-workflow.md)로 대체했다.

에이전트는 티켓 작성·구현·리뷰 때 관련 PRD·ADR과 일치하는지 확인한다. 벗어나야 하면 작업을 멈추고 이유와 대안을 담은 PRD 변경안 또는 ADR 초안(상태 `제안`)으로 사람의 승인을 받는다. 승인 전에는 이탈하는 구현을 머지하지 않는다.

### 머지

> 이 절은 [ADR-0009](0009-review-without-cross-agent.md)로 대체되었고, ADR-0009는 [ADR-0010](0010-merge-authority.md)으로 대체되었다.

PRD·ADR을 바꾸지 않고 벗어나지도 않는 변경은 다른 에이전트의 교차 리뷰와 자동 검사를 통과하면 에이전트가 머지한다. PRD·ADR을 바꾸는 PR은 사람이 승인한다.

### 실행 예외

다음은 문서 소유권과 별개로 사람이 요청하거나 승인한 범위에서만 실행한다: 운영 배포, 운영 DB 적용, 비용이 드는 서비스 생성, 비밀값 교체·폐기, 운영 데이터 복원.

## 결과

- 사람은 PRD·ADR과 이탈 질문, 배포 지시에만 개입한다. 나머지 작업은 에이전트가 끝까지 진행한다.
- 결정이 PRD·ADR에 모여 있어야 에이전트가 이탈을 판단할 수 있다. 가이드에 섞인 결정 문단은 ADR 링크로 옮긴다.
- 기존 개발 방법의 "기준 자체를 바꾸면 정본을 함께 갱신한다" 규칙은 가이드에만 적용하고, PRD·ADR의 변경은 이 ADR의 승인 절차를 따른다.
