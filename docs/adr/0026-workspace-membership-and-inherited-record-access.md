# ADR-0026: 워크스페이스 참여와 연결 대상에 따른 기록 권한

- 상태: 설계 채택, 구현·검증은 [스펙 #511](https://github.com/kimyongin/agent-workspace-template/issues/511)
- 날짜: 2026-10-18
- 승인 근거: 이 날짜의 대화에서 다른 사용자의 워크스페이스 참여, 자료 종류별 권한, 관리자 최소 1명과 기록의 소속 대상 권한 상속을 합의했다. 기록은 일반·단독 기록을 없애고 자료 하나 또는 할 일 하나에만 속하며 옮길 수 없는 것으로 최종 확정했다. 나머지 제안의 채택 범위는 [PRD](../product/concept.md#워크스페이스와-참여)에 기록한다.

개인 소유자별 데이터 격리에서 워크스페이스별 데이터 격리와 참여자별 권한으로 확장한다. 업무 데이터의 소속과 작업한 사람을 구분해 참여자의 탈퇴가 공동 데이터의 삭제로 이어지지 않게 한다. 같은 사용자가 여러 워크스페이스에서 서로 다른 권한으로 참여할 수 있다.

고정 역할 묶음 대신 자료 종류·할 일·설정에 접근 권한을 부여한다. 관리자는 설정 쓰기 권한을 가진 참여자를 뜻하며, 워크스페이스가 존속하는 동안 실제 관리 가능한 참여자를 최소 1명 유지한다. 권한 조합이 늘어나더라도 각 업무 영역에 필요한 접근 범위를 직접 표현하기 위한 선택이다.

권한 검사는 기존 공통 업무 실행 문맥에 모으고 DB의 같은 권한 판정을 서버 사전 검사·RLS·화면 조작 가능 정보에 재사용한다. 기록은 저장된 소속으로 권한 대상을 해석하며, 저장 성공 응답 재현 전에도 현재 권한을 검사한다. 권한 변경과 업무 실행의 경쟁 및 관리자 최소 인원 보호는 같은 저장 문맥에서 검증한다. 이 공통 모듈을 [첫 티켓 #512](https://github.com/kimyongin/agent-workspace-template/issues/512)의 최우선 작업으로 두고 기능별 호출자를 전환한다. 구체적인 인터페이스·잠금·검증 조건은 스펙이 소유한다.

기록은 같은 워크스페이스의 자료 하나 또는 할 일 하나에만 속하며, 자료·할 일 하나에는 기록을 여러 개 남길 수 있다. 소속은 생성 시 확정하고 변경·이동할 수 없다. 별도 기록 권한을 두지 않고 소속 대상의 현재 읽기·쓰기 권한을 적용한다. 자동 변경 기록과 할 일 결과 기록은 원본 업무의 쓰기 권한으로 생성한다. 복수 대상의 권한 결합과 연결 해제 이력을 유지하는 구조 대신, 업무 대상의 소속과 권한을 일치시켜 접근 검사를 단순하게 한다.

일반·단독 기록은 제공하지 않고 메모·문서 같은 직접 작성 내용은 자료 종류를 만들어 관리한다. 기록의 소속 연결 해제는 기록 삭제로 처리한다. 원본을 소프트 삭제하면 기록의 소속과 그 권한 기준은 유지한다. 이 결정은 ADR-0012와 ADR-0014의 일반 기록·선택적 연결 범위를 대체하며 결과·변경 메모의 편집과 사건 정보 보존 규칙은 유지한다.

할 일과 그 기록은 할 일 권한으로 공유하며, 연결 자료의 이름·속성 표시는 자료 종류의 읽기 권한으로 검사한다. 할 일 본문에 직접 작성한 내용은 할 일의 공유 내용이다. 자료 종류에서 검색할 텍스트 입력 항목을 지정해 자료 본문도 의미 검색에 포함하고, 자료 검색에는 해당 종류의 현재 읽기 권한을 적용한다. 이 검색 범위 결정은 ADR-0014의 기록 본문 한정 범위를 확장한다.

참여는 관리자 이메일 초대와 Google OAuth 로그인·명시적 수락으로 확정한다. 서버가 검증한 OAuth 이메일·이메일 검증 상태를 초대와 대조하며, 누락·미검증·불일치는 거절한다. 별도 이메일·비밀번호 가입은 필요하지 않다. 수락 후 멤버십과 권한은 이메일이나 Google 제공자 sub가 아닌 애플리케이션 사용자 ID(Supabase Auth user ID)로 관리하고 (workspace_id, user_id)의 유일성을 보장한다. 같은 사용자 ID의 이메일 변경은 참여를 유지하며 동일 이메일의 다른 사용자 ID에 기존 권한을 자동 승계하지 않는다. 워크스페이스 삭제는 관리자만 할 수 있으며 초기에는 복원 가능한 소프트 삭제로 제공한다. 기존 업무 데이터는 모두 테스트용이므로 삭제를 허용하고 이관하지 않기로 합의했다. 일반 기록 변환이나 복수 연결의 소속 추정 엔진은 만들지 않으며 전환 시 초기화 대상과 검색 파생 데이터를 함께 확인한다.

웹·MCP·검색·백그라운드 처리와 저장 경계에 같은 워크스페이스·권한 문맥을 적용한다. 이 결정은 ADR-0006의 소유자 본인 한정 접근과 ADR-0024의 멀티 테넌시 제외 범위를 확장한다. 로그인·MCP 인증 분리와 비신뢰 자료 처리 규칙은 유지한다. 기존 테스트 업무 데이터 초기화는 승인 범위에 포함하며 계정·인증·비밀값·서비스 설정은 보존한다. 문서 채택은 구현·데이터 초기화·배포 완료를 뜻하지 않으며 배포 실행은 별도 지시 범위를 따른다.

태그 연결은 데이터 연결과 같은 독립 업무 동작으로 정리한다. 자료·할 일·수행 결과의 신규 작성과 내용 편집에는 태그 선택·연결 저장을 넣지 않고, 저장된 대상의 보기에서 별도의 태그 연결·해제로 관리한다. 웹·HTTP·MCP에 같은 연결 계약을 제공하며 일반 생성·수정의 `tag_ids` 입력은 제거한다. 태그 사전 관리와 자동 변경 기록의 고정 태그·기록 자동 완성 계약은 구분해 유지한다. 2026-10-18의 추가 지시가 기존 #503의 신규 작성 초기 태그 예외와 태그 부분 수정 API 재사용 방침을 대체하며, 구현·검증은 #511의 관련 기능 티켓에서 수행한다.
