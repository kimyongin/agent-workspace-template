# ADR-0019: 테이블 PK 기반 서버 ID 생성

- 상태: 채택
- 날짜: 2026-10-11
- 승인 근거: 발급 이력 원장 없이 PK로 충돌을 막고 삭제 후 재발급 가능성을 받아들이기로 한 사용자 대화 합의, [#297](https://github.com/kimyongin/agent-workspace-template/issues/297)

## 배경

요청 키는 업무 요청의 중복 실행을 막는다. 별도 ID 발급 원장은 모든 모델의 전역 유일성과 삭제 후 영구 재사용 금지를 보장하지만 사용자에게 필요한 범위를 넘어 지속적으로 증가한다.

## 결정

- 날짜형 ID 형식과 기존 UUID·업무 데이터·참조를 유지한다. 서버가 저장 트랜잭션에서 순수 난수 후보를 만든다.
- 자동 ID 충돌은 받는 테이블의 PK로 검사하고 최대 64회 재발급한다. 소진하면 `unavailable`로 업무·기록·큐·요청 결과를 전부 롤백한다. 다른 업무 unique 제약·권한 오류는 그대로 실패하며 임의 재발급으로 숨기지 않는다.
- 자동 엔터티는 실제 owner/발급처/식별자 PK에서 충돌을 처리한다. 명시 외부 식별자는 입력값과 중복/복원 계약을 유지한다.
- 새 변경 기록의 사건 식별자는 기록 ID를 사용한다. 기존 `event_id`는 수정하지 않는다.
- 테이블 간 전역 유일성·삭제 후 영구 재사용 금지를 보장하지 않는다. 과거 사건의 대상 ID는 현재 대상의 존재/동일성 보증이 아니다.
- 순방향 migration으로 ID 기본값을 순수 후보 함수로 전환하고 미사용 예약 allocator와 `private.data_id_reservations`를 제거한다. 과거 migration은 보존한다.
- 요청 키의 결과 재현·tombstone·외부 effect 수명은 변경하지 않는다. 운영 적용은 별도 지시 범위에서 수행한다.

## 결과

영구 발급 이력과 추가 쓰기가 사라진다. 같은 난수 ID가 테이블 사이 또는 삭제 이후 다시 사용될 수 있는 극히 드문 가능성을 받아들인다. 각 테이블의 PK는 현재 행의 중복을 막는다. schema와 writer를 함께 적용하며 제거된 예약 allocator를 사용하는 이전 writer로 단순 rollback하지 않는다.
