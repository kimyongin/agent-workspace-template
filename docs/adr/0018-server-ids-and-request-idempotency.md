# ADR-0018: 서버 내부 ID 발급과 요청·외부 작업 멱등성

- 상태: 채택. 구현·검증 증거는 [스펙 #289](https://github.com/kimyongin/agent-workspace-template/issues/289)에서 관리
- 날짜: 2026-10-11
- 승인 근거: 내부 ID의 서버 발급·저장, 요청 키 중복 방지, 외부 작업의 멱등 키·결과 관리까지 스펙과 티켓으로 정리하라는 사용자 대화 합의

데이터 ID 사전 예약은 생성 중복을 줄이지만 수정·삭제·외부 작업을 포함하는 요청 전체의 재실행과 이전 성공 결과를 설명하지 못한다. 내부 ID는 서버가 생성 트랜잭션에서 발급·저장하고, 호출자가 같은 논리 요청의 재시도 동안 유지하는 요청 키로 중복 처리를 방지한다. 업무 변경·변경 기록·필수 큐 등록·요청 성공 결과는 함께 커밋하며, 같은 키·같은 입력에는 이전 결과를 반환하고 다른 입력에는 충돌을 반환한다. 다른 요청의 동시 변경을 막는 expected_version은 유지한다.

외부 작업 의도는 로컬 변경과 함께 등록하고 커밋 후 실행한다. 외부 멱등 키와 접수 후 작업 ID를 구분해 상태·결과와 연결한다. 타임아웃은 결과 불명이며, 공급자의 결과 조회·멱등 재요청 또는 작업별 명시 정책으로 조정한다. 외부 기능이 없을 때 중복 실행·비용을 완전히 방지한다고 보장하지 않는다.

ADR-0017의 날짜 기반 ID 형식·기존 자료 보존은 유지한다. 서버 내부 충돌 처리는 [ADR-0019](0019-pk-based-data-id-generation.md)의 테이블 PK 기반 재시도를 따르며, 클라이언트 사전 예약과 충돌만으로 재시도를 마치는 계약은 이 결정으로 대체한다. 요청 원장과 외부 상태의 저장·수명 관리 비용을 받아들인다. 요청 성공 결과는 최대 1 MiB JSON으로 제한하며 22,000자 본문과 최대 100개 엔터티 문맥을 함께 반환하는 현재 형태를 지원한다. 무제한 과거 이력/snapshot의 초과 응답은 업무·기록·큐·원장을 원자적으로 롤백하며 모든 과거 응답을 지원한다고 보장하지 않는다. 기존 업무 입력을 줄이거나 과거 자료를 절단하지 않는다. 요청 성공 본문 30일·계정 존속 기간 tombstone·owner별 100,000개 한도와 passage effect별 최대 실제 전송 5회를 구현 계약으로 채택한다. 웹의 정확한 입력은 메모리에만 두며 MCP는 명시 키를 요구한다. 현재 Pinecone의 documented 멱등/조회 지원이 없어 unknown과 중복 과금 가능성을 보존한다. 구현·실제 통합 검증의 revision과 미검증 호스트 범위는 스펙 #289의 증거가 소유한다. 운영 DB 적용·서비스 배포·설치 갱신은 별도이며 이 결정의 채택으로 완료되지 않는다.
