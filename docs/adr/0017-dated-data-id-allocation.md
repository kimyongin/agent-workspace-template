# ADR-0017: 날짜 기반 앱 ID 예약과 기존 UUID 보존

- 상태: ID 형식·기존 자료 보존은 유지. 클라이언트 사전 예약·재시도 계약은 [ADR-0018](0018-server-ids-and-request-idempotency.md)로 대체. 구현·검증 revision은 [#289](https://github.com/kimyongin/agent-workspace-template/issues/289)에서 확인
- 날짜: 2026-10-10
- 승인 근거: 대화의 전체 데이터 ID 적용 합의, [#265](https://github.com/kimyongin/agent-workspace-template/issues/265)

## 결정

자동 발급되는 앱 데이터 ID와 엔터티 외부 식별자는 `YYYYMMDD-영문대문자숫자8자리`를 사용한다. 날짜 기준은 Asia/Seoul이다. 할 일·기록·원칙·태그·변경 사건을 포함하며 인증 공급자의 사용자 UUID·세션·UI 임시 키는 해당 계약을 유지한다.

암호학적 난수도 충돌할 수 있으므로 private 예약 원장의 PK로 중복을 차단하고 최대 64회 재시도한다. 소진하면 발급을 실패시키며 중복 ID를 반환하지 않는다. 예약 원장은 삭제하지 않는다. 현재 생성 트랜잭션 안에서 서버가 같은 예약 함수를 사용한다. 공개 HTTP/MCP 사전 발급과 준비에서의 ID 예약은 제거하며 클라이언트는 논리 요청의 UUID 요청 키·정확한 입력·대상·버전을 유지한다. 예약 이후 사용하지 않은 ID도 재발급하지 않는다.

기존 저장 UUID와 모든 참조는 보존하고 앱 ID·FK·검색 큐를 text로 전환한다. 기존 ID 읽기·쓰기 호환을 유지한다. 발급처 코드는 기존 기술 계약에 따라 이름과 분리된 불변 코드이며 사용자가 직접 입력하는 식별자는 자동 발급 형식을 강제하지 않는다.

## 대가

예약 원장은 지속적으로 증가한다. 발급 중복 금지와 삭제 후 이미 알려진 ID의 명시 생성 요청은 별개다. 내부 ID를 생성 입력으로 받지 않는다. 삭제 엔터티의 명시 외부 조합 복원에는 현재 버전과 새 요청 키를 사용한다.

새 형식이 저장된 이후 UUID 스키마로 단순 rollback할 수 없다. 운영 적용에는 앱·HTTP/MCP·검색 worker와 migration을 함께 반영하며, 복구는 명시적인 후속 migration으로 처리한다. 이 합의는 운영 적용이나 배포 실행 권한을 포함하지 않는다.
