# ADR-0003: 업무 규칙은 core, 일관성은 로컬 트랜잭션과 큐

- 상태: 채택 (소급 기록)
- 날짜: 2026-10-01

## 배경

할 일 완료처럼 여러 데이터를 함께 바꾸는 작업은 부분 저장이 없어야 한다. 검색 색인처럼 외부 호출이 필요한 후속 작업은 오래 걸리고 실패할 수 있다. 업무 규칙이 DB 프로시저와 코드에 이중으로 생기는 것도 피해야 한다.

## 결정

- 업무 판단(예: 완료 가능 여부)은 core의 도메인에 둔다. DB는 FK·UNIQUE·CHECK·RLS·권한·원자성을 담당하고 업무 상태 엔진을 프로시저로 구현하지 않는다. 인프라 함수와 보안 정책은 허용한다.
- 함께 성공해야 하는 변경은 서버 어댑터가 확보한 하나의 Postgres 트랜잭션으로 확정한다. 여러 supabase-js HTTP 호출을 트랜잭션처럼 취급하지 않는다.
- 무거운 후속 작업은 같은 DB의 pgmq 큐로 분리하고, 원본 저장과 큐 등록을 같은 트랜잭션에서 커밋한다. 외부 호출은 트랜잭션 밖에서 하며 재시도·멱등성·오래된 결과 거부를 작업마다 정한다.
- 일반 사용자의 업무 데이터 직접 쓰기(DML·RPC)는 막고 인증된 HTTP/MCP 경로만 허용한다.

## 결과

- 원본과 후속 작업이 함께 롤백되며 별도 메시지 브로커나 Outbox 테이블이 필요 없다.
- 직접 Postgres 연결에는 RLS 사용자 문맥이 자동 적용되지 않으므로, 트랜잭션 한정 문맥 전달과 연결 재사용 시 격리를 실제 DB로 검증해야 한다. 이 방식이 성립하지 않는 것으로 확인되면(Template-02 T02-1의 사전 검증) 대안을 담은 새 ADR로 대체한다.
