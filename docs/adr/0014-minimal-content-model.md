# ADR-0014: 요약 제거와 본문 하나로 쓰는 기록

사용자 원칙과 그 보존 계약은 [ADR-0022](0022-remove-user-principles.md)로 대체되었다. 아래의 해당 부분은 당시 결정의 배경이다.
- 상태: 채택
- 날짜: 2026-10-07
- 근거: 모델 속성 간소화에 대한 대화와 빈 변경 메모에는 기본 변경 설명을 남긴다는 사용자 답변. 구현 범위와 진행 상태는 [#166](https://github.com/kimyongin/agent-workspace-template/issues/166)이 소유한다.

템플릿 사용자가 제목·요약·본문과 별도의 변경 기록을 반복 작성하는 부담을 줄인다. 할 일과 원칙의 사용자 내용은 제목·본문으로, 일반·결과·변경 기록의 사용자 내용은 본문 하나로 통일한다. 엔터티에는 현재 예제 업무 속성을 유지한다. 기록의 ID·버전·시각·사건 식별정보와 필요한 관계는 본문과 구별되는 시스템 정보다.

업무 변경 시 입력한 메모가 있으면 그것만 기록 본문으로 저장한다. 비어 있으면 확인 가능한 사실로 기본 변경 설명을 생성한다. 기록 제목·요약을 추가하지 않으며 업무 데이터와 기록을 한 번에 저장하고 업무 변경과 기록은 같은 트랜잭션에서 확정한다. 삭제 의사 확인, 미저장 변경 보호, 같은 ID/version 재시도 의미는 유지한다. 기록 자체의 편집은 추가 로그를 만들지 않는다.

유사도 검색의 대상은 과거 기록의 본문이다. 엔터티·할 일의 최신 값을 별도로 임베딩하지 않는다. 이 데이터의 내용이 유사도 검색으로 발견되길 원하면 변경 메모에 그 내용을 포함해 기록으로 남긴다. 검색한 기록에서 필요한 대상의 최신 정보를 조회하고 당시 내용과 근거는 기록 본문에서 확인한다. 기존 사건 대상·수행 결과 관계나 필요한 본문 설명을 이용하며 이를 위해 원칙 적용 관계나 모든 데이터 간 새 연관키를 의무화하지 않는다. 키워드 검색의 범위와 구분한다. 기록 목록의 대표 문구는 본문에서 표시용으로 계산하며 별도 제목·요약 속성으로 저장하지 않는다.

2026-10-07의 추가 대화에서 본문 구간별 임베딩(청킹)을 채택했다. 기록 원문은 하나로 보존하고 검색 준비 과정에서 문단·문장 경계를 고려해 분할하며 인접 구간을 일부 겹친다. 짧은 기록은 한 구간으로 처리할 수 있다. 검색 결과는 구간별로 계산하되 같은 기록은 하나로 합쳐 반환하고, 일치 구간을 미리 보여준 뒤 기록 전체 원문을 조회한다. 구간은 원문에서 재생성 가능한 내부 색인 자료이며 사용자 편집 모델이나 AI 요약 생성 기능을 추가하지 않는다. 기록 수정·삭제 시 해당 색인을 교체·삭제하고 이전 본문의 구간이 최신 검색에 섞이지 않게 한다. 구간 크기·겹침·점수 집계는 실제 한국어 자료로 검증하는 기술 설정이며 사용자 결정으로 고정하지 않는다. 여러 벡터 저장으로 늘어나는 내부 색인 구조·처리량·공간은 원문 뒷부분까지 검색하기 위한 대가다.

ADR-0012의 기록 제목·요약·본문 및 저장 전 메모 확인 규칙과 ADR-0004의 제목+요약 검색 입력을 이 결정으로 대체한다. 소유자 격리·트랜잭션·큐·현재 상태와 통합 기록의 책임은 유지한다. 기존 제목·요약 중 본문에 없는 내용은 후속 migration에서 보존하고 폐기한 입력과 미리보기 인터페이스는 남기지 않는다. 이 결정 기록은 코드 전환이나 DB 적용 완료를 의미하지 않는다.

2026-10-07의 추가 합의([#181](https://github.com/kimyongin/agent-workspace-template/issues/181))로 웹의 저장 전 입력 위치를 변경한다. 업무 데이터 입력 뒤 작은 중앙 확인 단계에서 기본 설명을 채운 기록 메모와 별개의 기록 태그를 받는다. 확인 취소는 초안을 보존하며 같은 dialog의 단계 전환을 사용한다. 등록/수정/삭제/중단/재개의 기록 작성 방식과 삭제 이유 입력을 통일한다. 일반 기록 작성·기록 자체 편집은 추가 로그와 확인 단계를 만들지 않는다. 수행 결과 작성은 별도 변경 기록을 추가하지 않고 결과 본문·태그를 직접 저장한다. UI 확인은 웹 상호작용이며 MCP에 별도 확인 API나 승인 토큰을 추가하지 않는다. 최종 본문과 기록 태그, 업무 변경은 같은 트랜잭션에서 저장한다.
