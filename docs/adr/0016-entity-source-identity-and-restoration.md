# ADR-0016: 발급처별 엔터티 식별과 소프트 삭제·복원

- 상태: 채택
- 날짜: 2026-10-09
- 근거: 외부 식별자 직접 사용·발급처 구분·같은 식별자의 재등록 시 복원에 대한 대화 합의, [#242](https://github.com/kimyongin/agent-workspace-template/issues/242)

엔터티는 같은 사용자 안에서 발급처와 외부 식별자의 조합으로 구분한다. 외부 식별자는 입력한 문자열의 대소문자와 선행 0을 보존하며, 다른 발급처나 다른 사용자는 같은 값을 사용할 수 있다. 웹과 에이전트의 할 일·기록 연결도 이 식별을 사용한다. 별도 내부 UUID를 외부 코드의 별칭으로 관리하지 않는다.

설정은 발급처의 고정 코드·표시 이름·기본 발급처와 직접 입력/날짜와 무작위 8자 코드 자동 발급 방식을 제공한다. 이름 변경은 식별을 바꾸지 않는다. 저장한 발급처의 코드는 보존하며 삭제는 설정 안의 deleted 표시로 처리한다. 활성 발급처가 하나 이상이고 기본 발급처도 활성 상태여야 한다. 삭제된 발급처의 기존 엔터티 읽기·속성 편집·삭제와 과거 연결은 유지한다. 그 발급처로 새 엔터티 등록·삭제 엔터티 복원 등록·식별 정보 변경을 하려면 발급처부터 복원한다. 저장하지 않은 새 발급처의 제거는 초안만 지운다. 생성 방식 변경은 새 엔터티부터 적용하고 새 자동 식별자는 한국 날짜 `YYYYMMDD`와 영문 대문자·숫자 8자로 서버 생성 트랜잭션에서 발급하며 기존 UUID는 바꾸지 않는다. 충돌 처리는 [ADR-0019](0019-pk-based-data-id-generation.md)의 PK 재시도를 따른다. 기존 uuid 발급 설정은 short 방식으로 해석한다. 웹은 보기에서 발급처·식별자를 본문 첫 항목으로 표시하고 편집에서 일반 속성과 함께 저장한다. 같은 트랜잭션에서 중복·버전을 검사하고 모든 변경과 참조 전환을 원자적으로 확정한다. MCP의 독립 rekey_entity도 동일한 식별 변경 규칙을 유지한다. 과거 메모 본문에 적힌 당시 코드는 유지한다.

엔터티 삭제는 속성·태그·관계를 보관하는 소프트 삭제다. 활성 목록과 연결 후보에서는 제외하지만 과거 기록에서 삭제 상태와 당시 문맥을 확인할 수 있다. 삭제된 동일 식별자의 등록은 기존 값을 기본으로 복원하며, 명시한 변경을 반영하고 버전을 계속 증가시킨다. 별도로 삭제한 할 일·기록을 복원하지 않는다. 활성 대상의 동일 식별자 등록은 거부한다.

기존 UUID 엔터티는 기본 앱 발급처로 이관하면서 자료와 관계를 함께 보존한다. 이미 물리 삭제한 자료를 만들어내거나 과거에 합쳐진 대상을 자동으로 분리하지 않는다. 이관과 사용자 격리·원자성의 검증은 [#244](https://github.com/kimyongin/agent-workspace-template/issues/244)에서 관리하며 운영 DB 적용은 별도 실행 권한을 따른다.

발급처 목록의 첫 활성 항목을 기본값으로 사용한다. 사용자는 각 발급처의 이름과 자동 발급/직접 입력 방식을 지정하고 위아래 이동으로 순서를 바꾼다. 새 발급처의 코드는 내부에서 생성하며 기존 코드는 유지한다. 기존 공통 발급 방식과 별도 기본 발급처 설정은 읽을 때 기존 선택을 보존해 목록 순서와 개별 방식으로 변환한다.
