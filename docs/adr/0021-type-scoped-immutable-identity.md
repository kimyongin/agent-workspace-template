# ADR-0021: 종류 범위의 불변 자료 식별자와 재사용 발급처

- 상태: 채택, 구현·운영 적용 여부는 [#426](https://github.com/kimyongin/agent-workspace-template/issues/426)에서 확인
- 날짜: 2026-10-15
- 승인: 외부 플랫폼 자료 통합 설계안에 대한 사용자의 “진행하자” 지시
- 대체 범위: [ADR-0016](0016-entity-source-identity-and-restoration.md)의 자료 식별 범위·식별 정보 변경 허용·전역 식별 설정·중지 발급처 복원 제한

현재 결정: [ADR-0027](0027-field-identifiers-and-workspace-keys.md)이 일반 항목 밖 식별 정보·출처당 규칙 하나·출처 기반 참조 키를 대체한다. 아래 원래 결정과 이유는 과거 근거로 보존한다.

2026-10-22 후속 합의: 일반 입력 항목 밖 식별 정보·출처당 규칙 하나 연결·출처 기반 참조 키의 결정은 [PRD의 항목 기반 식별자](../product/concept.md#항목-기반-식별자) 목표에 따라 변경한다. 자료 종류·식별자 종류의 불변 ID·원본 값으로 참조 키를 구성하고 등록 후 불변·명시 복원 정책은 유지한다. 같은 날 사용자가 기존 자료 전체의 삭제를 허용하여 최초 전환의 보존 이관 대신 [#551](https://github.com/kimyongin/agent-workspace-template/issues/551)의 명시 초기화·공간 복합 PK 전환과 [#543](https://github.com/kimyongin/agent-workspace-template/issues/543)의 식별자 기능을 함께 준비한다. 계정·인증·개인 설정·공간·참여·권한과 관련 없는 업무 자료는 보존한다. 아래의 과거 구현 계약과 새 목표, 티켓 등록과 실제 초기화·구현 완료를 구분한다.

## 목적

여러 마켓의 상품·주문을 공통 자료 종류로 관리하되 마켓의 등록 건마다 별도 행을 보관한다. 여러 상품을 묶을 때는 상품 그룹 같은 별도 자료와 기존 양방향 연결을 사용한다. 자동 병합이나 스키마 상속을 도입하지 않는다.

## 결정

- 자료를 소유자·자료 종류·발급처·문자열 번호로 구분한다. 발급처와 종류의 불변 설정 키, 원본 번호를 결합한 단일 문자열을 참조 키로 사용한다. 별도 자료 UUID를 추가하지 않는다.
- 등록 이후 자료 종류·발급처·번호는 불변이다. 라벨·이름·업무 속성 편집과 구분하며 일반 수정·MCP·직접 DB 경계에서 같은 정책을 강제한다.
- 식별자는 모든 자료의 필수 공통 정보로 관리하고 일반 JSON properties 밖에 둔다. 종류별 `식별자` 설정에서 번호 라벨·지원 발급처/규칙·기본 발급처를 정한다. 업무 속성은 기존 버전 JSON Schema를 유지한다.
- 발급처와 번호 규칙은 소유자별 재사용 정의다. 종류+발급처마다 번호 규칙 하나를 연결한다. 참조된 의미/연결을 바꾸거나 물리 삭제하지 않으며 표시 이름 변경·새 등록 사용 중지는 허용한다.
- 완전 미사용 오등록은 명시 삭제할 수 있다. 번호 종류는 자료 종류 연결이 전혀 없을 때만, 발급처는 번호 종류와 자료 종류 연결이 모두 없을 때만 삭제한다. 삭제는 현재 버전·소유권·요청 원장 계약을 따른다. 시스템 앱 정의는 삭제하지 않으며 계정 탈퇴의 전체 소유 자료 정리는 별도다. 참조된 연결은 제거할 수 없으므로 삭제된 자료를 포함한 과거 의미도 보존한다.
- 기본값으로 사용되는 발급처·번호 종류의 중지는 정책 거절(`invalid_input`)이다. 영향받는 자료 종류를 반환하고 같은 편집 문맥에서 기본 발급처를 먼저 변경한다. 실제 버전 경쟁(`settings_changed`)과 구분한다.
- 외부 번호는 직접 입력, 자체 자료는 앱 자동 발급을 사용한다. 새 종류는 앱 자동 발급과 이름 항목으로 바로 사용할 수 있다.
- 원본 번호의 앞자리 0·대소문자·구분자·Unicode를 임의 변환하지 않는다. 앞뒤 공백/빈 값/제어문자 검증은 공유 입력 계약으로 통일한다. 사용자별 최대 길이 설정 UI는 제공하지 않으며 공통 서버 한도는 유지한다.
- 관계는 각 자료의 단일 참조 키로 연결한다. 숫자/문자열 번호가 같다는 이유로 자동 연결하지 않는다. 연결/그룹 삭제는 상대 자료 삭제가 아니다.
- HTTP와 MCP는 같은 공개 유스케이스·검증·재시도·소유권 계약을 사용한다. 실제 caller를 함께 전환한 뒤 구 rekey/전역 identity 계약을 제거한다.

## 대안과 이유

발급처:번호만으로는 같은 마켓의 상품과 주문 번호가 충돌한다. 모든 FK에 복합 구성값을 전달하면 연결·기록·도구 호출의 입력이 길어진다. 단일 파생 참조 키와 구성 컬럼을 함께 유지하면 기존 연결 구조를 활용하면서 종류/발급처 필터와 원본 표시도 간단하다.

임의 업무 속성을 PK로 지정하면 삭제·타입 변경·schema migration과 불변 식별 정책이 얽힌다. 별도 공통 식별 정보는 이러한 복잡성을 줄인다. 추가 보조 번호는 현재 문자열 업무 속성으로 관리하며 범용 보조 식별자 엔진을 미리 만들지 않는다.

## 전환과 실행 범위

사용자는 기존 자료가 테스트용이므로 데이터 이관이 필요 없다고 명시했다. 구 번호·참조·성공 재현 receipt·봉인 schema 작업을 새 키로 변환하는 엔진을 만들지 않는다. 후속 migration은 관련 구 자료/참조가 남으면 자동 삭제 없이 중단하고, 준비된 빈 저장소에서 새 계약을 적용한다.

실제 기존 로컬/운영 데이터 정리는 별도 실행 범위다. 이번 구현은 기존 DB를 건드리지 않고 새 격리 개발 DB에서 전체 migration과 계약을 검증한다. 운영 적용·배포는 하지 않는다. 구 자료 정리가 필요한 배포 때에는 명시 대상과 dry-run 결과를 확인한다.

외부 API 가져오기·인증·응답 매핑·동기화·주문 처리 엔진은 이 결정의 구현 범위에 포함하지 않는다. 플랫폼 번호의 유일성 범위(전체 플랫폼/판매자 계정)는 실제 연동 전에 확인한다.

## 결과

번호를 잘못 입력한 경우 일반 번호 수정으로 정체성을 바꾸지 않는다. 올바른 번호로 새 자료를 만들며 기존 연결/기록을 조용히 다른 대상으로 옮기지 않는다. 삭제 자료는 동일 식별자로 명시 복원하며 새 생성 재시도로 복원하지 않는다. 발급처를 중지해도 기존 자료의 읽기·일반 편집·복원을 막지 않는다.

설정 화면은 기본·자료·태그·기록·발급처로 나누고 한 대상의 설정은 같은 작업 공간에서 완료한다. 자료별 기록 자동 완성은 기록 설정으로 이동한다. 디자인의 세부 동작은 [UI 패턴](../design/ui-patterns.md), 승인된 전체 범위는 [설계](../design/identifier-foundation-concept.md)와 #426이 소유한다.
