PRD·ADR을 정하는 사람의 경로

무엇을 왜 만들지 정하고, 중요한 결정을 승인하고, 배포를 지시합니다. 나머지는 에이전트가 끝까지 진행합니다.

이 순서로 읽기

  1. 에이전트와 일하는 방법: 무엇이라고 말하면 되는지
  2. PRD: 내가 소유하는 제품 요구사항
  3. ADR 목록: 내가 소유하는 되돌리기 비싼 결정
  4. START-HERE 현재 상태: 지금 어디까지 왔는지

이렇게 말하면 됩니다

정리해봐: …→PRD 반영해→티켓 만들어→티켓 진행해→배포해 (환경)

직접 개입하는 네 가지 경우

  • PRD·ADR PR 승인
  • 에이전트가 멈추고 물을 때의 판단
  • 다른 에이전트에게 교차 리뷰 요청
  • 운영 배포·운영 DB·비용·비밀값·데이터 복원 지시

개발 에이전트(Codex·Claude Code)의 경로

PRD·ADR 안에서 티켓·구현·테스트·리뷰·가이드·스킬을 소유합니다. PRD·ADR을 벗어나야 하면 멈추고 변경안으로 승인을 받습니다.

이 순서로 읽기

  1. AGENTS.md (Claude Code는 CLAUDE.md가 가져옴)
  2. develop-agent-app 스킬: 요청별로 읽을 정본
  3. START-HERE와 관련 기능 티켓, 실제 checkout 확인
  4. 요청에 맞는 정본만: 코드 원칙, 아키텍처, 보안, 디자인…

항상 지키는 것

  • 문서의 제안과 실제 구현 상태를 구분
  • main에 직접 푸시하지 않고 작은 PR(약 400줄)로 올림
  • 다른 에이전트의 교차 리뷰와 자동 검사를 통과하면 머지
  • 검증 증거와 환경 제약은 해당 티켓에 기록
  • 문서를 바꾸면 node scripts/check-docs.mjs 실행

앱 사용자의 경로 (이 템플릿으로 만든 앱)

사람은 웹 앱으로, 외부 에이전트는 플러그인으로 같은 업무를 합니다. 웹에서 만든 할 일을 에이전트가 완료하고, 그 결과를 다시 웹에서 확인할 수 있습니다.

할 수 있는 일

  • 할 일(일회성·반복)을 만들고 수행 결과를 기록
  • 할 일 없이 바로 활동을 기록
  • 판단 기준이 되는 사용자 원칙을 저장
  • 쌓인 기록·원칙을 검색하고 원문을 확인

먼저 볼 것

  1. 2 무엇을: 기본 기능과 지식이 쌓이는 흐름
  2. 제품 스킬(workspace): 에이전트가 자료를 찾고 기록하는 방법
  3. 보안 가이드: 내 데이터는 기본적으로 나만 접근
01

왜: 복제해서 새 앱을 시작하는 구현형 템플릿

이 역할에 중요

같은 핵심 컨셉을 공유하는 여러 도메인 앱을 쉽게 만들기 위한 템플릿입니다. 에이전트와 함께 일하는 초보자도 쓸 수 있어야 합니다.

  1. 저장소 복제문서·스킬·실험 포함
  2. 서비스 연결새 프로젝트의 설정·비밀값은 독립 구성
  3. 도메인 조정엔터티 속성·업무 규칙·화면·제품 스킬
  4. 새 도메인 앱공통 기능은 다시 쓰지 않음
새 앱마다 바꾸는 것

예제 엔터티 Entity와 그 주변

명시적인 컬럼(id, prop1, prop2…)을 가진 테이블 하나와 그 모델·유스케이스·화면·제품 스킬입니다. 예를 들어 고객 앱은 entity 자리를 customers로 바꿉니다. 고유한 계산·상태 전환은 정해진 확장 위치에 추가합니다.

모든 앱이 그대로 갖는 것

인증·할 일·기록·원칙·검색의 공통 구조

선택 모듈이 아니라 모든 앱의 기본 기능입니다. 동적 키–값 저장소나 범용 payload 저장소는 만들지 않습니다. 메인·서브 테이블이나 특정 도메인 모델도 기본 템플릿에 넣지 않습니다.

02

무엇을: 필수 기본 기능과 지식이 쌓이는 흐름

이 역할에 중요

앱은 데이터를 보관하고 권한과 업무 규칙에 따라 정확히 조회·변경합니다. 판단은 외부 에이전트가 합니다. 앱 안에 대화형 추론 엔진을 넣지 않습니다.

계획

할 일

앞으로 할 행동. 한 번 하는 일회성 할 일과 규칙에 따라 되풀이하는 반복 할 일이 있습니다.

결과

활동 기록

실제로 한 일과 결과. 할 일 없이도 바로 쓸 수 있습니다.

기준

사용자 원칙

사용자가 저장한 판단 기준 데이터. 개발용 코드 설계 원칙과는 다릅니다.

회수

검색(RAG)과 원문 확인

쌓인 할 일·기록·원칙을 찾고, 원문을 읽어 다음 업무에 씁니다.

접점

웹 앱과 플러그인

사람과 에이전트가 같은 업무를 하는 두 입구입니다.

기록이 지식이 되는 순환

  1. 업무 계획할 일을 만든다
  2. 수행웹이나 에이전트로 한다
  3. 결과 기록제목·요약에 핵심, 본문에 근거
  4. 색인제목+요약을 벡터 하나로
  5. 새 질문다음 업무에서 생긴다
  6. 원칙·자료 검색의미 검색과 키워드 검색
  7. 원문 확인검색 결과에서 원본 상세로
  8. 에이전트의 판단다음 할 일과 기록으로

↺ 판단의 결과가 다시 할 일과 기록이 되어 1번으로 돌아갑니다. 모델을 재학습하지 않고, 저장된 자료를 작업할 때 꺼내 씁니다.

할 일의 두 종류

일회성 할 일은 완료하고, 반복 할 일은 중단합니다

반복 할 일은 매일·매주(요일)·매월(날짜) 규칙으로 회차가 정해집니다. 회차에 기록이 하나 이상 있으면 수행한 것이고, 없으면 아직 하지 않은 것입니다. 중단하면 이후 회차가 생기지 않고, 기존 기록은 남으며, 다시 재개할 수 있습니다. 앱이 정해진 시각에 자동 실행하거나 알림을 보내는 기능은 아닙니다.

검색이 지키는 약속

결과는 원본으로 이어지고, “없음”과 “아직 못 찾음”을 구분합니다

에이전트가 참고한 기록을 사람도 웹에서 열어 볼 수 있습니다. 결과 없음·색인 지연·검색 장애를 구분해서, 아직 색인되지 않은 자료를 없는 자료로 오해하지 않게 합니다.
