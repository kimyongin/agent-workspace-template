# 기록 본문 검색

## 목적과 정본

[ADR-0014](../adr/0014-minimal-content-model.md)에 따라 유사도 검색은 과거 기록의 본문만 사용한다. 엔터티·할 일·원칙의 최신 값은 해당 도메인에서 조회한다. 업무 내용이 의미 검색으로 회수되길 원하면 변경 메모에 그 내용을 포함해 기록으로 남긴다. 필요한 대상·수행 결과 관계와 본문 설명을 사용하며 새로운 원칙 적용 연관키를 의무화하지 않는다.

이 문서는 검색 입력·색인 단위·조회·갱신 계약의 정본이다. 일반 큐와 서버 책임은 [아키텍처](hexagonal-review.md), 재색인은 [운영 방법](../operations/runbook.md)을 따른다. 구현·DB 적용·실제 한국어 검색 품질의 완료 증거는 [#166](https://github.com/kimyongin/agent-workspace-template/issues/166)과 PR에서 구분한다.

## 원문과 구간

기록의 사용자 내용은 본문 하나다. 별도 제목·요약을 저장하거나 자동 요약 모델을 사용하지 않는다. 목록의 대표 문구는 본문에서 표시용으로 계산한다. 검색 결과의 title은 파생 표시값이며 snippet은 검색에 일치한 본문 구간이다. 사용자 입력이나 별도의 기록 내용 속성이 아니다.

긴 본문은 문단·문장 경계를 고려해 나누고 인접 구간을 일부 겹친다. 짧은 기록은 한 구간으로 처리할 수 있다. 원문 전체를 손실 없이 덮고 각 공급자 입력 제한 안에서 임베딩하며 조용히 잘라내지 않는다. 원문을 하나로 보존하고 구간은 재생성 가능한 내부 색인 자료로 취급한다. 구간 크기·겹침·점수 집계는 한국어·마크다운·공백 없는 문자열에서 검증하는 기술 설정이다.

본문과 변경 메모는 같은 Unicode 코드 포인트 길이 정책을 사용한다. 계약의 상한은 기존 제목·요약·메모를 합친 자료도 수정할 수 있게 22,000자다. 기존 내용 이관은 본문에 없는 고유 내용을 보존하며 원문을 절단하지 않는다.

## 색인과 갱신

Pinecone Inference에서 본문 구간의 임베딩을 생성하고 PostgreSQL/pgvector에 보관한다. 질의는 같은 모델·차원을 사용한다. 공급자 응답의 모델·개수·차원·유한 수치를 검증한다. 품질·임계값·비용·한도는 해당 프로젝트의 평가 증거로 관리한다.

본문 변경과 현재 해시·색인 세대의 큐 작업 등록은 같은 트랜잭션에서 확정한다. 기록 수정·삭제 시 구간을 교체·삭제한다. 작업 완료 전에 소유자·현재 본문 해시·색인 세대를 다시 확인해 동시 변경·재색인·삭제 뒤 늦은 결과가 이전 구간을 노출하지 않게 한다. 모든 구간이 준비된 현재 세대만 검색에 사용하며 부분 생성·실패·재시도 상태를 구분한다. 다른 소유자의 원문·구간·작업은 읽거나 확정하지 않는다.

할 일·원칙 최신 값에는 벡터와 임베딩 큐 작업을 만들지 않는다. 해당 업무 변경으로 생성한 기록은 본문으로 색인한다. 사건 metadata와 과거 snapshot·태그명은 본문에 포함되지 않았다면 별도 임베딩 입력으로 덧붙이지 않는다.

## 조회·필터·페이지

의미 검색은 기록 본문 구간에서 후보를 찾는다. 키워드 검색은 기록 본문과 할 일·현재 원칙의 제목·본문을 사용한다. 엔터티는 이름·속성 필터를 사용한다. 검색 방식은 최신 도메인 조회와 구별한다. 의미 검색을 사용할 수 없으면 허용된 키워드 결과와 keyword_fallback 상태로 안내한다.

같은 기록의 구간 결과를 하나로 합치고 기록 단위로 정렬·페이지 처리한다. 결과는 종류·ID·표시용 title·일치 snippet·Unicode 코드 포인트 구간 위치 snippet_start/snippet_end·날짜·태그·path·검색 상태를 반환한다. 상세 조회에서 본문 전체를 읽는다. 원문의 저장 title/summary/change_note나 편집용 chunk 필드를 제공하지 않는다.

task_kind/task_status, record_kind(user/result/change), entity_id와 대상 종류에 해당하는 태그 조건은 후보와 coverage·anchor에 같은 범위로 적용한다. 커서는 소유자·질의·필터에 묶이고 조건 변경 시 첫 페이지부터 조회한다. 원칙의 키워드 조회는 현재 문서만 대상으로 하며 과거 근거는 보존된 기록에서 검색한다.

semantic_coverage.pending/excluded와 index_state는 색인 상태를 알린다. 결과 0건·색인 지연·검색 장애를 구분한다. 원본 저장 성공은 의미 검색 준비 완료를 뜻하지 않는다. 원문·일치 구간·개수·커서에도 같은 소유자 권한을 적용한다.

## 검증

- 짧은 본문과 긴 한국어·마크다운·공백 없는 자료의 마지막 구간도 임베딩·검색된다.
- 메모에 포함한 업무 내용은 기록 검색으로 찾고 최신 할 일·원칙 값은 별도 임베딩하지 않는다.
- 같은 기록의 중복 구간은 하나의 결과로 합치며 필터·커서·anchor는 기록 단위를 유지한다.
- 동시 수정·삭제·재색인·부분 생성·공급자 실패와 재시도에서 이전 본문이나 다른 소유자의 구간이 노출되지 않는다.
- 웹·HTTP·MCP·제품 스킬은 같은 snippet→원문 조회 계약을 사용한다.

실제 공급자 품질과 통합 검증을 fixture·정적 검사 결과와 구분해 해당 티켓에 기록한다.

## 외부 구간 재시도

색인 worker는 원본 owner·record version·본문 hash·pipeline과 공급자 account scope·model·dimension·구간·입력 hash로 passage effect를 구분한다. 큐 message ID는 검증 경로이며 effect identity가 아니다. 각 성공 벡터를 다음 구간 호출 전에 저장하고 부분 실패·final apply 실패·재전달에서 재사용한다. input_limit 부모는 같은 입력을 재전송하지 않고 별도 자식 구간으로 분할한다. 원본 변경·삭제 이후의 결과는 적용하지 않는다.

Pinecone 2026-07의 [문서화된 embed 계약](https://docs.pinecone.io/reference/api/2026-07/inference/generate-vectors)에는 사용 가능한 멱등 키·job ID·결과 조회 계약이 없다. 내부 키를 가상의 공급자 헤더로 전송하지 않는다. 정확한 구간별 실제 전송은 첫 호출 포함 최대 5회이며 보내기 전에 내구 횟수를 증가시킨다. timeout·invalid response·결과 저장 불명은 unknown을 유지하며 제한 재계산에 따른 중복 과금 가능성이 있다. 다섯 번째 unknown은 unknown/retry_exhausted로 남기고 큐를 보류·archive한다. 검색 coverage는 pending으로 남으며 record passage effect 조회에서 이유를 확인한다. 수동 재등록도 같은 원본·pipeline의 비용 상한을 초기화하지 않는다.

동기 질의는 public search 호출당 embed 한 번, 자동 재시도 없이 owner별 분당 20회 예산을 사용한다. 실패해도 예약 비용을 돌려주지 않으며 질의 원장·장기 cache를 만들지 않는다. 공급자 timeout 30초·응답 128000 bytes·최대 5개 jobs는 유지한다. 실제 공급자 호출·과금·품질 검증은 장애 주입 DB 검사와 별도다.
