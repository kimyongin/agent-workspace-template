# 자료·기록 검색과 상태

## 목적과 정본

[ADR-0026](../adr/0026-workspace-membership-and-inherited-record-access.md)의 현재 공간과 권한 계약을 따른다. 자료 종류에서 명시적으로 선택한 텍스트 입력 항목과 소속 기록의 본문을 의미 검색하고, 할 일의 현재 제목·본문은 키워드로 찾는다. 자료 내용을 의미 검색하려고 변경 메모에 중복 작성할 필요는 없다.

이 문서는 검색 입력·색인 단위·조회·갱신 계약을 소유한다. 일반 큐와 서버 책임은 [아키텍처](hexagonal-review.md), 재색인과 실행 권한은 [운영 방법](../operations/runbook.md)을 따른다. 구현·실제 DB/HTTP/MCP/웹 검증·외부 공급자 품질의 증거는 [#511](https://github.com/kimyongin/agent-workspace-template/issues/511)과 [#516](https://github.com/kimyongin/agent-workspace-template/issues/516)에서 구분한다.

## 검색 입력과 원문

자료의 게시 정의에서 활성 일반 텍스트 항목에 `x-search-text: true`를 지정한다. nullable 텍스트도 지원하며 날짜·선택형·보관 항목은 선택할 수 없다. 선택은 항목의 불변 키에 속하므로 이름 변경과 모델 내보내기·가져오기에서도 보존한다. 보관한 항목은 선택을 해제하고 복귀만으로 다시 선택하지 않는다.

색인 입력은 현재 게시 정의의 입력 순서와 키 순서로 선택 항목을 정렬하고, 항목 이름과 현재 문자열 값 사이에 고정 경계를 둔 하나의 텍스트다. 선택하지 않은 속성·null·누락 값·빈 값·관계 캡처를 덧붙이지 않는다. `source_fields`의 키·이름·Unicode 코드 포인트 위치는 이 텍스트와 원래 입력 항목의 값을 연결한다. 자료 snippet 위치를 속성 JSON이나 기록 본문의 위치로 취급하지 않는다.

기록의 사용자 내용은 본문 하나다. 별도 제목·요약이나 자동 요약 모델을 저장하지 않는다. 결과의 `title`은 표시용 파생값이고 `snippet`은 일치 구간이다. 기록 본문·변경 메모의 상한은 Unicode 코드 포인트 22,000자이며 원문 전체는 상세 조회로 읽는다.

긴 입력은 문단·문장 경계를 고려하고 구간을 겹쳐 나눈다. 현재 보수적 상한은 구간별 UTF-8 1,800바이트와 최대 180바이트 겹침이다. 공급자 입력 제한에는 재귀 분할을 적용하고 원문의 마지막 문자까지 덮는다. 조용히 자르거나 부분 구간만 공개하지 않는다. 본문 구간은 재생성 가능한 내부 색인 자료다.

## 원자적 갱신과 현재 세대

업무 저장과 현재 원본 버전·입력 해시·게시 정의·공간 세대의 상태/큐 등록은 같은 트랜잭션에서 확정한다. 자료 생성·편집·선택 추가/해제·선택 항목 이름 변경·스키마 게시·삭제/복원은 해당 입력을 무효화한다. 선택 정의가 동일한 무관한 표시 변경은 보호된 값을 읽거나 같은 입력을 다시 전송할 이유가 되지 않는다.

기록은 실제 자료 또는 할 일 하나에 불변으로 소속한다. 본문이 같아도 저장 버전이 바뀌면 이전 작업이 새 버전을 대신하지 못한다. 할 일의 현재 값에는 벡터나 임베딩 큐를 만들지 않으며, 그 업무로 생성한 소속 기록은 본문으로 색인한다. 사건 metadata·과거 snapshot·태그명은 별도 입력으로 덧붙이지 않는다.

큐 claim·원문 준비·구간 전송 예약·성공 벡터 재사용·외부 응답 완료·최종 공개마다 실제 시작자의 현재 Auth/참여/권한, 활성 공간과 세대, 실제 원본 종류·소속·버전·해시·message/fence를 검사한다. 모델 게시로 만든 입력은 해당 게시의 전체 영향 권한을 보존한다. 설정 쓰기만으로 자료 본문을 읽지 않는다. 각 DB 단계는 짧게 커밋하고 공급자 I/O 동안 Auth·공간·업무 잠금을 잡지 않는다. 회수 후 늦은 완료는 새 구간을 공개하지 않으며 이미 전송한 텍스트를 회수했다고 주장하지 않는다.

## 조회·필터·페이지

`entity`·`record`는 의미/키워드 검색, `task`는 키워드 검색을 제공한다. 같은 원본의 중복 구간은 하나의 결과로 합친다. 결과·snippet·원문·개수·coverage·anchor·페이지를 만들기 전에 현재 공간과 실제 자료 종류/할 일/기록 소속 읽기를 적용한다. 삭제된 자료·할 일은 현재 검색 후보에서 제외하며, 보관 중인 소속 기록의 읽기는 그 실제 소속 권한으로 판단한다.

`task_kind`/`task_status`, `record_kind`(`result`/`change`), `entity_id`, 종류별 태그와 기간 조건을 후보·coverage·anchor에 동일하게 적용한다. 기록의 `entity_id`는 실제 자료 소속이며, 할 일이 해당 자료에 연결됐다는 이유로 할 일 소속 결과 기록을 포함하지 않는다.

결과는 종류·불변 ID·표시 제목·snippet·코드 포인트 위치·시각·태그·현재 원문 `path`·검색 상태를 반환한다. 자료에는 원래 선택 항목의 위치 정보도 포함한다. 원문은 같은 현재 권한으로 상세 조회한다. 커서는 실행자·공간·질의·필터·순위/벡터 문맥에 묶이고 Unicode 자료 번호를 보존한다. 유효한 예전 커서라도 현재 권한을 우회하지 못한다.

질의 임베딩을 사용할 수 없으면 허용된 키워드 결과와 `keyword_fallback`을 반환한다. `semantic_coverage.pending`/`excluded`/`failed`와 결과의 `index_state`는 준비·대상 제외·확인 필요를 구분한다. `failed`의 확인 필요에는 응답 불명도 포함되므로 확정 실패라고 단정하지 않는다. 원본 저장 성공과 색인 준비 완료는 별개다.

## 외부 구간 재시도

채택한 Pinecone Inference 임베딩은 PostgreSQL/pgvector에 저장하며 질의와 본문에 같은 모델·차원을 사용한다. 모델·개수·차원·유한 수치와 응답 크기를 검증한다. 공급자 멱등 키·작업 ID·결과 조회를 가정하지 않는다. 공급자 계약의 근거는 채택한 [embed 문서](https://docs.pinecone.io/reference/api/2026-07/inference/generate-vectors)와 프로젝트의 별도 평가에 둔다.

단일 `private.passage_effects` 원장은 공간·원본 종류/ID·버전/게시 입력·세대·시작자·전체 필요 권한·해시/pipeline과 공급자 scope·모델·차원·구간·입력 해시를 보존한다. 별도 외부 의도 원장은 만들지 않는다. message ID는 현재 작업 검증 경로이며 동일한 실제 구간의 전송 한도를 재설정하지 않는다.

실제 전송은 첫 호출 포함 최대 5회이며 전송 전에 내구 횟수와 fence를 확정한다. timeout·잘못된 응답·저장 불명·만료된 실행 lease는 `unknown`을 유지하고, backoff 이후 제한 재계산에 중복 과금 가능성이 있다. 다섯 번째 unknown은 `unknown/retry_exhausted`로 보류한다. 정확히 일치하는 성공 벡터는 현재 권한을 다시 확인한 뒤 재사용한다. input-limit 부모는 같은 입력을 재전송하지 않고 자식 구간으로 나눈다.

원본 변경·삭제 뒤에는 성공/확정 실패 결과만 정리할 수 있다. pending/running/unknown을 원본·Auth·공간 삭제의 cascade나 TTL로 지우지 않는다. 시작자 삭제로 식별 참조가 비면 후속 실행은 차단하며 공동 업무 원문은 다른 현재 독자의 권한으로 보존한다.

동기 질의는 호출당 embed 한 번과 자동 재시도 없음을 유지한다. 전송 전과 결과 조회 시 현재 인증·공간을 검사하고 I/O 중 DB 잠금을 유지하지 않는다. 질의 원장·장기 cache·임의의 사용자별 예산 제한은 두지 않는다. timeout 30초·응답 128,000바이트·최대 5개 작업의 전송 보호를 유지한다. 결정적 모의 공급자와 실제 DB worker 성공은 외부 검색 품질·실제 과금 검증을 대신하지 않는다.

## 사용자 상태 조회

`GET /status`와 읽기 전용 MCP `get_status`는 현재 공간에서 읽을 수 있는 보관 자료·할 일·기록의 개수와 최근 30일 활동을 공유한다. 자료의 활성/삭제 개수를 구분하고 소프트 삭제한 공동 원본도 보관 데이터 총수에 포함한다. 물리적으로 삭제한 기록은 현재 보관 개수·활동에서 빠진다. 시간대는 UTC/IANA 정본 이름을 사용하며 숫자 offset은 거부한다.

`indexing`은 기록 단위이고 `entity_indexing`은 자료 단위다. 각각 현재 준비/완료/제외/확인 필요와 오래 대기한 수·최초 갱신 시각·점검 기준 분을 제공한다. 최근 30일 그래프는 각 원본 작성일에 묶은 현재 상태이며 과거 대기량 이력이 아니다.

`GET /status/indexing/issues`와 `list_indexing_issues`는 같은 확인 필요 분류에서 자료/기록 종류·원문 path·파생 제목·이유·현재 leaf 구간 전송 시도 합계·진행 개수만 최근 작성일/ID 순으로 최대 5개 반환한다. 자동 분할된 input-limit 부모와 오래된 버전/해시/pipeline의 효과는 제외한다. effect ID·공급자 응답·벡터·비밀·작업 원장을 공개하지 않는다. 조회는 큐 소비·재시도·외부 호출·숨은 쓰기를 시작하지 않는다.

웹은 실행자·공간·API 수명과 권한 재검사에 읽기를 묶는다. 공간 전환·초점 복귀·재조회에서 보호된 이전 결과/문제 페이지/커서를 비우고 늦은 응답을 무시한다. 그래프의 선택 날짜처럼 보호된 본문이 아닌 표시 상태만 안전하게 보존한다.
