# 요약 기반 단일 벡터 검색

## 목적과 기본 결정

할 일과 기록의 짧은 제목·요약을 통째로 임베딩하고 항목당 현재 벡터 하나를 관리한다. 본문을 청크로 나누거나 청크별 작업·검색 점수를 합치는 구조를 두지 않는다. 원문은 그대로 보존하고 검색으로 찾은 뒤 상세 조회에서 읽는다.

이 문서는 검색 입력·요약 작성·색인 단위·조회·갱신 계약의 정본이다. 일반 큐 처리와 서버 책임은 [아키텍처](hexagonal-review.md), 운영 재색인은 [운영 방법](../operations/runbook.md)을 따른다. 실제 모델 품질과 동작의 검증 결과는 해당 기능 티켓에 기록한다.

## 제목·요약·본문의 역할

| 필드 | 용도 | 초기 입력 기준 |
| --- | --- | --- |
| 제목 | 무엇에 관한 항목인지 식별 | 최대 100 Unicode 코드 포인트 제안 |
| 요약 | 검색에 필요한 핵심 의미와 짧은 미리보기 | 최대 300 Unicode 코드 포인트 제안 |
| 본문 | 상세 근거·절차·결과·출처 보존 | 별도 도메인 입력 한도. 의미 임베딩에는 넣지 않음 |

제목과 요약은 신규 작성에서 별도 필수 필드로 받는 것을 기본으로 한다. 본문의 필수 여부·한도는 각 도메인의 작성 계약에서 정한다. 요약은 사용자가 웹에서 작성하거나 외부 에이전트가 제품 스킬에 따라 작성해 MCP로 전달한다. 서버는 필드·길이와 저장 계약을 검증하고 임베딩한다. 서버 내부 자동 요약 LLM을 필수 구성으로 추가하지 않는다.

자동 생성 기록은 서버가 이미 알고 있는 확정 사실로 짧은 설명을 만들 수 있다. 일반 본문의 앞부분을 잘라 요약으로 대체하거나 제목 복사로 요약 누락을 숨기지 않는다. 기존 원문·요약을 재색인 과정에서 자동 절단·재요약하지 않는다.

## 요약 작성 기준과 제품 스킬

요약은 원문의 핵심 대상·상황·행동/결론과 중요한 조건·근거를 담는다. 나중에 어떤 질문으로 이 기록을 찾을지 고려해 핵심 명칭을 보존한다. 부정·불확실성·조건부 결론을 확정 사실로 바꾸거나 원문에 없는 주장을 추가하지 않는다. 보통 1~3문장으로 작성하되 문장 수를 서버의 고정 규칙으로 만들지 않는다.

예를 들어 “검토 완료”보다 “고객 A의 갱신 요청을 검토했다. 사용 인원 증가로 상위 요금제가 필요하지만 예산 승인 전까지 변경을 보류한다”가 검색에 필요한 문맥을 담는다. 세부 비교표·대화 전문·출처는 본문에 둔다.

제품 플러그인의 스킬에는 제목·요약·본문을 함께 작성하고, 본문 변경 시 요약의 의미도 맞는지 확인하도록 안내한다. 웹에서도 같은 필드와 한도를 제공한다. 내용 변경을 검토한 결과 요약이 여전히 정확하면 요약을 불필요하게 다시 쓰지 않는다.

## 임베딩 입력과 모델 검증

```text
임베딩 입력 = 제목 + 줄바꿈 + 요약
원본 항목 1개 → 입력 1개 → 현재 벡터 최대 1개
```

본문·태그·연결된 다른 원문을 임베딩 입력에 추가하지 않는다. 문자열 정규화·구분자·해시 계산은 공통 검색 계약에서 고정한다. 분할·겹침·자동 절단을 하지 않으며 공급자 호출은 절단 거부 설정을 사용한다.

공급자는 Pinecone Inference, 저장은 Supabase pgvector다. 첫 검증 후보는 `llama-text-embed-v2`와 dense 1,024차원으로 둔다. 모델·차원·입력 예산·API 버전은 실제 모델 metadata와 한국어/도메인 평가를 통과한 뒤 구현 계약으로 확정한다. 후보를 적었다는 이유로 품질 검증 완료로 보지 않는다. Pinecone의 독립 임베딩 호출은 [모델 문서](https://docs.pinecone.io/models/llama-text-embed-v2)를 참고한다.

문자 수·UTF-8 byte·모델 토큰 수는 다른 단위다. 100/300자라는 상한만으로 모든 모델의 입력 한도를 보장하지 않는다. 웹·MCP·서버의 문자 계산 기준을 맞추고 한글·이모지·결합문자·긴 무공백 입력 경계를 실제 공급자로 확인한다. 검증된 입력 예산과 여유를 정하며 공급자가 한도 초과를 거절하면 입력 오류/색인 제외로 처리한다. 자동 청킹이나 반복 재시도로 우회하지 않는다.

검색 질의는 같은 모델·차원으로 `query`, 저장할 제목·요약은 `passage` 등 채택 모델의 입력 종류를 사용한다. 응답의 모델·벡터 개수·차원·유한한 수치 여부를 검증한다. 임계값은 실제 도메인 자료로 보정하며 다른 앱·모델의 점수를 복사하지 않는다.

## 저장·큐·갱신

원본 종류·안정 ID·소유자에 연결된 현재 벡터를 하나만 저장한다. 입력 해시와 모델/파이프라인 버전으로 최신성을 확인한다. 청크 번호·청크별 키·완료 수·청크 점수 병합을 만들지 않는다. `chunk_no=0` 형태로 다중 청크 구조를 남기는 것도 기본 설계에 포함하지 않는다.

| 변화 | 처리 |
| --- | --- |
| 제목·요약 변경 | 원본 저장과 색인 작업 등록을 같은 트랜잭션으로 확정 |
| 본문만 변경 | 본문·키워드 검색 갱신. 제목·요약 입력 해시가 같으면 임베딩 재생성 안 함 |
| 원본 삭제 | 벡터와 대기 작업 정리, 실행 중인 늦은 결과의 저장 거부 |
| 모델/입력 형식 변경 | 새 파이프라인 버전으로 재색인, 구 벡터·작업·커서 혼용 방지 |
| 요약 누락/입력 한도 초과 | 원본 보존, 의미 색인 제외 상태와 수정 경로 제공 |

항목별 최신 입력을 처리할 논리적 대기 작업은 하나로 합친다. 구체적인 pgmq 교체/중복 억제는 어댑터 계약과 경쟁 테스트로 확정한다. 이미 실행 중인 이전 작업은 완료 시 원본 존재·소유자·현재 해시·파이프라인을 다시 비교해 최신 내용을 덮지 못하게 한다. 새로운 범용 작업 엔진이나 이력 체계를 추가하지 않는다.

원본에 맞지 않는 벡터는 검색에서 제외한다. 외부 호출은 긴 DB 트랜잭션 밖에서 수행하고, 조건부 벡터 저장과 작업 완료는 짧은 트랜잭션에서 확정한다. 재전달은 같은 결과를 중복 효과 없이 처리한다.

## 검색과 원문 읽기

의미 검색은 제목·요약 벡터에서 후보를 찾고, 키워드 검색은 제목·요약·본문을 대상으로 한다. 조합·정렬·페이지 계약은 웹 HTTP와 MCP가 공유한다. 본문에만 있는 세부 내용의 의미 검색 재현율은 낮아질 수 있으므로 중요한 정보가 요약에 담겼는지 평가하고 본문 키워드·원문 읽기로 보완한다. 본문 전체의 의미 검색을 제공한다고 설명하지 않는다.

결과는 항목 단위의 ID·제목·요약·날짜·검색 상태를 반환한다. 에이전트는 필요한 원문을 추가 조회하고 사용자는 같은 상세를 웹에서 연다. 청크 원문·청크 위치·최고 청크 점수는 반환하지 않는다. 모든 후보·요약·원문에 같은 권한을 적용한다.

색인 중·입력 제외·공급자 장애·검색 결과 없음을 구분한다. 의미 검색 실패 시 계약된 키워드 대체 결과임을 알린다. 제외 항목을 무관한 항목으로 판단하지 않도록 검색 상태와 운영 집계에 드러낸다.

## 전환과 검증

기존 데이터가 있는 프로젝트에서는 원본을 보존하고 새 입력 계약에 맞는 항목부터 재색인한다. 요약이 없는 자료의 보완은 사용자/에이전트의 별도 작업으로 수행하고 자동 backfill을 배포 부수효과로 넣지 않는다. 기존 청크 구현이 있다면 새 경로 검증 후 사용하지 않는 청크 저장·API·worker·검색 병합·테스트·지침을 함께 정리한다.

첫 기능에서 필수 확인할 사항:

- 제목·요약을 한 입력으로 보내며 본문 전용 문구가 임베딩 payload에 들어가지 않는다.
- 항목당 현재 벡터 하나와 최신 논리 작업 하나를 유지하고 동시 수정·재전달·삭제 후 늦은 응답을 처리한다.
- 상한 경계·공급자 한도 초과·미설정/실패·요약 없는 기존 자료를 숨은 절단 없이 처리한다.
- 관련 질의·무관 질의·요약에서 누락된 세부 정보 질의를 구분해 품질과 한계를 기록한다.
- 본문만 수정하면 불필요한 재임베딩이 없고 키워드·상세에는 최신 내용이 보인다.
- 웹 작성/수정, MCP 작성/수정, 제품 스킬의 요약 기준과 원문 조회를 함께 확인한다.

모델 품질·임계값·비용·한도는 해당 프로젝트의 평가 증거로 관리한다. 일반 원칙을 변경할 필요가 생기면 이 문서와 관련 스킬·구현을 함께 갱신한다.
