# 앱을 사용하는 방법

웹에서 직접 업무를 관리하거나 연결한 Claude·Codex 에이전트에게 맡긴다. 두 접점은 같은 데이터와 업무 규칙을 사용한다. 제품의 목표와 완료 기준은 [PRD](concept.md#제품의-세-가지-성공-기준)가 소유하며, 이 문서는 그 목표에 따른 요청 방법을 설명한다.

## 업무 의도로 요청하기

도구 이름·검색 방식·태그를 외우는 대신 필요한 업무를 말한다. 아래 상담은 설명용 예시이며 검증 앱을 선택한 뜻이 아니다.

| 요청 | 기대하는 결과 |
| --- | --- |
| “이 고객의 다음 상담을 준비해줘” | 최신 고객 정보·할 일·현재 원칙을 조회하고 과거 기록을 검색해 필요한 원문을 읽은 뒤 준비안을 제시한다. 업무 데이터를 변경하지 않는다 |
| “상담을 준비하고 그 준비안을 기록해줘” | 자료를 확인해 준비하고 요청한 기록을 저장한다. 이미 요청한 저장의 승인을 다시 요구하지 않고 실제 저장 결과를 확인한다 |
| “지난번 판단의 근거를 찾아줘” | 통합 기록에서 관련 자료와 원문을 찾고 사용자가 웹에서 다시 열어볼 수 있는 근거를 제시한다 |

새 대화나 다른 에이전트에서도 앱의 자료를 조회해 이어간다. 이전 대화만으로 최신 상태를 판단하지 않는다. 현재 값은 자료·할 일·원칙 조회에서, 과거 근거는 통합 기록에서 확인한다.

자료가 부족하거나 충돌하면 확인한 사실·불확실한 내용·지금 가능한 작업을 구분해 설명하고 결과를 크게 바꿀 정보만 질문한다. 검색 장애·색인 지연·접근 제한은 자료가 없는 경우와 구분한다. 필요한 자료의 원문을 읽지 못했다면 그 한계를 밝힌다.

## 웹과 에이전트 사이에서 이어가기

웹에서 만든 할 일을 에이전트가 조회하고 요청한 업무 결과를 저장하면 웹에서 같은 결과를 확인하고 편집할 수 있어야 한다. 저장 응답이 불확실하면 반영 범위를 확인한 뒤 재시도한다. 작업 접수·원본 저장·검색 색인 반영은 서로 다른 상태다.

탐색 메뉴는 프로필과 사용자가 고른 자료 종류·할 일·기록 바로가기로 구성한다. 프로필에서 전체 자료·원칙·설정에도 접근한다. 자료 종류를 먼저 만들고 속성과 이름·아이콘을 정한 뒤 자료를 등록한다. 기록은 일반 자료·수행 결과·업무 변경 메모를 모으는 화면이며 별도의 활동 탭은 없다. 일반 기록과 로그성 기록의 메모는 편집할 수 있고 추가 편집 로그를 만들지 않는다. 로그의 사건 시각·대상·행동은 유지한다. 업무 변경 시 저장 전 기본 메모를 확인하고 이유·근거를 보충해 변경과 함께 저장한다. 상세 의미는 [통합 기록 설계](../architecture/unified-record-model.md)를 따른다.

에이전트 연결은 앱 도구를 제공하는 MCP 연결과 사용 방법을 안내하는 제품 스킬을 함께 설치한다. 설치와 인증만 성공했다고 실제 업무 행동까지 검증된 것은 아니다. 실제 설정은 [배포 방법](../deployment/release.md), 지원 여부와 관측 결과는 해당 검증 티켓에서 확인한다.

일반 기록은 메모·참고 자료다. 할 일에 연결한 기록을 작성해도 완료 상태는 바뀌지 않는다. 일회성 할 일을 실제로 수행했다면 상세의 ‘완료하고 기록’으로 결과와 완료를 함께 저장한다. 반복 할 일은 수행한 날짜의 ‘회차 기록’으로 결과를 남기며 그 날짜의 회차만 완료된다. 반복 업무는 자동 실행·알림 기능이 아니다.

반복 회차는 할 일의 시간대를 기준으로 계산한다. 수행 결과는 오늘까지 작성할 수 있고 미래 회차에는 작성할 수 없다. 매월 31일처럼 해당 달에 없는 날짜는 그 달의 마지막 날로 옮긴다. 9월은 30일, 평년 2월은 28일, 윤년 2월은 29일이며 여러 지정 날짜가 같은 날로 겹치면 회차 하나다.

## 자료 현황과 색인 문제 확인

상태 메뉴에서 내 자료·할 일·기록의 현재 개수와 상태, 최근 30일 활동을 확인한다. 집계는 서버의 현재 보관 자료를 기준으로 하므로 다른 브라우저에서도 같은 자료를 조회한다. 삭제된 할 일·기록은 과거 활동 집계에서도 빠질 수 있다. 그래프 막대를 클릭하거나 터치하면 선택한 날짜와 건수를 그래프 아래에서 확인한다. 키보드로는 그래프에 초점을 둔 뒤 좌우 방향키로 날짜를 옮기고 Home·End로 처음·마지막 날짜를 선택한다.

색인 현황은 기록이 의미 검색을 위해 준비되었는지를 나타낸다. 작성일별 색인 그래프는 당시의 대기량이 아니라 각 날짜에 작성한 기록의 현재 상태다. ‘색인 문제 기록’을 펼치면 최대 5개씩 제목과 원인을 확인하고 이전·다음 페이지로 이동한다. 행을 펼쳐 시도 수와 본문 구간 진행을 확인하며, 응답 확인 불가는 성공·실패가 확정되지 않은 상태다. 상태 조회만으로 외부 작업을 재전송하지 않는다. 에이전트에게는 ‘내 자료 현황을 확인해줘’ 또는 ‘색인이 멈춘 기록을 확인해줘’라고 요청한다.

## 자료 설정

설정에서 자료 설정을 열고 상단에서 자료 종류를 선택한다. 종류가 없으면 같은 화면에서 종류를 추가한다. 이름·아이콘·보관 상태는 기본 정보에서, 속성의 상세 조건·대표 이름·순서·목록 표시는 속성 행을 펼쳐 편집한다. 행의 편집 완료는 변경안에 반영하며 실제 적용은 속성 변경 검토에서 진행한다. 기본 정보와 식별자는 섹션별로 저장한다. 접힌 섹션의 미저장·오류·진행 표시를 확인할 수 있으며 한 섹션 저장이 다른 입력을 버리지 않는다.

속성 변경은 요약과 영향 결과를 확인한 뒤 적용한다. 값 변환이 필요한 경우에만 규칙·전후 미리보기·실패값 보완을 이어서 표시한다. 접수한 작업은 화면을 닫아도 계속되며 다시 열면 진행·실패·재시도를 확인한다. 이력의 항목에서 버전 차이와 원본 복구 가능 여부를 확인하고 복구안을 검토·실행한다.

기록 자동 완성은 자료 종류별 기록 문구와 기본 태그를 설정한다. 문구를 설정하지 않거나 기본 문구로 되돌리면 고정 기본 문구를 보여주며 종류별 기본 기록 태그는 유지한다. 자료·할 일·기록 태그는 태그 설정에서 함께 관리한다. 설정 화면 오른쪽 위 메뉴로 기본·자료·태그·기록·발급처 설정을 전환한다. 재사용 발급처와 번호 종류는 발급처 설정, 종류의 지원 발급처·기본값·번호 이름은 자료 설정의 식별자에서 관리한다. 새 속성은 적용한 뒤 해당 종류의 기록 문구 변수로 사용할 수 있다. 구현·검증 상태는 [#390](https://github.com/kimyongin/agent-workspace-template/issues/390)에서 확인한다.

## 기본 기록과 자료 식별 설정

기록 설정에서 자료 종류·할 일·원칙과 액션을 선택하고 메모 문구·변수·기본 기록 태그를 지정한다. 액션을 바꾸어도 초안은 남으며, 저장·취소는 표시된 변경 액션 전체에 적용한다. 미저장·오류 표시는 액션 선택에서 확인하고 오류 항목을 눌러 해당 입력으로 돌아간다. 잘못된 구문이나 변수는 안내에 따라 고친 뒤 저장한다. 웹의 업무 변경 확인창에서는 실제 입력으로 채워진 메모와 태그를 확인·수정할 수 있고, 에이전트도 같은 기본값을 사용한다. 결과가 불확실한 저장은 처음 준비한 메모·태그·입력으로 재시도하며 템플릿 변경이 과거 기록을 다시 쓰지 않는다.

긴 속성값으로 목록을 정렬하거나 필터를 적용해도 더 보기는 값을 줄이지 않고 이어 읽는다. 긴 조건은 복사한 주소와 새로고침·뒤로/앞으로 이동에서도 유지한다. 자료 종류를 바꾸면 이전 속성 조건과 읽던 위치를 해제한다. 펼친 필터의 정렬·기간·종류·태그·속성 조건은 초안으로 바꾸고 맨 아래 `필터 적용`으로 함께 반영한다. `조건 초기화`도 초안만 비우며 적용 전에는 기존 결과를 유지한다. 검색어는 필터 박스 밖에서 기존 방식으로 검색한다. 태그는 선택한 태그만 표시하며 `태그 선택`으로 중앙 모달을 열어 이름 검색과 체크 목록에서 고른다. `선택 완료`는 원래 초안으로 돌아가며 실제 반영은 필터 적용이나 해당 폼의 저장에서 진행한다. 목록 조회는 자료나 변경 기록을 생성하지 않는다.

자료는 종류·발급처·문자열 번호로 구분한다. 상품 설정에서 쿠팡과 네이버를 연결하면 등록할 때 발급처 하나를 골라 원본 번호를 입력한다. 같은 실물 상품이 두 마켓에 있으면 각각 등록하고 상품 그룹 같은 별도 자료에 연결한다. 같은 마켓의 상품과 주문 번호가 같아도 서로 다른 자료다. 앱 자동 발급은 번호 입력 없이 저장할 수 있으며 발급된 번호가 해당 자료의 정식 번호다.

등록한 종류·발급처·번호는 수정할 수 없다. 이름·가격·상태 같은 일반 항목은 편집한다. 삭제 자료는 보관된 항목과 연결을 확인하고 동일 식별자로 명시 복원한다. 발급처 사용을 중지해도 기존 자료의 읽기·일반 편집·복원은 유지한다. 번호를 잘못 입력했다면 올바른 번호로 새 자료를 만들며 기존 연결을 자동 이전하지 않는다. 외부 API에서 정보를 가져오는 기능은 아직 제공하지 않는다.

정확한 제품 규칙은 [기록 템플릿](../adr/0015-change-record-templates.md)과 [종류별 불변 식별·복원](../adr/0021-type-scoped-immutable-identity.md), 구현 상태는 [#426](https://github.com/kimyongin/agent-workspace-template/issues/426)와 연결된 PR에서 확인한다.

## 목표와 현재 구현 구분하기

위 내용은 합의한 목표 경험이며 현재 checkout의 기능과 새 세션 행동·웹 왕복의 검증 완료를 구분한다. 정확한 진행 상태·실행 조건·미확인은 [통합 명세 #120](https://github.com/kimyongin/agent-workspace-template/issues/120)의 하위 티켓과 연결된 PR에서 확인한다.

별도 앱 제작은 업무 대상·규칙·화면·제품 스킬을 함께 바꾸고 공통 기능을 유지해 독립 서비스에서 실제 로그인과 웹·에이전트 업무까지 확인하는 것이 목표다. 선택한 고객 관리 앱은 전화번호·이메일·상담 일정과 상담 내역 기록을 다룬다. #126·#127·#128의 보류는 해제했으며 선행 작업과 실행 조건에 따라 진행한다. 외부 연동과 운영 설정은 별도 확인한다. 초기화 지침이나 로컬 실행만으로 새 앱 제작 목표 전체를 완료 처리하지 않는다. 서비스 설정·비밀값 입력 등 사람이 직접 해야 하는 단계는 개발 에이전트가 안내한다.

이 저장소를 개발하는 사람의 스킬 호출과 결과의 흐름은 [프로젝트 지도](../overview.html#skill-invocation)와 [Matt 원본 스킬](../development/matt-skills.md)에서 확인한다.
