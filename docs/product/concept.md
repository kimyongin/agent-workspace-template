# 제품 요구사항(PRD) — 에이전트 워크스페이스 템플릿

- 소유: 사람 ([ADR-0008](../adr/0008-document-ownership.md)). 에이전트는 변경안을 제안하고 사람이 승인한다.
- 갱신: 2026-10-02

## 어떤 템플릿인가

같은 핵심 컨셉을 공유하는 여러 도메인 앱을 쉽게 만드는 **구현형 템플릿**이다. 사람과 외부 에이전트가 같은 데이터와 업무 기능을 사용하고, 업무 과정에서 쌓인 계획·활동·원칙을 다음 판단에 활용한다.

저장소를 복제하고 서비스 설정을 연결한 뒤 도메인 엔터티의 속성·업무 규칙·화면·제품 스킬을 조정하면 새 앱으로 쓸 수 있어야 한다. 일반적인 데이터 관리는 속성과 화면 변경 중심으로 시작하고, 고유한 계산·상태 전환은 정해진 확장 위치에 추가한다. 이 템플릿은 에이전트와 함께 작업하는 초보자도 사용할 수 있어야 한다.

## 대상 사용자와 해결하는 문제

| 대상 | 설명 |
| --- | --- |
| 템플릿으로 앱을 만드는 사람 | 개발 에이전트와 함께 업무 앱을 만들려는 초보 개발자와 비개발자. 무엇을 왜 만들지 정하고 중요한 결정을 승인하며, 구현은 개발 에이전트에게 맡긴다 |
| 만들어진 앱을 쓰는 사람 | 자신의 할 일·기록·판단 기준을 쌓고 웹 화면과 AI 에이전트로 업무를 이어 가는 개인 사용자 |

| 문제 | 이 템플릿의 해결 |
| --- | --- |
| 해 둔 일과 결과가 흩어져 다음 판단에 쓰이지 않는다 | 한 일을 제목·요약·본문으로 기록하고, 다음 업무에서 검색해 원문을 확인한다 |
| 사람이 쓰는 앱과 AI 에이전트가 쓰는 도구가 따로 놀아 데이터와 결과가 어긋난다 | 웹 앱과 에이전트 플러그인이 같은 업무 기능과 데이터를 쓴다 |
| 업무 분야가 바뀔 때마다 로그인·할 일·기록·검색 같은 기본 기능을 처음부터 만든다 | 저장소를 복제하고 업무 대상과 화면·제품 스킬만 바꿔 새 앱을 시작한다 |

## 필수 기본 기능

다음은 선택 모듈이 아니라 모든 앱이 갖는 기본 기능이다. 구현 순서를 나누는 것은 이 기능을 제외한다는 뜻이 아니다.

| 기능 | 의미 |
| --- | --- |
| 할 일 | 앞으로 수행할 행동. 한 번 하는 일회성 할 일과 일정 규칙에 따라 되풀이하는 반복 할 일이 있다 |
| 활동 기록 | 수행·관찰·판단 결과와 사용자 데이터의 생성·수정·삭제 이유. 직접 작성 기록과 자동 변경 기록을 함께 조회한다 |
| 사용자 원칙(principles) | 사용자당 현재 판단 기준 문서 하나와 과거 저장본. 여러 기준은 한 본문에 쓰고 현재 문서를 편집한다 |
| 검색(RAG)과 원문 확인 | 쌓인 할 일·기록·원칙을 찾아 원문을 읽고 다음 업무에 활용 |
| 웹 앱과 에이전트 플러그인 | 같은 업무를 수행하는 두 사용자 접점 |

할 일과 기록의 관계·삭제 영향은 명확히 정하되 계획과 수행 결과를 하나의 상태로 취급하지 않는다.

### 현재 원칙과 과거본

- 현재 원칙은 사용자당 0~1개다. 최초 등록 후 현재 문서를 수정하면 새로운 최신 저장본을 만들고 과거 본문·저장 시각·변경 메모를 보존한다. 여러 문서를 동시에 활성화하지 않는다.
- 원칙에는 태그를 붙이지 않는다. 웹과 에이전트의 기본 판단 기준은 현재 원칙 하나이며, 과거 판단 검토에는 당시 원칙을 확인한다.
- 과거 저장본의 조회·본문/메모 정정·삭제를 제공한다. 정정은 저장 순서를 바꾸지 않는다. 최신본 삭제 시 남은 최신본이 현재가 되며 마지막 본 삭제 시 현재 원칙이 없는 상태다. 삭제 전에 이 영향을 안내한다.
- 원칙의 저장본과 그 변경을 보여주는 활동 기록은 같은 사건을 가리킨다. 활동 기록을 삭제해도 원칙 저장본을 연쇄 삭제하지 않는다.

### 두 태그 사전

- 엔터티에는 엔터티 태그, 할 일과 기록에는 활동 태그를 사용한다. 두 사전의 이름·ID·연결 범위는 독립적이며 같은 이름을 각각 가질 수 있다.
- 원칙에는 태그가 없다. 관련 엔터티와 활동은 대상 연결로 찾으며 엔터티 태그를 활동 태그로 자동 복제하지 않는다.

### CRUD·편집 메모와 변경 기록

- 엔터티·할 일·기록·원칙의 생성·조회·수정·삭제는 웹과 MCP에서 같은 규칙으로 제공한다. 일반 조회·취소·실패·동일 값 저장은 성공 변경 기록을 만들지 않는다.
- 수정에는 공백이 아닌 편집 메모를 받아 활동 기록에 표시한다. 생성·삭제의 이유는 선택 입력으로 제공한다. 완료·중단·재개 같은 목적별 상태 전이도 실제 변화와 결과를 기록한다.
- 대상 변경과 필수 활동 기록은 함께 성공하거나 함께 실패한다. 같은 요청 재시도로 대상과 이력이 중복 생성되지 않아야 한다.
- 변경 기록은 대상·행동·변경 전후·메모·시각·웹/에이전트 출처를 보여준다. 대상 삭제 뒤에도 당시 문맥을 보존한다. 비밀값·인증 정보는 기록에 넣지 않는다.
- 직접 작성 및 자동 변경 기록도 소유자가 정정·삭제할 수 있다. 서버 식별 정보는 임의 위조하는 편집 필드로 제공하지 않는다. 기록 정정/삭제는 원래 엔터티·할 일·원칙의 상태를 되돌리지 않는다.
- 기록에 대한 명시적 사용자 변경도 한 번 기록하지만 그 자동 기록 저장 자체는 다시 기록하지 않는다. 할 일 완료와 결과 기록처럼 하나의 작업에서 생긴 변화는 같은 원인으로 묶어 중복 표시를 피한다.

2026-10-04 사용자 승인 근거와 상세 의미·전환 계약은 [Template-20](../tickets/template-20-current-principle-change-records.md), 세 탭과 설정·반응형 상세는 [Template-19](../tickets/template-19-three-tab-release-ux.md)에서 추적한다.

### 일회성 할 일과 반복 할 일

- **일회성 할 일**은 수행하면 완료하고 그 결과를 기록으로 남긴다.
- **반복 할 일**은 매일, 매주(요일 선택), 매월(날짜 선택) 규칙으로 회차(날짜)가 정해진다. 앱이 정해진 시각에 작업을 자동 실행하거나 알림을 보내는 기능이 아니다.
- 반복 할 일의 회차에 연결된 기록이 하나 이상 있으면 그 회차를 수행한 것이고, 없으면 아직 하지 않은 일이다. 지난 회차에 기록이 없으면 하지 않은 회차로 표시한다.
- 한 회차에 기록을 여러 개 남길 수 있고 지난 회차에도 나중에 기록할 수 있다.
- 반복 할 일은 완료하지 않고 중단한다. 중단하면 이후 회차가 생기지 않고 기존 기록은 남는다. 중단한 반복 할 일은 다시 재개할 수 있다.

## 사람과 에이전트의 사용 방식

사람에게는 HTTP API를 사용하는 웹 앱을, 외부 에이전트에게는 MCP 연결과 제품 스킬을 함께 패키징한 플러그인을 제공한다. 서버에서 두 접점은 같은 유스케이스를 실행하므로 결과·권한·변경 범위가 같다([ADR-0001](../adr/0001-hexagonal-shared-usecases.md)).

앱은 데이터를 보관하고 권한과 업무 규칙에 따라 정확하게 조회·변경한다. 외부 에이전트는 자료를 읽고 해석하며 사용자 요청에 따라 작업한다. 앱 자체에 대화형 추론 엔진을 내장하지 않는다.

플러그인의 MCP 연결은 데이터 조회와 업무 실행 도구를, 제품 스킬은 어떤 자료를 먼저 찾고 원문을 어떻게 확인하며 결과를 어떻게 기록할지를 제공한다. 도구 접근과 업무 안내가 함께 제공되는 것이 기본 사용 경험이다. 지원 클라이언트는 Claude와 Codex다([ADR-0005](../adr/0005-plugin-delivery-claude-codex.md)).

사용자는 데이터 관리, 할 일 수행, 기록 확인을 웹과 에이전트 사이에서 이어갈 수 있어야 한다. 예를 들어 웹에서 만든 할 일을 에이전트가 읽고 결과를 저장하면, 웹에서 그 결과를 확인하고 다음 대화에서 다시 찾을 수 있다.

## 할 일과 기록이 지식이 되는 과정

```text
업무 계획 → 수행 → 결과 기록
                     ↓
새 질문 → 사용자 원칙·관련 자료 검색 → 원문 확인 → 외부 에이전트의 판단
                                                    ↓
                                             다음 작업과 기록
```

모델을 재학습시키는 대신 저장된 자료를 작업 시점에 회수한다. 기록할 때 핵심 의미를 짧은 요약에 담고 자세한 근거는 본문에 남긴다. 검색 방식은 [ADR-0004](../adr/0004-summary-single-vector-search.md)를 따른다.

검색 결과는 원본으로 이어져야 한다. 에이전트가 참고한 기록을 사람도 웹에서 열어 확인할 수 있어야 한다. 검색 결과 없음과 검색 장애·색인 지연을 구분해, 아직 찾지 못한 자료를 존재하지 않는 자료로 오해하지 않게 한다.

시간이 오래 걸리는 작업은 처리 중임을 알리고 결과가 준비되면 확인할 수 있게 한다. 작업 접수와 실제 완료를 구분하고, 실패한 작업은 확인하고 다시 처리할 수 있어야 한다.

## 기본 예제 엔터티

특정 도메인 대신 테이블 하나의 중립적인 예제 엔터티를 제공한다.

```text
Entity
  id
  prop1
  prop2
  ...
```

- `id`는 식별자이고 `prop1`·`prop2` 등은 같은 엔터티의 명시적인 속성·컬럼이다.
- 메인·서브 테이블이나 부모·자식 엔터티를 추가하지 않는다. 동적인 키–값 저장소나 범용 payload 저장소를 만드는 의미도 아니다.
- 기본 화면은 엔터티의 목록·상세·생성·편집을 제공하고, 엔터티 상세에서 관련 할 일·기록·원칙을 보고 이동할 수 있다.
- 새 앱에서는 엔터티와 속성의 이름·타입·검증, 화면과 제품 스킬을 변경한다.
- 기본 템플릿에는 홈카페·고객 관리 같은 특정 도메인 모델을 넣지 않는다.

예제 테이블 하나라는 범위는 도메인 교체용 예제에 한정된다. 인증·할 일·기록·원칙·검색에 필요한 공통 저장 구조는 별도로 유지한다. 속성의 타입·필수값·검증은 구현 티켓에서 정한다.

## 범위

| 구분 | 범위 |
| --- | --- |
| 템플릿 완성 범위 | 필수 기본 기능, 단일 예제 엔터티와 공통 화면, Claude·Codex 플러그인, 새 프로젝트 초기화·배포·운영 절차 |
| 첫 구현 범위 | 일회성 할 일 작성·조회·완료 결과 저장, 반복 할 일 작성·조회·회차 기록·중단·재개, 직접 기록 작성·조회, 검색과 원문 확인 |
| 이후 구현 범위 | 사용자 원칙 관리·적용, 태그 관리, 예제 엔터티, 도메인 전환 검증 |
| 요구가 있을 때 별도 PRD로 추가 | 공유·조직·첨부·실시간 갱신 |

첫 구현 범위와 이후 구현 범위는 순서일 뿐이며 모두 템플릿 완성에 필요하다. 구현 순서와 완료 기준은 [Template-02](../tickets/template-02-implementation-base.md)가 관리한다.
