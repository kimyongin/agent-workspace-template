# 제품 요구사항(PRD) — 에이전트 워크스페이스 템플릿

- 소유: 사람 ([ADR-0008](../adr/0008-document-ownership.md)). 에이전트는 변경안을 제안하고 사람이 승인한다.
- 갱신: 2026-10-21
- 목표/구현 구분: 아래 통합 기록 모델과 제품 성공 기준은 대화에서 합의한 목표다. 현재 소스와 실제 서비스·제품 검증의 완료 범위는 [통합 실행 명세 #120](https://github.com/kimyongin/agent-workspace-template/issues/120)의 하위 티켓·PR 증거에서 확인한다. 이전 #110·#111은 대체된 계획으로 종료했다.

## 어떤 템플릿인가

같은 핵심 컨셉을 공유하는 여러 도메인 앱을 쉽게 만드는 **구현형 템플릿**이다. 사람과 외부 에이전트가 같은 데이터와 업무 기능을 사용하고, 업무 과정에서 쌓인 계획·활동·자료을 다음 판단에 활용한다.

저장소를 복제하고 서비스 설정을 연결한 뒤 도메인 자료의 속성·업무 규칙·화면·제품 스킬을 조정하면 새 앱으로 쓸 수 있어야 한다. 일반적인 데이터 관리는 속성과 화면 변경 중심으로 시작하고, 고유한 계산·상태 전환은 정해진 확장 위치에 추가한다. 이 템플릿은 에이전트와 함께 작업하는 초보자도 사용할 수 있어야 한다.

## 대상 사용자와 해결하는 문제

| 대상 | 설명 |
| --- | --- |
| 템플릿으로 앱을 만드는 사람 | 개발 에이전트와 함께 업무 앱을 만들려는 초보 개발자와 비개발자. 무엇을 왜 만들지 정하고 중요한 결정을 승인하며, 구현은 개발 에이전트에게 맡긴다 |
| 만들어진 앱을 쓰는 사람 | 자신의 워크스페이스 또는 참여한 워크스페이스에서 자료·할 일·기록·판단 기준을 쌓고 웹 화면과 AI 에이전트로 업무를 이어 가는 사용자 |

| 문제 | 이 템플릿의 해결 |
| --- | --- |
| 해 둔 일과 결과가 흩어져 다음 판단에 쓰이지 않는다 | 한 일을 본문 하나로 기록하고, 다음 업무에서 검색해 원문을 확인한다 |
| 사람이 쓰는 앱과 AI 에이전트가 쓰는 도구가 따로 놀아 데이터와 결과가 어긋난다 | 웹 앱과 에이전트 플러그인이 같은 업무 기능과 데이터를 쓴다 |
| 업무 분야가 바뀔 때마다 로그인·할 일·기록·검색 같은 기본 기능을 처음부터 만든다 | 저장소를 복제하고 업무 대상과 화면·제품 스킬만 바꿔 새 앱을 시작한다 |

## 제품의 세 가지 성공 기준

세 목표는 모두 중요하며 하나를 선택하거나 다른 목표를 제외하지 않는다. 아래는 2026-10-05 제품 목표 논의에서 합의한 기준이며 아직 검증 완료를 뜻하지 않는다. 구현·검증 명세와 후속 작업은 [#120](https://github.com/kimyongin/agent-workspace-template/issues/120)에서 연결한다.

| 목표 | 성공한 모습 |
| --- | --- |
| 업무의 연속성 | 새 대화나 다른 에이전트에서도 최신 상태와 과거 근거를 찾아 업무를 이어간다. 사용자가 필요한 자료를 하나씩 모아 전달하지 않아도 된다 |
| 업무 관리의 편의성 | 자료·할 일·기록의 핵심 조회와 변경을 웹과 에이전트 양쪽에서 같은 규칙으로 수행한다. 한쪽에서 만든 데이터를 다른 쪽에서 이어서 사용하며, 에이전트에게는 도구 이름·검색 방식·태그 대신 업무 의도로 요청한다 |
| 새 앱 제작의 용이성 | 비개발자가 업무를 설명하고 중요한 결정을 내리면 개발 에이전트가 필요한 질문·설계·코드/화면/제품 스킬 변경·검증을 진행한다. 사람이 직접 해야 하는 계정 연결·비밀값 입력 등은 안내하고, 독립 서비스 설정·배포 후 실제 로그인과 웹/에이전트 업무 수행까지 검증한다 |

업무 연속성의 예시는 “이 고객의 다음 상담을 준비해줘”라는 요청이다. 에이전트는 고객의 최신 정보·관련 자료·할 일을 확인하고, 과거 상담 기록을 검색해 필요한 원문을 읽은 뒤 준비안을 제시한다. 별도 검증 앱은 고객 관리로 선택했다. 고객 전화번호·이메일·상담 일정을 관리하고 기록에 상담 내역을 남긴다. 템플릿의 기본 자료와 구분하며 선택·도메인 교체·독립 서비스 검증은 #126·#127·#128이 맡는다.

- 조회와 준비안 작성은 요청 안에서 수행하되, 저장은 사용자가 요청한 범위에서 수행한다. “준비하고 기록해줘”처럼 저장까지 지시했다면 같은 행동의 승인을 다시 요구하지 않는다.
- 자료가 부족하거나 서로 다르면 확인된 사실과 불확실한 내용을 구분하고 가능한 부분을 진행한다. 결과를 크게 바꿀 정보만 사용자에게 질문한다. 검색 장애·색인 지연과 실제 자료 부재를 구분한다.
- 웹과 에이전트의 상호작용 방식은 각 접점에 맞게 구성하되 핵심 업무의 권한·규칙·결과는 같아야 한다.
- 템플릿 완성은 교체 지침이나 로컬 동작만으로 판정하지 않는다. 별도 프로젝트에서 선택한 고객 관리 도메인으로 업무 대상·속성·규칙·화면·제품 스킬을 바꾸고, 독립된 서비스 설정·배포·실제 로그인·웹/에이전트 업무와 공통 기능 유지까지 검증한다. #126·#127·#128의 보류는 해제했으며 선행 관계에 따라 진행한다. 외부 연동·공개 서비스 주소·계정 설정과 실제 운영 배포·비용 호출의 실행 조건은 별도로 확인한다.

### 공통 검증 기준

| 검증 장면 | 통과 기준 |
| --- | --- |
| 기존 대화를 전달하지 않은 새 대화에서 업무 요청 | 에이전트가 필요한 최신 상태·관련 자료·관련 과거 기록을 직접 찾아 업무를 이어간다 |
| 과거 자료를 활용한 준비안 또는 판단 | 필요한 원문을 확인하고 사용자가 참고 자료를 다시 열어볼 수 있다 |
| 자료 누락·내용 충돌·검색 장애 | 사실과 불확실성을 구분하고 가능한 작업을 진행하며 중요한 정보만 질문한다. 장애·지연을 자료 없음으로 단정하지 않는다 |
| 준비만 요청 / 저장까지 요청 | 준비만 요청하면 데이터를 변경하지 않는다. 저장까지 요청하면 해당 범위에서 실행하고 실제 반영을 확인한다 |
| 웹에서 만든 데이터를 에이전트가 변경하고 다시 웹에서 확인 | 핵심 업무의 결과·권한·규칙이 같고 접점을 바꿔도 작업을 이어간다 |
| 도구 이름이나 검색 절차를 지정하지 않은 업무 요청 | 제품 스킬이 필요한 도구·조회·검색·원문 확인 절차를 안내하고 에이전트가 수행한다 |
| 비개발자의 업무 요구로 별도 앱 제작 | 개발 에이전트가 설계·변경·검증을 진행하고 사람에게 필요한 결정과 직접 수행할 설정을 안내한다 |
| 새 도메인과 독립 서비스로 실제 사용 | 업무 대상·속성·규칙·화면·제품 스킬이 양쪽 접점에 일관되게 반영되고 공통 기능이 유지된다. 배포 후 실제 로그인과 웹/에이전트 업무 수행을 확인한다 |

검증의 실행 조건·자료·관측 결과와 미확인은 후속 검증 티켓에 남긴다. 위 기준은 제품의 목표이며 현재 앱이나 새 도메인 교체 검증이 완료됐다는 주장이 아니다.

## 워크스페이스와 참여

2026-10-18 대화에서 합의한 제품 요구다. 현재 구현의 소유자 본인 한정 접근과 구분하며, 구현 완료를 뜻하지 않는다.

- 워크스페이스는 업무 데이터와 자료 설정을 격리하는 단위다. 사용자가 워크스페이스를 선택하면 해당 공간의 자료·할 일·기록·검색·설정으로 전환한다.
- 사용자는 자신의 워크스페이스뿐 아니라 다른 사용자의 워크스페이스에도 참여할 수 있다.
- 참여자별로 자료·할 일·설정에 대한 권한을 부여한다. 권한은 계정 전체가 아니라 해당 워크스페이스에서의 참여와 대상에 적용한다.
- 자료는 자료 종류별로 권한을 지정한다. 예를 들어 상품은 읽기·쓰기를 허용하고 고객은 읽기만 허용할 수 있으며, 같은 종류 안의 개별 자료마다 별도 권한을 지정하지 않는다.
- 할 일·설정은 각각 하나의 권한 영역으로 권한을 지정한다. 권한 수준은 접근 불가·읽기·읽기와 쓰기로 구분하며, 쓰기에는 생성·수정·삭제·복원을 포함한다. 각 대상의 기존 불변값·수정 제한과 행동 규칙은 유지한다.
- 할 일 본문과 해당 할 일에 속한 결과·변경 기록은 할 일 권한으로 공유한다. 연결한 자료의 이름·속성은 해당 자료 종류의 읽기 권한이 있을 때만 표시한다. 사용자가 할 일 본문에 직접 적은 내용은 할 일의 공유 내용으로 취급한다.
- 기록 하나는 같은 워크스페이스의 자료 하나 또는 할 일 하나에만 속한다. 자료와 할 일 양쪽에 동시에 속하거나 여러 자료에 속할 수 없다. 자료·할 일 하나에는 기록을 여러 개 남길 수 있다.
- 기록의 소속은 생성할 때 확정하며 이후 변경할 수 없다. 다른 자료·할 일로 옮기거나 소속 없이 보관하지 않는다. 연결 해제는 기록 삭제로 처리한다.
- 기록에는 별도 권한을 지정하지 않는다. 소속 대상의 현재 읽기 권한으로 열람하고 현재 쓰기 권한으로 작성·수정·삭제한다. 자동 변경 기록은 원본 업무의 쓰기 권한으로 생성하며, 할 일 완료와 결과 기록 작성도 할 일의 쓰기 권한으로 수행한다. 함께 변경하는 대상에 필요한 권한과 원자적 저장을 유지한다.
- 일반 기록과 단독 기록 기능은 제공하지 않는다. 직접 작성하는 메모·문서 등은 이를 위한 자료 종류를 만들어 자료로 관리하고 해당 종류의 권한을 적용한다.
- 자료·할 일을 소프트 삭제하면 기록의 소속을 유지하며 해당 대상의 권한을 계속 적용한다. 연결 해제 이력을 기록의 접근 권한 근거로 계속 유지하는 방식은 채택하지 않는다.
- 관리자는 해당 워크스페이스의 설정 쓰기 권한을 가진 참여자를 뜻한다. 관리자·운영자·게스트 같은 고정 역할 묶음으로 업무 데이터 접근 권한을 정하지 않는다.
- 설정 쓰기에는 멤버 초대·제외와 권한 변경을 포함한다. 관리자는 자신에게도 자료 접근 권한을 부여할 수 있는 신뢰 주체다. 개인 화면·계정 설정은 워크스페이스의 공유 업무 설정과 구분한다.
- 초대할 때 참여자의 권한을 지정한다. 새 자료 종류에 대한 기존 참여자의 기본 권한은 접근 불가다. 초대 대기자는 관리자 최소 인원에 포함하지 않는다.
- 관리자는 이메일로 참여자를 초대한다. Google OAuth에서 서버가 확인한 이메일과 이메일 검증 상태를 초대 대상과 대조하고 사용자가 명시적으로 수락해야 참여가 확정된다. 별도 이메일·비밀번호 가입은 필요하지 않으며 수락 전에는 데이터 접근을 허용하지 않는다. 참여 후 멤버십과 권한은 애플리케이션 사용자 ID로 관리한다. 같은 사용자 ID의 이메일이 바뀌어도 참여를 유지하며, 같은 이메일의 다른 사용자 ID에 기존 권한을 자동 부여하지 않는다.
- 워크스페이스가 존속하는 동안 설정 쓰기 권한을 실제로 행사할 수 있는 참여자가 항상 1명 이상 있어야 한다. 생성할 때도 이 조건을 함께 충족한다.
- 권한 변경·탈퇴·멤버 제외·계정 삭제 등으로 마지막 관리자가 사라지는 변경을 허용하지 않는다. 다른 참여자에게 설정 쓰기 권한을 넘기는 경우에도 중간에 관리자 0명 상태가 확정되지 않아야 한다.
- 두 명 이상의 관리자가 동시에 자신의 권한을 해제하는 경우에도 최소 1명 조건을 지킨다. 화면 안내에만 의존하지 않고 서버·저장 단계에서 강제하며 웹과 MCP에 같은 기준을 적용한다.
- 목록·원문·검색·연결 자료 표시와 변경은 같은 참여·읽기·쓰기 권한 기준으로 접근을 검사한다.
- 참여자가 탈퇴하거나 계정을 삭제해도 공동 업무 데이터와 작성자 표시는 유지한다. 마지막 관리자는 다른 참여자에게 설정 쓰기 권한을 넘기거나 워크스페이스를 삭제한 뒤 탈퇴할 수 있다.
- 워크스페이스 삭제는 관리자만 수행하며, 초기에는 복원 가능한 소프트 삭제로 제공한다. 삭제된 워크스페이스에서는 일반 업무 조회·변경을 허용하지 않는다.
- 메모·문서 등 자료 본문도 의미 검색에 포함한다. 자료 종류 설정에서 검색할 텍스트 입력 항목을 지정하며, 검색 결과·원문·미리보기에는 해당 종류의 현재 읽기 권한을 적용한다.
- 기존 업무 데이터는 모두 테스트 용도이므로 삭제를 허용하며 새 모델로 이관하지 않는다. 일반 기록을 메모 자료로 변환하거나 복수 연결 기록의 소속을 추정하는 전환 기능은 만들지 않는다. 실제 초기화는 전환 대상 저장소의 기존 테스트 업무 데이터와 파생 검색 데이터를 확인해 처리하고 계정·인증·비밀값·서비스 설정은 보존한다.

구조 결정은 [ADR-0026](../adr/0026-workspace-membership-and-inherited-record-access.md), 구현 명세·작업 티켓·검증 증거는 [스펙 #511](https://github.com/kimyongin/agent-workspace-template/issues/511)이 소유한다. 공통 권한 모듈과 요청 문맥을 [#512](https://github.com/kimyongin/agent-workspace-template/issues/512)에서 먼저 확정하고 기능별 호출자를 전환한다. 명세 게시와 기능 구현·데이터 초기화·배포 완료는 구분한다.

## 필수 기본 기능

다음은 선택 모듈이 아니라 모든 앱이 갖는 기본 기능이다. 구현 순서를 나누는 것은 이 기능을 제외한다는 뜻이 아니다.

| 기능 | 의미 |
| --- | --- |
| 할 일 | 앞으로 수행할 행동. 한 번 하는 일회성 할 일과 일정 규칙에 따라 되풀이하는 반복 할 일이 있다 |
| 기록 | 자료·할 일에 연결된 수행 결과와 업무 변경 메모를 같은 형식으로 남기고 한 화면에서 조회한다 |
| 검색(RAG)과 원문 확인 | 통합 기록에서 과거 근거를 회수한다. 최신 업무 값은 해당 도메인의 조회로 확인한다 |
| 사용자 상태 확인 | 내 자료의 현재 개수·상태, 최근 30일 활동과 기록의 색인 준비 상태를 확인한다 |
| 웹 앱과 에이전트 플러그인 | 같은 업무를 수행하는 두 사용자 접점 |

할 일과 기록의 관계·삭제 영향은 명확히 정하되 계획과 수행 결과를 하나의 상태로 취급하지 않는다.

### 최신 상태와 통합 기록

- 자료·할 일은 최신 값을 관리한다. 판단 기준은 필요한 자료에 작성하고 대상·조건에 맞는 자료를 조회한다.
- 과거 내용은 모든 도메인에 흩어진 저장본 대신 통합 기록의 메모로 회수한다. 메모에 전체 내용을 담을 수도 변경점만 담을 수도 있으며 별도 snapshot/diff 모드를 강제하지 않는다. 남기지 않은 과거 전체 내용을 재구성할 수 있다고 보장하지 않는다.
- 결과·변경 기록의 설명 메모는 편집 가능하며 추가 편집 로그를 생성하지 않는다. 사건 시각·대상·행동 등 식별정보는 유지한다. 불변 메모·정정 체인은 요구하지 않는다.
- 할 일은 자료 여러 개에 선택적으로 연결할 수 있다. 기록의 소속은 자료 하나 또는 할 일 하나로 고정하며, 본문에서 인용·링크로 참고하는 다른 자료와 구분한다. 할 일의 결과·회차 기록은 해당 할 일에 속한다.
- 소속 대상이 소프트 삭제되어도 관련 기록의 당시 문맥과 소속을 보존한다. 소속 연결 해제는 기록 삭제로 처리한다. 최신 값은 해당 도메인 조회, 과거 내용·판단 근거는 소속된 기록 RAG으로 확인한다.

### 사용자 바로가기와 기록 화면

- 탐색은 프로필과 사용자 바로가기다. 프로필에서 전체 자료·자료 종류·설정에 접근하며, 바로가기는 활성 자료 종류·할 일·기록 중에서 고르고 순서를 저장한다. 보관된 종류는 읽을 수 있으며 새 자료 생성은 보관 해제 뒤 제공한다. 기록은 활동 화면과 같으며 별도 활동 탭이나 업무 객체를 만들지 않는다.
- 기록 화면은 수행 결과·변경 메모의 읽기와 검색을 중심으로 한다. 일반 기록 작성은 제공하지 않으며, 업무 수행과 변경 과정에서 본문을 작성하고 기존 기록의 메모를 편집한다.
- 등록·수정·삭제·수행 같은 업무 사건을 남긴다. 조회·검색·화면 이동 같은 사용 로그는 포함하지 않는다.

### 사용자 상태 화면

업무 탭과 별도로 상태 메뉴를 제공한다. 자료·할 일·기록의 현재 개수와 상태, 현재 보관 자료를 기준으로 최근 30일의 등록·일회성 완료·기록 작성 활동을 서버에서 집계한다. 삭제된 할 일·기록은 과거 집계에서도 빠질 수 있으며 과거 전체 상태를 복원하는 통계가 아니다. 기록의 색인 완료·준비 중·확인 필요·대상 제외를 기록 단위로 구분하고, 작성일별 그래프는 각 날짜에 작성한 기록의 현재 색인 상태를 보여준다.

상태 개요와 색인 문제 목록은 목적별 조회 기능으로 나누고 웹과 MCP에서 같은 계약을 사용한다. 문제 목록은 기본 접힘이고 페이지당 최대 5개이며 원인·시도 수·본문 구간 진행을 펼쳐 확인한다. 데스크톱과 모바일에서 같은 정보와 조작을 제공하며, 별도 통계·스냅샷 테이블이나 브라우저별 업무 통계를 만들지 않는다. 조회는 외부 작업의 재전송을 수행하지 않는다.

### 두 태그 사전

- 자료·할 일·기록은 각각 독립 태그를 사용한다. 세 사전의 이름·ID·연결 범위는 독립적이며 같은 이름을 각각 가질 수 있다.
- 관련 자료와 활동은 대상 연결로 찾으며 자료 태그를 할 일·기록 태그로 자동 복제하지 않는다.
- 태그 연결은 데이터 연결처럼 별도의 업무 동작이다. 자료·할 일·수행 결과의 생성·편집에서는 태그를 선택하거나 연결 집합을 저장하지 않는다. 신규 대상은 먼저 저장한 뒤 보기의 `태그 연결`에서 연결·해제한다. 웹과 MCP에 같은 독립 연결·해제 계약을 제공하고, 일반 생성·수정 요청의 `tag_ids`는 허용하지 않는다. 본문·속성 편집의 저장·취소는 이미 확정한 태그 연결을 덮지 않는다.
- 태그 영역은 다른 데이터 속성 뒤에 두고, 편집에서는 같은 태그를 읽기 전용으로 유지한다. 태그 사전의 생성·이름 변경·삭제와 대상에 태그를 연결하는 작업은 구분한다. 변경 기록의 고정 태그와 기록 자동 완성 설정·업무 변경 확인의 기록 태그는 자동 변경 기록을 만드는 기존 계약으로 유지하며 원본 대상의 태그 연결 수단으로 사용하지 않는다. 구체적인 배치와 상호작용은 [데이터 표시와 모드 일치](../design/ui-patterns.md#데이터-표시와-모드-일치)를 따른다.

### 변경 메모와 일관성

할 일은 제목·본문, 결과·변경 기록은 본문 하나를 사용한다. 기록의 ID·버전·시각·사건 metadata와 필요한 관계는 사용자 내용과 구별한다. 목록 대표 문구는 본문에서 표시용으로 계산하며 별도 제목·요약을 저장하지 않는다.


- 자료·할 일의 업무 변경은 한 번에 저장한다. 입력한 변경 메모가 있으면 그것만 기록 본문으로 저장하며 비어 있으면 확인 가능한 사실의 기본 설명을 생성한다. 업무 변경과 기록은 같은 트랜잭션에서 확정한다. 삭제 의사 확인과 미저장 보호는 유지한다.
- 함께 성공해야 하는 변경과 필수 기록은 같은 트랜잭션에서 확정한다. 실패·무변경·동일 요청 재시도는 성공 기록을 중복 생성하지 않는다.
- 기록의 메모 편집은 추가 로그를 만들지 않는다. 기록 편집으로 원래 업무 상태를 되돌리지 않으며, 편집 결과는 검색 색인에도 반영한다.
- 기록에 비밀값·인증 정보를 넣지 않는다. 필요한 사건 식별정보만 구조화하며 모든 서술을 연관키로 바꾸거나 별도 관계망을 만들지 않는다.
- 별도 사용자 원칙 기능과 기존 원칙 내용은 제거한다. 판단 기준은 자료로 관리하며 기존 원칙을 자동 이관하지 않는다([ADR-0022](../adr/0022-remove-user-principles.md)). 운영 DB 적용은 별도 실행 범위다.

내용·검색의 최신 결정은 [ADR-0014](../adr/0014-minimal-content-model.md), 현재 상태와 통합 기록의 책임은 [ADR-0012](../adr/0012-current-state-and-unified-records.md)와 [구현 인계](../architecture/unified-record-model.md)를 따른다. 이전 탐색·사용자 원칙 계약의 구현 근거는 Git/GitHub 이력에서 확인하며 현재 목표와 구분한다.

### 변경 기록 템플릿

설정에서 자료·할 일의 모델·액션별 기록 메모 템플릿과 기본 기록 태그를 관리한다. 웹 확인창과 에이전트는 같은 규칙으로 기본값을 채우고 사용자가 명시한 메모와 태그를 우선한다. 변수 삽입과 미리보기를 제공하며 유효하지 않은 템플릿은 위치·이유를 설명하고 저장을 거부한다. 기본값·수정 입력·같은 요청 재시도의 책임과 업무 설정의 저장 결정은 [ADR-0015](../adr/0015-change-record-templates.md)를 따른다.

### 일회성 할 일과 반복 할 일

- **일회성 할 일**은 수행하면 완료하고 그 결과를 기록으로 남긴다.
- **반복 할 일**은 매일, 매주(요일 선택), 매월(날짜 선택) 규칙으로 회차(날짜)가 정해진다. 앱이 정해진 시각에 작업을 자동 실행하거나 알림을 보내는 기능이 아니다.
- 반복 할 일의 회차에 연결된 기록이 하나 이상 있으면 그 회차를 수행한 것이고, 없으면 아직 하지 않은 일이다. 지난 회차에 기록이 없으면 하지 않은 회차로 표시한다.
- 한 회차에 기록을 여러 개 남길 수 있고 지난 회차에도 나중에 기록할 수 있다.
- 반복 할 일은 완료하지 않고 중단한다. 중단하면 이후 회차가 생기지 않고 기존 기록은 남는다. 중단한 반복 할 일은 다시 재개할 수 있다.

## 사람과 에이전트의 사용 방식

사람에게는 HTTP API를 사용하는 웹 앱을, 외부 에이전트에게는 MCP 연결과 제품 스킬을 함께 패키징한 플러그인을 제공한다. 서버에서 두 접점은 같은 유스케이스를 실행하므로 결과·권한·변경 범위가 같다([ADR-0001](../adr/0001-hexagonal-shared-usecases.md)).

앱은 데이터를 보관하고 권한과 업무 규칙에 따라 정확하게 조회·변경한다. 외부 에이전트는 자료를 읽고 해석하며 사용자 요청에 따라 작업한다. 앱 자체에 대화형 추론 엔진을 내장하지 않는다.

플러그인의 MCP 연결은 데이터 조회와 업무 실행 도구를, 제품 스킬은 어떤 자료를 먼저 찾고 원문을 어떻게 확인하며 결과를 어떻게 기록할지를 제공한다. 도구 접근과 업무 안내가 함께 제공되는 것이 기본 사용 경험이다. 지원 클라이언트는 Claude와 Codex다([ADR-0005](../adr/0005-plugin-delivery-claude-codex.md)).

사용자는 데이터 관리, 할 일 수행, 기록 확인을 웹과 에이전트 사이에서 이어갈 수 있어야 한다. 예를 들어 웹에서 만든 할 일을 에이전트가 읽고 결과를 저장하면, 웹에서 그 결과를 확인하고 다음 대화에서 다시 찾을 수 있다.

## 할 일과 기록이 지식이 되는 과정

```text
업무 계획 → 수행 → 결과 기록
                     ↓
새 질문 → 관련 자료 조회·통합 기록 검색 → 원문 확인 → 외부 에이전트의 판단
                                                    ↓
                                             다음 작업과 기록
```

모델을 재학습시키는 대신 과거 기록 본문을 작업 시점에 회수한다. 긴 본문은 구간별로 임베딩하며 같은 기록의 결과를 합친다. 최신 업무 값은 해당 도메인에서 조회한다. 검색 방식은 [ADR-0014](../adr/0014-minimal-content-model.md)를 따른다.

검색 결과는 원본으로 이어져야 한다. 에이전트가 참고한 기록을 사람도 웹에서 열어 확인할 수 있어야 한다. 검색 결과 없음과 검색 장애·색인 지연을 구분해, 아직 찾지 못한 자료를 존재하지 않는 자료로 오해하지 않게 한다.

시간이 오래 걸리는 작업은 처리 중임을 알리고 결과가 준비되면 확인할 수 있게 한다. 작업 접수와 실제 완료를 구분하고, 실패한 작업은 확인하고 다시 처리할 수 있어야 한다.

## 자료 종류와 업무 속성

사용자는 자료 종류(예: 재료·상품)의 이름·아이콘·속성을 설정한다. 종류의 이름·설명·아이콘·보관 여부와 속성 규칙·표시 설정은 JSON Schema 문서 하나가 정본이다. 여러 종류의 자료는 단일 테이블에 저장하며 업무 속성은 JSONB와 타입별 JSON Schema 정의를 사용한다. 서버 발급 prop_n 키는 고정하고 라벨·순서는 설정으로 관리한다. 필수 텍스트 대표 속성은 대상의 이름을 표시한다. 새 계정은 타입이 없는 상태이며 사용자가 첫 종류를 명시적으로 만든다. 고정 데모 타입은 자동 생성하지 않는다.

- 종류의 이름·아이콘·보관·속성 변경은 같은 정의 문서의 새 게시 버전을 만든다. 전체 자료 종류·관계와 필요한 식별자 설정을 한 자료 모델 JSON으로 내보내고 파일/붙여넣기의 차이·영향을 함께 검토해 반영하거나 새 종류·관계로 복사한다. 파일의 원본 버전은 최신 정의를 덮어쓰는 권한이 아니며 실제 자료 값·개별 연결 이식은 포함하지 않는다.
- 자료 종류별 불변 게시 버전과 현재 정의를 구분한다. 일반 호환 게시와 영향 분석·미리보기·실패 보완·원자적 변환·복구가 필요한 변경을 구분한다. 삭제/보관 자료도 해당 타입 변환에 포함한다.
- 생성 이후 자료 종류 변경은 제공하지 않는다. 같은 공간·종류·발급처·문자열 번호 안에서 자료를 구분한다. 등록 후 종류·발급처·번호는 불변이며 식별/복원 계약은 [ADR-0021](../adr/0021-type-scoped-immutable-identity.md)을 따른다. 같은 마켓의 상품과 주문이 같은 번호를 사용해도 별도 자료다.
- 종류 보관은 정의·자료·연결을 유지한다. 임의 중첩 JSON과 타입 전용 테이블은 제공하지 않는다. 별도 자료 관계 설정에서 양쪽 종류·표시 이름·하나만/여러 개를 정의하고 양끝 역할을 구분한다. 같은 종류끼리의 다른 역할도 표현하며 자료 간 연결은 명시한 관계 정의를 통해서만 허용한다. 과거 일반 연결 원본과 기록은 보존하되 현재 연결로 제공하거나 의미를 자동 배정하지 않는다. 단일은 0~1개, 복수는 0개 이상이며 필수 자료 관계는 추가하지 않는다. 워크스페이스별 격리와 참여는 위의 워크스페이스 요구를 따른다.
- 자료 상세는 단일 값과 복수 목록을 구분하고 연결·교체·해제와 새 자료를 작성해서 연결하는 동작을 제공한다. 작성·연결·필요한 단일 교체·변경 기록은 함께 성공하며 실패하면 기존 상태를 유지한다. 삭제·보관 상대의 기존 연결도 보존하고 명시적으로 해제·교체한다.
- 자료 모델 교환은 공통 설정 화면에서 전체 변경을 검토·준비·확정한다. 파일에 없는 정의를 자동 삭제하지 않는다. 복사는 새 ID와 관계·번호 정의 참조를 함께 대응하며, 여러 종류의 값 변환이 필요해도 일부만 반영된 모델을 완료로 공개하지 않는다. 웹·MCP·제품 스킬은 같은 규칙을 사용한다. 합의와 개발 완료 상태는 [스펙 #482](https://github.com/kimyongin/agent-workspace-template/issues/482) 및 [ADR-0024](../adr/0024-entity-relations-and-data-model.md)에서 구분한다.
- 일반 화면은 실제 자료 종류 이름을 사용하며 설정 진입은 자료 설정으로 표시한다. 타입 이름·아이콘은 업무 정본이며 개인 메뉴는 타입 ID 참조만 저장한다. 프로필을 고정하고 최대 네 개 업무 바로가기를 구성한다.
- 자료 설정은 한 작업 화면에서 종류 선택·추가·기본 정보·속성/표시·기록 기본값·이력을 관리한다. 기존 앱 메뉴 하나와 상단 종류 선택을 사용하고 필요한 섹션/속성 행만 펼친다. 기본 정보·속성 변경안·종류별 기록 기본값은 독립적으로 저장하며 전체 저장은 제공하지 않는다.
- 일반 편집은 해당 위치에서 변경을 표시하고 적용하며 별도 변경 검토 구획에서 입력을 반복하지 않는다. 영향 분석과 값 변환·기존 데이터 손실 등에 필요한 확인·실패 보완·변환 진행/취소/재시도·원본 복구는 보존한다. ERD는 자료 설정 마지막 `미리보기` 탭의 읽기 전용 보조 화면으로 제공하고 편집 화면의 공간을 차지하지 않는다. 기존 흐름·점진적 확장·행동 배치·반응형의 합의는 [UI·UX 정돈 방향](../design/ui-refinement-direction.md)을 따른다. 이는 2026-10-21 합의한 목표이며 구현 완료를 뜻하지 않는다.
- 자료·할 일·기록 태그는 태그 설정에서, 재사용 발급처·규칙은 발급처 설정에서 관리한다. 종류별 식별자는 자료 설정, 종류별·할 일의 기록 자동 완성은 기록 설정에서 관리한다. 자료 종류에 문구가 없거나 null이면 고정 기본 문구를 사용한다. 종류 전환과 화면 이탈에서 미저장 입력을 보호하고 직접 주소·새로고침·뒤로 가기로 선택한 종류/변경안/작업을 확인한다. 구현·검증 상태는 [자료 설정 통합 #377](https://github.com/kimyongin/agent-workspace-template/issues/377)을 따른다.
- 특정 도메인 타입은 제품 기본값으로 넣지 않는다. 정의 정본·게시 정책은 [ADR-0023](../adr/0023-single-schema-document.md), 유지하는 키·변환 보장과 한도는 [ADR-0020](../adr/0020-typed-entity-schema.md)을 따른다. 단일 문서 전환의 구현/검증은 [#468](https://github.com/kimyongin/agent-workspace-template/issues/468)이 소유한다.

## 범위

| 구분 | 범위 |
| --- | --- |
| 템플릿 완성 범위 | 필수 기본 기능, 다중 자료 종류·동적 속성과 공통 화면, Claude·Codex 플러그인, 새 프로젝트 초기화·배포·운영 절차 |
| 첫 구현 범위 | 일회성 할 일 작성·조회·완료 결과 저장, 반복 할 일 작성·조회·회차 기록·중단·재개, 수행 결과·자동 변경 기록 조회와 메모 정정, 검색과 원문 확인 |
| 이후 구현 범위 | 태그 관리, 예제 자료, 도메인 전환 검증 |
| 요구가 있을 때 별도 PRD로 추가 | 공유·조직·첨부·실시간 갱신 |

첫 구현 범위와 이후 구현 범위는 순서일 뿐이며 모두 템플릿 완성에 필요하다. 현재 구현 순서와 완료 기준은 [통합 실행 명세 #120](https://github.com/kimyongin/agent-workspace-template/issues/120)과 하위 티켓이 관리한다.
