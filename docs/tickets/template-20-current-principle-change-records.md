# Template-20 — 현재 원칙 하나·태그 범위·변경 이유가 남는 활동 기록

작성: 2026-10-04
상태: 진행 중
검토 기준: main `399b82b744f3ea9471dc335ccf5b13c972c16e93`

## 목적과 요청 범위

이 앱은 사람과 외부 에이전트가 같은 업무 대상·계획·판단 기준을 사용하고, 수행 결과와 변경 이유를 다시 찾아 다음 판단에 활용하는 개인 업무 워크스페이스다. 현재 상태만 관리하는 것으로 끝내지 않고 무엇을 왜 바꿨는지 함께 남긴다. 금융 모델·친구 공유·내장 추론 엔진을 추가하는 의미가 아니다.

사용자 요구: 현재 원칙은 최신 하나, 현재 편집으로 덮어쓰되 과거 편집본은 목록에 보존; 엔터티 태그와 활동 태그를 분리하고 원칙에는 태그 없음; 엔터티·할 일·기록·원칙을 CRUD할 수 있고 변경 이력을 활동 기록에 표시; 편집 시 메모를 받아 기록에 표시. 2026-10-04 사용자의 “좋아. 티켓 정리하고 개발해줘”로 앞선 정리안과 구현을 승인했다. 수정 메모 필수, 생성/삭제 이유 선택, 최신 원칙 삭제 후 이전본 승격, 과거본 정정/삭제, 자동 기록 정정/삭제, 원칙의 계정 전체 적용을 구현 기본값으로 확정한다. 운영 이관·배포는 실행 범위에 포함하지 않는다.

사용자 요구와 추가 기본안은 아래에서 구분한다. [Template-19](template-19-three-tab-release-ux.md)의 세 탭/모달/설정 구성을 유지하되 다중 원칙·원칙 태그/상태 필터 가정은 이 티켓으로 대체한다.

기준: [PRD](../product/concept.md), [ADR-0001](../adr/0001-hexagonal-shared-usecases.md), [ADR-0003](../adr/0003-core-rules-and-local-transactions.md), [ADR-0004](../adr/0004-summary-single-vector-search.md), [문서 소유권](../adr/0008-document-ownership.md), [검색](../architecture/search.md), [디자인](../design/guide.md), [보안](../security/guide.md).

fin의 `docs/tickets/principles-01-single-current-document.md`, `docs/tickets/crud-01-principles.md`, `docs/design/domain-crud-parity.md`를 직접 확인했다. 현재 템플릿의 principle 계약은 여러 활성 원칙·태그·엔터티 연결이고 기록의 적용 원칙은 현재값 참조다. 따라서 이번 요청은 화면 변경뿐 아니라 제품/저장/API/MCP/검색 의미 변경이다. PRD·ADR 정본은 수정하지 않고 제품 변경안을 이 티켓에 제안한다. 사용자 설명을 재확인하라고 반복 요구하지 않으며 추가 미정 의미만 구현 전에 확정한다.

## 데이터의 역할

| 자료 | 역할 | 현재와 과거 |
| --- | --- | --- |
| 엔터티 | 업무 대상의 현재 속성 | 단순 prop1~4 유지. 수정/삭제 전 문맥은 변경 기록에서 확인 |
| 할 일 | 앞으로 할 행동·반복 규칙 | 현재 계획과 상태. 수행 결과는 기록이며 변경 기록과 구분 |
| 기록 | 수행·관찰·판단과 데이터 변경 이유 | 직접 작성/수행 결과/자동 변경 기록을 활동 탭에서 함께 조회 |
| 원칙 | 현재 지켜야 할 판단 기준 | 사용자당 현재 문서0~1개, 이전 저장본은 과거 원칙 |

업무 흐름: 현재 원칙과 엔터티 확인 → 할 일 계획 → 실행/관찰 → 기록 → 기록을 근거로 엔터티·계획·원칙 수정 → 다음 판단. 웹과 MCP는 같은 유스케이스와 권한·메모·삭제 영향을 따른다.

## 원칙: 현재 문서 하나와 과거 저장본

### 확정 요구

- 활성 상태를 켜고 끄는 여러 항목으로 취급하지 않는다. 사용자가 보는 현재 원칙은 하나의 문서이며 여러 판단 기준을 본문 안에 쓸 수 있다. 원칙에는 태그가 없다.
- 원칙이 없을 때는 최초 등록을 제공한다. 있으면 현재 문서를 편집하고 한 번 저장한다. 별도 두 번째 활성 원칙 추가는 서버에서도 허용하지 않는다.
- 사용자는 현재 문서를 덮어쓰는 경험을 하되 저장 전/후의 본문을 잃지 않는다. 저장마다 과거본과 저장 시각·변경 메모를 남긴다. 원칙 탭 상단은 현재 본문+편집, 아래는 저장 시각·변경 메모 중심 과거본 목록이다. 과거본을 열면 당시 전체 본문을 확인한다.
- 현재 원칙 편집은 원칙 저장본 보존과 활동의 원칙 변경 기록을 함께 확정한다. 원칙 과거본과 활동 항목은 같은 저장 사건을 가리키며 본문/메모의 독립적인 두 정본을 만들지 않는다.

### 다듬을 기본안

- 현재 문서의 실제 정책 변경과 과거본 오타 정정을 다른 행동으로 제공한다. 과거본 정정은 해당 본문/메모만 바꾸고 저장 순서·소유자·적용 시각을 바꾸지 않는다. 오래된 행을 정정해도 현재가 되지 않는다.
- CRUD 요구에 맞춰 과거본의 단건 조회·정정·삭제도 웹/MCP에 제공한다. 과거본을 현재에 다시 적용하려면 이를 바탕으로 새로운 최신본을 저장하고 이유를 남긴다. 원클릭 복원 기능을 첫 범위에 강제하지 않는다.
- fin과 같은 기본안은 최신 저장본 삭제 시 남은 최신본을 현재로 삼고, 마지막 본 삭제 시 현재 원칙 없음으로 전환한다. 삭제 확인에서 어떤 본문이 현재가 되는지 명시한다. 이는 추가 삭제 정책 제안이며 조용히 자동 부활시키지 않는다.
- 원칙은 계정 전체의 판단 기준으로 제안한다. 기존 원칙별 entity_id·applies_when·status·replaced_by_id의 존치/본문 이동은 이관 계약에서 정한다. 자동 내용 합치기나 삭제를 하지 않는다.
- 과거 기록에서 적용 당시 원칙을 확인할 수 있게 한다. 이후 현재 원칙 편집이나 과거본 정정 때문에 과거 판단의 근거가 현재 본문으로 바뀌었다고 표시하지 않는다. 적용 시점 식별/내용 보존 방식은 저장 계약에서 확정한다.

## 태그: 두 사전과 연결 범위

| 사전 | 연결 대상 | 경계 |
| --- | --- | --- |
| 엔터티 태그 | 엔터티 | 대상 분류에 사용 |
| 활동 태그 | 할 일·기록 | 계획/활동 분류에 사용 |
| 원칙 | 태그 없음 | 현재 문서와 변경 시점으로 탐색 |

- 같은 이름을 두 사전에 각각 쓸 수 있다. 이름 중복 검사·목록·선택·수정·삭제·커서·캐시는 소유자와 사전 범위를 포함한다.
- 엔터티 태그 ID를 할 일/기록에 연결하거나 활동 태그를 엔터티에 연결하는 요청은 서버가 거부한다. 화면에서 목록만 나누는 것으로 끝내지 않는다.
- 태그 연결/해제는 해당 대상의 편집에 포함한다. 대상 속성·태그·편집 메모를 한 번 저장하고 하나의 변경 사건으로 기록한다.
- 엔터티 관련 활동은 entity_id 연결로 찾는다. 엔터티 태그를 활동 태그로 자동 복제하지 않는다. 태그 이름 변경/삭제 때문에 당시 변경 기록의 문맥이 사라지지 않도록 표시 자료를 보존한다.
- 태그 사전 자체의 생성/이름 변경/삭제를 자동 기록에 넣는 범위는 추가 기본안이다. 포함하면 태그 사전 범위와 변경 영향을 표시하며 연결된 부모의 동일 변경 사건을 중복 발행하지 않는다.

## CRUD와 편집 메모가 남는 기록

### 기록할 사건

| 작업 | 자동 기록 기본안 | 사용자 메모 |
| --- | --- | --- |
| 생성 | 무엇을 등록했는지·대상·당시 내용 | 선택 |
| 조회 | 일반 자료 조회는 기록하지 않음 | 없음 |
| 편집 | 무엇이 바뀌었는지와 이유 | 필수 제안, 공백만 입력 불가 |
| 삭제 | 무엇을 삭제했는지·삭제 전 문맥·연결 영향 | 삭제 이유도 받는 것을 권함 |
| 완료·중단·재개 등 업무 전이 | 실제 상태 변화와 수행 결과 | 목적별 메모/결과 입력 |

CRUD 권한을 제공하는 것과 모든 조회를 활동 기록으로 남기는 것은 구분한다. 조회까지 기록하면 다음 판단에 사용할 자료가 소음에 묻히므로 실제 상태를 바꾸는 작업을 기록하는 기본안을 권한다. 동일 값 저장/no-op·취소·실패·거부는 성공 변경 기록을 만들지 않는다. 필요하다면 운영 실패 로그를 별도로 사용한다.

편집 메모는 기록 본문과 별도의 변경 이유다. 예: 엔터티 prop2를10→20으로 편집, 메모 `실측 결과에 맞춰 수정`. 기록에는 대상·변경10→20·이 메모가 함께 표시된다. 메모를 원칙 본문·기록 본문에 끼워 넣지 않는다. 자동 기록의 제목/요약은 실제 작업과 메모에서 결정적으로 구성하고 원문 메모를 보존한다. 서버 요약 LLM이나 에이전트가 추측한 이유를 만들지 않는다.

활동 기록의 기본 표시는 시각 → 대상/작업 제목 → 변경 메모 → 변경 전후 → 웹/에이전트 출처 → 원문 링크다. 삭제된 대상은 당시 이름과 상태를 보여주고 삭제됨을 명시한다. 깨진 링크를 활성 대상처럼 표시하지 않는다. 활동 기록의 종류 조건은 전체/직접 작성·수행 결과/변경 기록으로 제안하며 최초에는 전체를 보여준다.

### 기록도 CRUD할 때의 경계

사용자 요청은 기록에도 CRUD를 허용하는 것이므로 자동 변경 기록을 모두 수정/삭제 불가능한 감사 원장으로 바꾸지 않는다. 별도 이벤트 저장소·모든 객체의 영구 불변 revision·범용 CRUD 엔진을 선행 도입하지 않는다.

- 직접 작성 기록과 사용자에게 보이는 자동 변경 기록 모두 조회·정정·삭제를 제공하는 기본안을 제안한다. 소유자·서버 시각·변경 대상/행위 등 시스템 식별값은 사용자가 임의 위조하는 편집 필드로 노출하지 않는다. 메모/설명 정정 범위는 기록 입력 계약에서 구체화한다.
- 기록 R을 제외한 사용자의 명시적 생성/수정/삭제도 변경 사건을 남긴다. 기록 A 정정 시 `기록 A 수정` 자동 기록을 한 번 생성한다.
- 그 자동 기록을 저장하는 내부 보조 작업은 새로운 사용자 명령으로 취급하지 않아 `기록 생성의 생성의 생성…`을 만들지 않는다. 나중에 사용자가 그 자동 기록을 명시적으로 정정/삭제하면 그 작업에 대한 변경 기록을 한 번만 남긴다.
- 작업 하나가 할 일 완료와 결과 기록 생성처럼 여러 자료를 함께 바꾸면 하나의 원인 ID로 묶어 화면에 완료 한 건과 결과를 보여준다. 부수 작업마다 같은 내용을 여러 줄 중복 표시하지 않는다.
- 기록의 정정/삭제는 엔터티 값을 되돌리거나 할 일을 미완료로 바꾸거나 원칙 본문을 복원하지 않는다. 되돌림은 현재 대상에 대한 별도 명시적 작업이다.
- 이력 수정/삭제를 허용하는 개인 지식 앱이므로 기록의 완전무결한 영구 감사 보존을 약속하지 않는다. 원칙 저장본 보존과 활동 기록 삭제 영향은 구분한다. 활동 표시 항목을 지웠다는 이유로 원칙 저장본까지 연쇄 삭제하지 않는다.

## 원자성·재시도·검색·당시 문맥

- 대상 변경과 필수 활동 기록 저장은 같은 서버 트랜잭션에서 성공하거나 함께 실패한다. 기록 저장 실패 후 원본만 저장됐다고 성공을 반환하지 않는다. 검색 색인 큐 등록도 기존 ADR-0003 경계를 따른다.
- 동일 요청 재시도는 대상과 이력을 중복 생성하지 않는다. expected_version으로 오래된 초안의 덮어쓰기를 막는다. 웹/HTTP/MCP는 같은 change_note·원자성·request_id 의미를 소비한다.
- 메모가 비어 있는 에이전트 수정 요청은 필요한 이유를 먼저 확인하거나 사용자가 실제 제공한 이유를 전달한다. 제품 스킬이 근거 없이 이유를 만들어 채우지 않는다.
- 삭제/이름 변경 후에도 당시 대상·변경 내용·이유를 이해할 최소 문맥을 남긴다. 보안 비밀값/세션/토큰/무관한 계정 정보를 snapshot에 넣지 않는다. 단순 Entity의 현재 prop 컬럼을 동적 payload 모델로 바꾸지 않는다.
- 자동 변경 기록은 의미 있는 제목/요약과 원문 메모를 가지고 활동 검색으로 찾을 수 있어야 한다. 기계적인 반복 문구가 검색을 압도하지 않도록 기록 종류 조건을 제공한다. 과거 원칙은 현재 원칙과 구분해 조회/검색하고 에이전트 기본 문맥에는 현재 하나만 사용한다.
- 구현은 과거 원칙 조회, 사용자 변경 기록, 시스템 식별 정보 각각의 정본을 명시한다. 같은 내용을 두 저장소에서 따로 편집하지 않는다. 전체 애플리케이션을 event sourcing으로 재구성하지 않는다.

## PRD 변경안과 이관

PRD의 원칙 설명을 `사용자당 현재 판단 기준 문서0~1개, 실제 정책 변경은 새 저장본으로 보존, 과거본 정정/삭제 가능`으로 구체화하고 활동 기록의 역할에 `수행 결과와 사용자 데이터 변경 이유`를 추가하는 안이다. 태그는 엔터티/활동 사전으로 분리하고 원칙 태그는 없앤다. 이 티켓은 변경안을 제시하며 PRD·ADR 채택을 완료한 것으로 표시하지 않는다.

기존 복수 활성 원칙을 실제 시간순 편집본이었다고 재해석하지 않는다. 이관 시 현재로 선택할 기준, 다른 문서의 보존과 출처, 엔터티 연결/태그의 처리 결과를 알려야 한다. 기존 태그의 실제 사용처를 조사하고 활동 연결을 보존하며 새로운 엔터티 태그를 분리한다. 원칙에 있던 태그/조건은 무단 삭제하거나 임의 합치지 않는다. 이전 C/U/D를 새 자동 기록으로 소급 생성해 실제 변경 사건인 것처럼 꾸미지 않는다. 운영 이관은 별도 요청 이후에 한다.
