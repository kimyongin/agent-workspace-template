# Template-01 — 할 일·기록·검색의 첫 기능

2026-10-01 · 설계 인계 · 구현 미시작

## 목적과 최소 기반

S1: MCP 연결과 제품 스킬을 묶은 플러그인 설치·인증 → 웹에서 할 일 작성 → 에이전트가 플러그인의 안내와 MCP 도구로 조회 → 사용자 요청으로 완료 결과 저장 → 웹에서 확인 → 다음 질문에서 검색 → 원본 상세 읽기.

이 흐름이 쓰는 인증, HTTP/MCP, 활동 도메인·유스케이스, 로컬 트랜잭션 포트, 검색/임베딩 포트와 Supabase Queues만 연결한다. 특정 앱의 도메인 데이터 없이 실행 가능해야 한다. 검색 색인은 비동기 작업 기반의 첫 사용처다. [프로젝트 컨셉](../product/concept.md), [아키텍처](../architecture/hexagonal-review.md)와 [폴더 구조](../design/template-structure.md)를 따른다.

첫 작업은 최소 입출력·저장 계약 확정이다. [코드 설계 원칙](../architecture/principles.md)과 [개발 방법](../development/workflow.md)을 적용한다. 이 티켓은 S1의 계약·미정 결정·검증 결과를 소유한다.

## 제안 인터페이스

| 작업 | HTTP 경로 예시 | MCP 예시 | 유스케이스 |
| --- | --- | --- | --- |
| 할 일 작성/조회 | POST /tasks, GET /tasks/:id | create_task, get_task | createTask, getTask |
| 완료와 결과 저장 | POST /tasks/:id/complete | complete_task | completeTask |
| 직접 기록 작성/조회 | POST /records, GET /records/:id | create_record, get_record | createRecord, getRecord |
| 검색 | POST /search | search | search |

경로는 api 내부 상대 경로다. 필드·목록·오류·수정·삭제·완료의 계약은 [T02-1 기능 계약](template-02-t02-1-contracts.md#기능-계약-작업-25)에서 정했다. 완료 조건은 domain, 작업 순서와 함께 저장할 범위는 application에 둔다. 같은 연결에서 실행되는 transaction 포트를 Supabase 어댑터로 구현한다. 변경 데이터는 Task, ActivityRecord, 필요한 태그 연결, 최소 요청 식별 정보 및 큐/벡터 데이터다.

## 구현 순서와 검증

1. S1a: 일회성 할 일 생성/조회·완료 기록과 직접 기록 작성/조회를 HTTP·MCP·웹·DB에 연결하고 인증/원자성을 검증한다.
2. S1b: 같은 기록을 pgmq→worker→pgvector로 색인하고 키워드·의미 검색으로 찾아 상세를 읽는다. 실제 공급자 품질, fallback, 수정/삭제 일치를 검사한다. 키워드만 통과하면 전체 완료로 보고하지 않는다.
3. S1 이후의 순서는 [Template-02](template-02-implementation-base.md)가 소유한다. 사용자 원칙은 [PRD](../product/concept.md)의 필수 기본 기능이며 S1b와 함께 T02-3에서 구현한다. 태그 관리와 단일 예제 엔터티도 템플릿 완성 범위다. 반복 할 일은 PRD에 따라 첫 버전에 포함하며 T02-2에서 구현한다. 공유는 별도 PRD가 필요하므로 추가하지 않는다.

완료 조건(굵은 글씨는 이 항목을 완료하는 [Template-02](template-02-implementation-base.md)의 단계):

- [ ] **T02-2·T02-3** 앱별 도메인 테이블 없이 새 격리 DB에서 공통 사용자 흐름이 재현된다.
- [ ] **T02-2** core 금지 의존성 및 웹 직접 업무 RPC 호출 검사 통과.
- [ ] **T02-2** S1에서 채택한 완료 조건을 실제 DB 없이 core 테스트로 검증하며 SQL에 동일 상태 엔진이 남아 있지 않다. 재개·반복 등 후속 행위를 완료 범위에 섞지 않는다.
- [ ] **T02-2** HTTP/MCP 동일 입력의 결과·입력 오류·충돌 의미가 일치한다.
- [ ] **T02-2** S1 기능 계약표의 지원 필드·단건/목록·페이지 탐색을 양쪽 진입점에서 검증하고 후속 기능과 구분한다.
- [ ] **T02-2·T02-3** 사용자 A/B의 목록·상세·검색·쓰기·직접 RPC 권한 거부를 검증한다.
- [ ] **T02-2·T02-3** 보안 가이드의 토큰 위조·잘못된 audience/scope, 참조/커서/요청 키 교체, 과도한 입력·호출, worker 위조, 악성 마크다운·자료 속 지시, 비밀 노출을 관련 경계에서 검사한다. 외부 에이전트 행동 평가와 서버 보장을 구분한다.
- [ ] **T02-2** 동시 완료·부분 실패·응답 유실 후 같은 키 재시도를 실제 DB로 검증한다. 중복 기록이 생기지 않는다.
- [ ] **T02-2·T02-3** 원본과 색인 요청 원자 저장, 수정·삭제·늦은 공급자 응답·모델 변경을 검증한다.
- [ ] **T02-3** 제목+요약을 분할·절단 없이 임베딩하며 본문이 공급자 입력에 포함되지 않는다. 항목당 현재 벡터 하나와 최신 논리 대기 작업 하나를 유지하고 본문만 변경할 때 재임베딩하지 않는다.
- [ ] **T02-3** 요약 작성 기준과 문자/byte/토큰 경계, 요약 누락·입력 제외, 요약에 없는 세부 내용의 검색 한계를 실제 모델로 검증한다. 원본은 보존한다.
- [ ] **T02-2·T02-3** 원본 저장 후 큐 등록 실패 시 함께 롤백된다. 큐 읽기 후 worker 종료, 벡터 저장 응답 유실, 재전달과 영구 실패 재처리를 검증한다.
- [ ] **T02-1 실험·T02-2** 직접 SQL의 사용자 문맥이 자동 적용된다고 가정하지 않고 서버 역할·RLS·일반 사용자 직접 쓰기 차단·연결 재사용 시 사용자 격리를 검사한다.
- [ ] **T02-3** 검색 장애 대체·페이지 일관성·무관 결과 거부를 검증한다. fixture와 실모델 평가를 구분한다.
- [ ] **T02-3** 검색 결과에서 원문과 웹 상세로 접근할 수 있으며, 권한 밖 자료가 검색 후보·요약에도 노출되지 않는다. 결과 없음·색인 지연·검색 실패를 구분한다.
- [ ] **T02-2·T02-3** 웹 작성→MCP 완료→웹 확인→검색→상세 읽기를 실제 DB E2E로 검증한다. 반대 방향 작성/편집도 해당 기능 도입 때 확인한다.
- [ ] **T02-2·T02-4** [디자인 검수](../design/guide.md)의 360/390/768/1024/1440px, computed style, 대비·키보드·200% 확대, 빈/긴/오류/처리 상태, 목록 복귀·초안 보존을 확인한다. 자동·시각·실기기 검증을 구분해 기록한다.
- [ ] **T02-2** 첫 기능이 사용하는 스타일 토큰·공통 UI만 구현하고, 기존 AGENTS·개발 스킬의 디자인/보안 문서 연결을 유지한다.
- [ ] **T02-1 실험·T02-2·T02-4** 실제 에이전트 OAuth/도구 호출을 검증한다. 여러 클라이언트 지원 주장은 각 검증 후 한다.
- [ ] **T02-2·T02-3** Pages의 자산 경로·상세 URL 직접 진입·새로고침과 실제 Google 로그인 복귀를 검증한다. Pinecone의 문서/질의 임베딩 차원 일치, 인증/한도/timeout 실패와 서버 키 보호를 확인한다.
- [ ] **T02-4** MCP 연결과 제품 스킬을 하나의 플러그인으로 패키징하고 신규 설치·업데이트 후 연결과 스킬을 함께 사용할 수 있다. 패키지 버전·해시·서버 호환 범위·클라이언트별 결과를 기록한다. MCP 단독 시험만으로 플러그인 완료를 선언하지 않는다.
- [ ] **T02-3·T02-4** 최소 제품 스킬의 참조·도구 설명 일치와 실제 클라이언트의 자료 탐색·원문 확인 행동을 구분해 검증한다. 스킬 없이도 서버의 접근 제한과 업무 규칙이 유지된다.
- [ ] **T02-2** cold/warm HTTP 지연과 번들/실행 가능성을 검증한다.
- [ ] **T02-6** 빈 새 프로젝트에서 설정·검증·배포 안내를 재현한다. 구현·자동 검사·배포·실클라이언트 완료를 구분한다.
- [ ] **T02-6** 첫 운영 배포 전에 큐 중지·제한 재처리, 이전 artifact 복귀, 격리 환경 백업 복원을 연습하고 결과를 기록한다. 로그·알림·비밀값 설정과 실제 점검 담당/기준을 확정한다.

명령은 실제 템플릿 스크립트를 만들면서 확정한다. core 단위, DB 포트, Edge 타입/번들, HTTP/MCP 계약, 브라우저 E2E, 인코딩 검사를 포함한다. 환경상 불가한 검사는 정확한 commit과 격리 환경으로 인계하며 운영 DB로 대체하지 않는다.

## 상태

현재: 설계 인계, 구현 미시작. S1a는 Template-02 T02-2, S1b는 T02-3에서 구현하며 위 완료 조건은 표시한 단계에서 체크한다. 다음 행동은 [Template-02 T02-1](template-02-implementation-base.md)의 계약·기술 선정이다.

### 이력
