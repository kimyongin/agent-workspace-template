### T21-1 공통 검색·탭 메뉴·fin 시각 규격

- 엔터티/활동/원칙 세 탭 유지. 상단 작업은 제목 우측 햄버거 하나로 제공한다. 엔터티: 등록→엔터티 태그 관리. 활동: 할 일 등록→기록 작성→활동 태그 관리. 원칙 현재 있음: 편집→보기, 없음: 원칙 작성, 조회 중/실패에는 생성 허용하지 않는다. 하단 앱 메뉴는 가이드/설정, 프로필은 로그인 상태를 나타낸다.
- 세 탭 검색 버튼과 외부 검색어 지우기·적용 조건 요약을 제거한다. 입력 안 우측 ×는 검색어가 있을 때만 표시, 44px 누름 영역과 접근성 이름·입력 초점 유지. 검색어 지우기는 즉시 반영한다.
- 텍스트는 마지막 입력/IME 조합 완료 뒤 300ms, 선택·태그·날짜는 즉시 반영. URL 검색 조건과 상세 왕복/스크롤 복원, 입력 초점, 이전 응답 무시를 유지한다. 입력 중 필터가 바뀌어도 최신 조건을 덮어쓰지 않는다.
- 웹 활동·과거 원칙 검색은 mode auto 고정이며 이전 keyword URL도 고정 정책을 적용한다. 실제 의미 검색 대체·색인 지연·장애 표시 유지. 엔터티는 기존 속성1 부분 일치 검색이며 신규 벡터 검색은 만들지 않는다.
- 엔터티 기존 속성3 시작/끝·속성4·정렬은 하나의 필터 disclosure에, 엔터티 태그는 밖에 둔다. 원칙에는 태그·별도 추가 필터를 만들지 않는다.
- fin 배경·중립 surface·Pretendard·72rem shell·모바일16/데스크탑24 여백·compact 제목/목록·하단 탐색을 적용한다. 기존 모달640px/42rem/초점/미저장 보호를 보존하고 영향을 검수한다.

### T21-2 단순 활동 필터·할 일/기록 동시 조회

- 활동 상단에는 검색어, 기록 시작일/종료일, 활동 태그만 항상 표시한다. 할 일/기록 전환, 연결 엔터티, 종류/상태/기록 종류, 검색 방식, 추가 조건 접기, 필터 초기화·전체 기간 버튼을 제거한다. 과거 URL의 제거된 필터가 목록을 몰래 좁히지 않게 정규화한다.
- 검색어·활동 태그는 할 일/기록 양쪽에 적용한다. 태그칩은 복수 선택 OR(하나 이상 포함), 재클릭 해제, 별도 모두 포함/선택 해제 버튼은 없음. 기존 단일 tag_id URL은 호환한다. backend 단일태그 제한은 페이지 후 필터링으로 우회하지 않고 공통 유스케이스/권한/cursor에서 처리한다. 최소 additive tag_ids 입력 확장이 필요하면 기존 HTTP/MCP 소비를 유지하고 관련 보안·계약 검증을 한다. DB 구조 변경 필요성은 먼저 보고한다.
- 할 일 구획은 위, 기록 날짜 타임라인은 아래에 항상 둔다. 날짜 변경/잘못된 범위/기록 오류/결과 없음이 할 일 구획을 제거하지 않는다. 공통 조건 결과가 없는 할 일은 별도 빈 상태를 보여준다.
- 기록 기간은 occurred_at의 사용자 표시 시간대 날짜 경계로 변환, 종료일 전체 포함. 빈값은 무제한, 초기값도 무제한(기존 목록 계약 유지). fin의 최근30일/검색어에 따른 자동 기간 해제는 이번 계약에 가져오지 않는다. 날짜 값은 사용자가 바꾸기 전까지 유지한다. 날짜 삭제로 제한 해제 가능. 시작>끝은 오류와 기존 유효 기록 문맥 유지, 할 일 조건은 계속 반영.
- /tasks를 활동의 기준 URL로 유지하고 /records 구 URL도 활동 목록으로 호환한다. 상세 경로 /tasks/:id, /records/:id는 유지한다. 등록 종류를 선택하려고 탭을 먼저 바꾸지 않아도 각각 모달을 열 수 있다.
- 할 일/기록 두 구획은 독립 조회·cursor·오류·더 보기 상태를 소유한다. 합친 페이지 후 분리하여 한쪽을 누락시키지 않는다. 검색 시 종류별 auto 입력을 보내며 task에는 기록 기간을 보내지 않는다. 필요 이상 중복 검색/임베딩을 피하는 구조를 검토하고 실유료 검색으로 격리 테스트를 대신하지 않는다.

### T21-3 기록·원칙 타임라인과 검증

- 기록과 과거 원칙은 날짜 그룹 카드, 세로선·점·시각·제목·보기/편집(과거 원칙 정정)·요약·변경 메모. 날짜 접기/펼치기는 제거하고 항상 표시한다. 현재 원칙은 별도 상단 단일 문서, 과거 정정은 저장 순서 유지.
- 검색 결과도 해당 타임라인을 사용한다. 검색 DTO와 본문 데이터를 구별하고 메모를 누락시키지 않기 위해 필요한 최소 additive 반환 필드를 공통 계약에 연결한다. 검색은 관련도 기반 결과 회수, 화면은 회수한 결과를 날짜별로 보여준다. 페이지 추가·중복 날짜에서 항목 유실/중복/새 cursor의 임의 변경 없이 목록 문맥을 보존한다.
- 의미 있는 검증: 300ms/IME/최신 필터 경쟁·inline clear 초점, 메뉴 생성/보기/편집과 없는 원칙 상태, 기간 밖 할 일 유지/날짜 경계/잘못된 범위/기록 오류, 양쪽 q/tag 검색·복수 OR·cursor·상세 복귀, 현재/과거 원칙·메모와 타임라인, 기존 CRUD/미저장 보호.
- 단위/빌드/문서/경계 검사, 공유 DOM·동작 변경에 맞는 전체 E2E를 담당 구현 세션이 수행한다. DB/API가 바뀌면 격리 공통/HTTP/MCP/DB 검증 추가. 320/390/640/1024/1440px·200% 확대 대표 화면/메뉴/모달 이미지 증거를 남긴다. 기존 root Vite55480·Supabase·사용자 데이터·비밀값은 보존하며 테스트 소유 환경으로 검증한다.

## 탭 작업 메뉴 제안 — 2026-10-05 후속 요청

사용자가 상단 등록·작성·편집 버튼을 그 옆 햄버거 메뉴 안으로 옮기도록 지시했다. 상단 제목 옆에는 작업 메뉴 버튼 하나만 표시하고, 검색 실행·필터·할 일/기록 전환은 해당 영역에 남긴다. 하단 앱 메뉴는 가이드·설정이며 탭 작업을 중복하지 않는다.

| 탭·상태 | 작업 메뉴 순서 | 범위 |
| --- | --- | --- |
| 엔터티 | 엔터티 등록 → 엔터티 태그 관리 | 새 엔터티와 엔터티 전용 태그 사전 |
| 활동 | 할 일 등록 → 기록 작성 → 활동 태그 관리 | 할 일/기록 어느 보기를 열어도 같은 메뉴·순서. 직접 작성 기록만 작성하며 변경 기록은 CRUD로 자동 생성 |
| 원칙·현재 있음 | 현재 원칙 편집 → 현재 원칙 보기 | 새 최신본 저장과 현재본 상세. 별도의 새 원칙 작성 항목은 없음 |
| 원칙·현재 없음 | 원칙 작성 | 최초 문서 작성만 가능. 편집·보기는 숨김 |
| 원칙·조회 중/조회 실패 | 작성·편집·보기 비활성 또는 숨김 | 현재 문서 부재로 오인해 작성하지 않음. 본문에 상태·다시 시도 표시 |

개별 엔터티·할 일·기록·과거 원칙의 보기/편집(정정)은 해당 목록 행에서 제공한다. 삭제는 대상 상세에서 수행하고 영향 확인을 거치며 탭 메뉴에 전체 삭제를 추가하지 않는다. 현재 원칙 보기는 상세의 저장 정보·삭제 경로를 유지한다. 과거본 정정·삭제는 현재 원칙 편집과 구별한다. 원칙에는 태그 관리가 없다. 검색 조건 초기화는 검색 영역, 새로고침/내보내기 등 미승인 기능은 메뉴에 추가하지 않는다.

아이콘의 접근 가능한 이름은 `엔터티 작업 메뉴`, `활동 작업 메뉴`, `원칙 작업 메뉴`이며 하단 `앱 메뉴`와 구분한다. 44px 조작 영역, 제목 오른쪽 정렬, 오른쪽으로 넘치지 않는 팝오버, 바깥 클릭·Escape 닫기/호출 버튼 초점 복귀를 공통으로 유지한다. 메뉴 선택 시 팝오버를 닫고 해당 1차 모달을 연다. 미저장/처리 중 보호와 상태별 검증은 앱 구현 단계의 완료 조건이다. 현재는 정적 시안만 수정하며 앱 구현은 사용자 합의 후 재개한다.
