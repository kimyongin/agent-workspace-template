## 승인·소유와 목표

사용자는 overview가 개요 목적보다 지나치게 상세하므로 운영 PR·검증 수치와 긴 시작 안내를 정리하도록 요청했다. 추가로 ‘어떻게 개발시키는가’에 멀티·서브세션 설명을 어떻게 넣을지 브리핑을 요청했다. 구현 담당은 overview·START의 유지 기준·필요 workflow/개발 스킬 문구·이 티켓을 소유한다. 메인은 제안 브리핑·독립 리뷰·PR/CI·머지를 조정한다. 전달받은 당일 desktop balanced/medium implement preflight PASS와 고정 `gpt-6.1-sol`/medium 배정으로 작업했다. checkout은 clean이었다.

이번 즉시 구현은 개요 정리다. 멀티·서브세션 새 섹션은 구현하지 않고 아래 제안만 작성한다. 모델 정책·PRD·ADR·앱·브라우저 script/style·운영/공유 서비스·CI 분류기를 변경하지 않는다. 기존 상세 사실은 START/tickets에 있어 복사·이동하거나 당시 기록을 수정하지 않는다.

## 멀티·서브세션 설명 제안

‘어떻게 개발시키는가’의 요청 흐름 뒤, 시작 card 앞에 작은 역할 그림과 짧은 세 설명을 둔다. 사람은 본 대화에서 요청하고 진행·결과를 받는다는 점을 먼저 보여준다.

```text
사람 ↔ 본 대화: 범위·설계 결정, 작업 분할·통합·브리핑
          ├ 구현 세션: 작은 기능 + 테스트·수정
          └ 독립 리뷰 세션: 분리된 검토
```

본문은 세 역할을 각각 한 문장으로 설명한다. 본 대화는 사람과 범위·설계를 정하고 일을 나눠 결과를 모은다. 구현 세션은 작은 기능을 만들고 테스트·실패 수정을 끝낸다. 독립 리뷰 세션은 구현 세션과 분리해 변경과 증거를 검토한다. 이어 ‘독립 작업은 병렬, 의존 작업은 순차로 진행하며 필요하면 통합 검증 담당을 둔다. 사람은 본 대화에서 결과를 본다’라는 짧은 문장을 둔다. 상세 배정·작업 공간·인계 규칙은 [개발 방법](../development/workflow.md#세션-배정과-인계)으로 연결한다.

이는 요청된 설명안이며 이번 overview에 새 섹션으로 적용하지 않는다. 메인이 이미 사용자에게 브리핑한 안과 같은 범위다. 이후 확정된 설명을 적용할 때 실행 이력·모델 metadata·검증 수치를 그림이나 본문에 추가하지 않는다.

## 검증과 인계

직접 검사: `npm run check:docs` 텍스트335개·모델/native 정합성 PASS, 회귀49개 중48 PASS/0 FAIL/기존 Windows file-symlink권한1 SKIP. `git diff --check` PASS. 기존/수정 overview의 모든 script/style 블록과 id 목록 동일, ul 열기/닫기 개수 동일을 Node로 대조했다. 내용 검색에서 overview의 반복 PR/SHA·HTTP200/31tools/queue·현재 미확인/제외 목록이 제거된 것을 확인했다. 실제 diff 내용으로 현재 분류기를 실행해 overview는 full, 나머지 정본 Markdown은 docs, 전체는 full로 확인했다. HTML markup 변경이 원인이며 CI 코드·분류 정책은 유지했다. 실제 시각 렌더링 검증·원격 CI는 이 로컬 문서 검사로 대체하지 않으며 메인에게 후속으로 인계한다.

문서/markup 정리 때문에 현재 CI가 보수적으로 full을 선택할 수 있다. 분류기를 바꾸거나 태그를 유지하는 편법으로 경량 판정을 만들지 않는다. 실제 화면 기능·script/style 변경은 없으며 운영/공유 서비스·추가 모델 호출을 수행하지 않는다. 상세 증거·현재 상태는 기존 정본을 그대로 보존한다.

독립 리뷰에서 작업 티켓 안내 링크가 실제 근거 대신 작성 규칙으로 이동하는 비차단 문제를 확인했다. 메인은 링크 정리 범위에서 START-HERE와 그곳에 연결된 기능 티켓으로 안내하도록 수정했다. 리뷰어는 기존 head에서 Chromium의 넓은/좁은 화면·어두운/밝은 테마 렌더링도 직접 확인했다. 최종 head의 재리뷰·CI·머지는 제출 후 외부 완료 기록에 남긴다.
