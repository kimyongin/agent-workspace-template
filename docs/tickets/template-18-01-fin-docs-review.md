## 요청과 검토 방법

사용자가 fin 레포지터리의 docs를 더 검토하도록 요청했다. 본 세션이 로컬 문서를 직접 읽고 template의 디자인/제품 정본과 관련 구현을 대조했다. 읽기 전용 조사이며 fin 파일·개인 설정·운영 자료는 변경하지 않았다. 배포 화면을 다시 검수하거나 서버 테스트를 실행한 결과가 아니다.

문서가 존재한다는 이유로 확정·구현·배포 상태를 같게 보지 않는다. START-HERE가 가리키는 최신 가이드와 후속 티켓을 먼저 적용하고, 이전 설계의 충돌 문장은 재사용하지 않는다. fin에서 받은 과거 사용자 승인은 template의 제품/권한 변경 승인으로 전용하지 않는다.

## 추가 적용할 내용

1. **태그 사전 관리의 이동 줄이기.** 현재 `TagsPage.tsx`는 이름 변경/추가 때 별도 폼 모달을 연다. 한 관리 페이지 또는 1차 관리 모달 안에서 칩 목록→선택 대상의 인라인 편집 하나→명시 저장으로 제공하는 후보를 추가한다. 초기 미선택·한 초안·다른 태그 선택 전 미저장 보호를 지킨다. 기록 폼의 태그 연결 저장과 사전 이름 변경을 섞지 않고 `/tags` 직접 진입을 보존한다. 대량 태그의 기존 cursor/더 보기를 제거하지 않는다.
2. **선택 전후 화면 흔들림 줄이기.** 선택 수·체크 자리로 라벨/첫 칩을 밀지 않고 칩 순서·폭을 유지한다. 전체 선택 해제는 칩 뒤에 둔다. 현재 template의10개 선택 제한과 단일 필터 계약은 유지한다.
3. **저장 성공과 화면 갱신 실패 분리.** 서버 쓰기 성공 후 재조회만 실패하면 ‘저장됨, 최신 표시를 다시 불러오세요’라고 구분하고 조회만 재시도한다. 같은 쓰기를 새 요청으로 반복하지 않는다. 응답 유실/버전 충돌은 각각 기존 복구 계약을 유지한다.
4. **상세 전환의 초안 보호 확장.** 관련 엔터티·원칙·할 일로 이동할 때도 닫기와 같은 보호가 적용되는지 검증한다. 같은 대상의 늦은 조회/태그 갱신이 본문 초안을 덮지 않고, 폐기 후 재편집은 저장값으로 시작해야 한다.
5. **모드별 검증 분리.** 일회성↔반복 전환 등에서 현재 모드에 해당하는 필드만 검증·전송한다. 숨긴 초안 때문에 저장이 막히거나 이전 모드 값이 섞이지 않게 한다. fin의 구 ‘이미 했음/판단’ 모델은 복원하지 않는다.
6. **검색 결과와 연결/현재 근거 구분.** 검색 점수는 정답 확률이 아니며 저장 기록은 최신 외부 조사와 다르다. 현재 연결된 원칙은 당시 원칙 snapshot이 아니다. 필요한 당시 주장은 기존 기록 본문에 남기는 사용 안내를 보강하고 새 snapshot/이론 테이블을 만들지 않는다.
7. **에이전트와 웹의 성공 의미 통일.** 연결 가이드에서 MCP 인증과 스킬 제공을 구분하고 조회·초안 제안·명시 저장·웹 재조회 흐름을 안내한다. 사용자에게 검색 순서/태그 이름을 반복 지시하게 하지 않되 실제 도구에 없는 동작을 약속하지 않는다. 앱을 열기만 해도 조사/요약 생성이 실행되는 UX를 추가하지 않는다.

## 이미 있는 기준과 유지할 차이

모바일 우선·단일 저장·미저장 보호·44px 조작·역할별 글자·안전한 마크다운·색인 대기/검색 대체·목록 복귀는 template 정본에 이미 있다. 새 가이드나 UI 엔진을 추가하기보다 실제 화면의 누락을 확인해 적용한다.

fin의 원칙은 현재 문서 하나+변경 이력, template는 여러 사용자 원칙+활성 상태+기록의 연결이다. 원칙 탭 전체를 fin처럼 바꾸면 제품 의미가 달라지므로 목록/문서 표현만 가져온다. fin 본문 필수·반복 중단/재개 차이·다중 태그 AND/OR·기간 자동 전환·종목 자동완성도 template 현 계약을 그대로 대체하지 않는다.

fin의 이전 E5/본문 청크/500·1000자 상한은 최신 단일벡터/100·300 계약으로 대체됐다. 그 최신 모델이 같더라도 fin의 cosine 임계값 `0.212384`를 template의 `0.27` 대신 쓰지 않는다. 평가 자료와 도메인이 다르며 이번은 검색 품질/공급자 변경 작업이 아니다. fin의 ‘결과 없이 완료’, 새 후속 task 연결·복잡한 리포트/원칙 이력도 과거 문서를 근거로 추가하지 않는다.

## 구현 인계 보완

상위 PR 분할의 탐색/활동·기록 목록·필터/작성·상세·첫 사용 순서는 유지하되 태그 관리 슬라이스를 추가 후보로 둔다. 상세 overlay보다 먼저 위3~5의 저장/초안 회귀를 기존 소비 화면에서 검증한다. 여러 화면 DOM/행동 수정은 전체 E2E 대상이다.

검증 자료는 중립 Entity·할 일·기록·원칙으로 만든 격리 fixture를 사용한다. fin의 실제 금융 데이터와 과거 사용자 삭제/배포 승인을 재사용하지 않는다. 날짜 자정 경계·동일 시각 정렬·같은 날짜 다음 페이지·긴 제목과 조작 묶음·0/1/30개 태그·선택/해제 전후 간격·추가 조회 실패·저장 성공 후 조회 실패·초안 상태 이동을 포함한다. 필수 화면 검증과 실제 휴대폰/스크린리더의 기존 이관/제외는 구분한다.
