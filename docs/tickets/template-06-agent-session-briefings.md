## 목표와 기준 문서

사용자는 메인 세션에서 기다리는 동안 서브세션이 무슨 작업을 어떤 이유로 어떤 모델·추론 강도로 수행했는지 알면 운영 의사 결정에 도움이 된다고 요청했다. 배정·중요한 변화·완료 시 본 세션이 같은 간결한 형식으로 보고하고, 티켓의 실행 이력과 연결한다. [개발 방법](../development/workflow.md)과 ADR-0007/0008/0010 안의 개발 절차 보강이며 PRD·ADR은 변경하지 않는다.

보고 범위는 세션별 작업 목적·모델 선택 이유·추론 강도 선택 이유·진행/결과·사람의 판단이 필요한 항목이다. 명시 배정과 실제 실행 증거를 구분한다. 없는 backend metadata나 세션별 토큰·비용을 만들어 내지 않는다. 앱·DB·운영 배포, T02-4 재개, 개인 설정 변경, 자동 계측 서비스 구현은 제외한다.
