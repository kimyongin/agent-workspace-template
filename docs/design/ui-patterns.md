# 컴포넌트와 상호작용

[ADR-0012](../adr/0012-current-state-and-unified-records.md)와 [통합 기록 설계](../architecture/unified-record-model.md)가 도메인 계약이다. 상위 탐색은 [ADR-0020](../adr/0020-typed-entity-schema.md)의 프로필+사용자 바로가기 합의를 따르고 자료 종류·할 일·기록 및 추가 로그 없는 기록 편집을 기준으로 화면을 구성한다. 구현과 검증 상태는 관련 GitHub 이슈·PR에서 확인한다.

## 책임과 재사용

표현 계층은 [ADR-0025](../adr/0025-shadcn-tailwind-ui.md)의 Tailwind·공식 shadcn 조합을 따른다. 아래의 조회·저장·초안·URL·권한 계약을 유지하며 이전 색·픽셀·native 구현 지시는 새 [시각 규격](visual-spec.md)으로 대체한다.

목록·카드·테이블은 같은 조회 데이터와 펼침·상세 행동을 공유한다. 기록의 변경 대상도 현재 조회 가능 여부와 무관하게 같은 연결 행에서 접고 펼친다. 삭제 작업의 대상이 없으면 `삭제됨`, 그 외 조회할 수 없으면 `조회 불가`를 제목 옆에 표시한다. 당시 제목과 연결 구획은 유지하고 안내·조회 실패 재시도는 펼친 행 안에 둔다. 현재 원문을 확인하지 못한 대상에는 상세 이동을 제공하지 않는다. 테이블 머리글과 행은 wrapper 구조와 제목 길이에 관계없이 같은 열 정렬을 유지한다. 관계 구획의 접근성 이름은 종류와 개수만 포함하고 보기 방식 선택기는 별도 이름을 제공한다.

각 목록의 늦은 응답은 최신 조건·검색 초안·입력 초점을 되돌리지 않는다. 이전 활동 화면의 두 목록 URL 병합은 호환 전환 검사로 보존하며 현재 바로가기 화면에 sibling readiness를 강제하지 않는다. 검색 행과 대체 상태·색인 coverage 안내는 같은 유효 요청이 갱신하며, 무시한 이전 응답이 안내만 덮어쓰지 않게 한다.

[디자인 가이드](guide.md)의 원칙과 [시각 규격](visual-spec.md)의 값을 사용한다. 이 문서는 구조와 행동만 정의한다. 컴포넌트 이름은 배치 예시이며 실제 소비 기능이 생길 때 만든다.

| 공통 표현 | 소유하는 책임 |
| --- | --- |
| PagePanel | 제목·행동·문맥·필터 구획 |
| PageStack | 페이지가 반환하는 독립 구획 사이의 간격. 라우터·상세 패널·화면 폭에 의존하지 않음 |
| ModalShell / ConfirmDialog | 초점·스크롤·닫기·미저장 보호의 공통 경로 |
| Field / ReadOnlyField | 라벨·입력·도움말·오류 표현 |
| TagChip | 읽기/선택 표현과 접근성 상태 |
| Timeline | 날짜 그룹·항목 배치 |
| MarkdownContent | 긴 본문의 안전한 표시 |

위 표현은 조회·저장·권한·필터 의미·날짜의 업무 의미를 소유하지 않는다. 기능이 데이터와 상태, 이벤트 처리를 전달한다. 공통 컴포넌트가 서버 업무 규칙을 재구현하거나 범용 폼/CRUD 엔진으로 커지지 않게 한다.

상세 화면의 조회 수명은 `src/features/details/useDetailResource.ts`가 소유한다. 객체 ID별로 읽기를 취소하고 늦은 응답을 배제하며, 편집 준비·저장 응답 보존·충돌 후 편집 종료 시 재조회를 함께 처리한다. 저장 성공 뒤 조회 실패는 저장 실패로 되돌리지 않는다. 엔터티의 기존 값으로 편집을 유지하는 정책은 명시적인 옵션으로 보존한다. 폼 초안·저장 시도·업무 행동·URL과 이동은 기존 모듈이 소유한다.

관계 검색과 연결된 할 일의 추가 페이지도 `src/features/collections/paged-list.ts`의 취소·중복 제거·cursor 검증·부분 성공·재시도를 사용한다. 검색 입력의 조합·지연·Enter 실행과 제외 후보는 관계 화면이 소유한다. 엔터티 상세의 초기 5건과 전체 개수는 서버 미리보기이며 실제 첫 cursor 페이지가 아니다. 더 보기를 눌렀을 때 첫 페이지를 읽고 미리보기와 ID로 합친다.

## 공통 화면 패턴

[UI·UX 정돈 방향](ui-refinement-direction.md)을 실제 화면에 적용할 때 다음 구조를 공유한다. 아래는 합의한 목표이며 현재 구현·샘플의 완료 상태와 구분한다. 화면별 세부 표현은 같은 역할의 공통 컴포넌트에서 결정한다.

| 화면 역할 | 공통 구조와 행동 |
| --- | --- |
| 목록 | 헤더는 목록 이름·상태와 목록 전체의 행동을 소유한다. 행은 같은 정보·펼침·개별 행동의 정렬 축을 공유한다. 펼친 내용·인라인 편집을 별도 내부 카드로 거듭 감싸지 않는다. 테이블·카드의 경계와 반응형은 시각 규격을 따른다. |
| 상세 작업 영역 | 한 대상의 보기·편집을 담는 공간이다. 업무 정보·본문·관련 목록의 소속과 우선순위를 유지하며, 패널·모달이라는 외형 때문에 데이터의 의미나 순서를 바꾸지 않는다. |
| 보기 | 개별 속성은 모바일에서도 왼쪽 키·오른쪽 값을 우선한다. 실제 공간이 부족할 때만 작은 보조 키를 위에, 값을 아래에 컴팩트하게 배치한다. 필요한 데이터 아이콘은 키 쪽에만 둔다. 긴 본문은 본문으로 읽고, 테이블의 공유 머리글을 행마다 복제하지 않는다. |
| 편집·작성 | 기존 대상의 편집은 보기와 같은 순서·묶음·정렬을 유지하며 수정 가능한 값만 입력으로 바꾼다. 수정·추가·삭제 예정은 해당 자리에서 표시한다. 저장·취소는 그 편집 범위에 속하며 일반 수정의 별도 변경 검토 화면은 만들지 않는다. |
| 모달·선택 | 제목은 대상·행동을, 본문은 한 작업을, 푸터는 그 작업의 확정·취소를 담당한다. 상세·편집·선택의 공통 패턴을 재사용하고 모달 전용의 다른 행·필드를 만들지 않는다. 초점·스크롤·복귀·초안 보호는 공통 surface를 따른다. |
| 실행 확인 | 데이터 손실·연결 교체·값 변환 등 추가 판단이나 기존 기록 계약에 필요한 경우에만 사용한다. 대상과 실행 결과를 보여주며 일반 편집 내용을 중복 작성하게 하지 않는다. |
| 빈 관련 자료 | 연결·작성을 허용하는 구획은 제목과 실제 가능한 행동을 헤더에 유지하고, 본문에는 연결된 자료가 없다는 짧고 동일한 상태 표현을 둔다. 내용 없는 목록 테두리나 내부 카드를 만들지 않는다. |

빈 관련 자료의 대표 문구는 `연결된 자료가 없습니다.`다. 필요한 안내는 같은 헤더의 `연결`·`작성` 등 실제 가능한 행동을 가리킨다. `오른쪽 연결` 같은 위치 표현은 모바일 재배치와 권한에 맞게 조정하고 존재하지 않는 버튼을 안내하지 않는다. 조회 중·실패·읽기 권한 없음·검색 결과 없음은 실제 빈 상태로 표시하지 않는다. 작성 중의 초기 선택과 저장된 대상의 관계 관리 권한·저장 범위는 기존 계약을 유지한다.

섹션은 데이터의 소속을 표현한다. 자료 종류의 입력 항목과 변경 이력은 형제 섹션으로 두며 이력을 입력 항목 안에 넣지 않는다. 독립 저장 범위를 표현하는 외곽 구획은 유지하되 목록 행·펼친 정보·편집 영역에 내부 박스를 반복하지 않는다. 변경 이력·번호 설정에도 같은 원칙을 적용한다.

펼침은 여러 구획의 탐색이나 긴 보조 정보의 밀도 조절에 실제 이점이 있을 때 제공한다. 한 화면의 유일한 주 편집 영역은 불필요하게 접지 않으며, 기록 자동 완성 입력을 별도 선택기처럼 감추지 않는다. 펼침은 선택값을 바꾸는 드롭다운과 시각·행동을 구분하고 펼침 상태·키보드 동작·초안을 보존한다.

## 페이지와 탐색

사이드바 상단의 공간 선택 메뉴는 공통 워크스페이스 아이콘과 현재 공간 이름을 표시한다. 메뉴는 참여 공간 전환과 현재 선택 표시·조회 재시도를 담당한다. 현재 공간의 구성원·권한·초대 관리와 계정의 공간 목록·생성은 기본 설정과 주 드로어의 공간 그룹에서 접근한다. 현재 공간 관리는 기존 관리 권한을 따르며, 계정의 공간 목록·생성은 공간 없음·설정 접근 불가 상태에도 제공한다. 기존 `/workspaces`와 `/w/:id/manage` 직접 경로와 삭제·복원·탈퇴·초대 복귀 계약을 유지한다.

상단 패널은 제목과 관련 행동 → 필요한 짧은 문맥·요약 → 필터 또는 문서 본문 순서다. 구획이 없으면 구분선과 여백도 생략한다. 같은 검색·기간·태그 조건은 하나의 필터 구획에 둔다. 꾸미기 위해 모든 페이지에 합계·검색·설명 카드를 추가하지 않는다.

엔터티·할 일·기록의 등록/작성은 목록 또는 문서 구획 제목 우측 `＋ 작성` 행동으로 제공하며 모달과 같은 작은 본문 행동 스타일을 사용한다. 태그 관리는 설정의 자료 관리에서만 접근하며 탭에 별도 메뉴를 두지 않는다. 삭제·편집은 상세에서 제공하고 목록 제목은 보기를 연다. 편집 저장은 해당 편집 영역에 둔다. 페이지 제목의 시각 크기는 패널형 화면에서 section-title을 쓸 수 있지만 의미상 h1은 유지한다.

탐색 항목·순서·현재 위치 표시는 앱 전역에서 일관되게 관리한다. 주 드로어는 상단 공간 선택만 드롭다운으로 두고 나머지 목적지를 펼친 그룹으로 제공한다. 개인 바로가기의 자료 종류·할 일·기록 선택과 순서는 Auth metadata에 부분 저장한다. ‘자료’ 그룹은 바로가기에 없는 전체 자료·할 일·기록과 등록한 자료 종류를 함께 표시하며 같은 목적지를 중복하지 않는다. 비어 있는 그룹은 생략하고 종류가 많으면 검색을 제공한다. 종류 이름·아이콘은 정의를 따르며 metadata 변경 뒤에도 종류 ID를 유지한다. 보관된 종류는 일반 바로가기에서 제외하고 자료 그룹에서 보관 표시와 함께 접근한다. 현재 위치는 정확한 종류·할 일·기록 또는 설정 범주를 표시한다. 기존 `/search` 경로를 유지한다.

설정 그룹은 기본·자료·태그·기록 설정을, 공간 그룹은 이 공간 관리와 공간 목록·새 공간을, 도움말 그룹은 상태·사용 가이드·로그아웃을 직접 제공한다. 설정 조회와 공간 관리 권한을 따르며 공간 없음·설정 권한 없음에도 기본 설정·공간 목록·로그아웃은 제공한다. 설정 제목 옆 내부 햄버거와 프로필 팝업은 두지 않는다. 하단 프로필은 저장된 이모지와 이름을 표시하는 정적인 계정 정보다. 모든 목적지는 링크이며 Tab으로 이동한다. 현재 자료 설정 범주를 다시 선택하면 하위 작업 화면과 초안을 유지한다.

좁은 화면에서는 헤더의 주 메뉴 버튼이 공식 Sheet를 열고 넓은 화면에서는 왼쪽 사이드바를 사용한다. 인증된 모바일 화면 상단은 메뉴 버튼·앱 대표 아이콘·Workspace·현재 공간 이름을 한 줄로 표시하며 앱 이름과 공간 이름 사이는 작은 구분점으로 구별한다. 현재 공간 이름은 이미 확인한 공간 문맥을 사용하고 공간이 없는 계정 화면에는 구분점과 공간 이름을 표시하지 않는다. 긴 이름과 글자 확대에서는 텍스트를 축약하며 전체 이름은 접근성 텍스트로 유지한다.

모바일 드로어는 공간 아이콘·현재 공간 이름·선택 화살표로 이루어진 공간 선택과 우측 닫기 버튼을 하나의 고정 헤더에 둔다. 앱 이름·대표 아이콘은 드로어에 반복하지 않으며, 공간 선택 행을 메뉴 안에 중복하지 않는다. 드로어와 탐색 영역의 접근성 이름은 ‘주 메뉴’로 유지한다. 공간 선택은 현재 공간 전체 이름을 접근성 설명으로 제공하며, 매우 좁거나 확대된 선택 영역에서는 장식 아이콘·화살표를 생략해 이름을 우선한다. 공간 선택·닫기는 고정하고 목적지부터 계정 정보까지는 하나의 세로 스크롤로 접근하며 짧은 높이·200% 확대에서도 44×44px 조작 영역을 유지한다. 모바일은 닫기와 Escape로 본문에 복귀하고 실제 경로 이동 후 드로어를 닫는다. 미저장 이동 확인을 취소하면 선택한 링크와 초안을 유지한다. safe-area와 본문 가용 영역을 확보한다. 로그인·OAuth 동의 제목은 유지한다.

설정은 기본·자료·태그·기록 화면으로 나눈다. 자료 화면은 자료 종류·연결 설정·번호 설정·일괄 설정으로 구분한다. 기본 설정에 프로필·날짜와 시각·화면 표시·메뉴 바로가기를, 자료 설정에 종류별 기본 정보·자료 번호·입력 항목·변경 이력을 둔다. 태그와 기록 설정은 대상을 선택해 같은 작업 공간에서 편집한다. 각 입력 구획에 자체 저장·취소를 두며 다른 구획의 초안을 저장하거나 지우지 않는다. 이모지 선택은 설정 입력과 같은 폭을 사용하고 가용 폭에 맞춰 열 수를 자동 조정한다. 두 줄 높이를 유지하며 넘치는 선택지만 내부 세로 스크롤로 표시한다. 20개 이상으로 선택지가 늘어나도 높이는 유지하며 선택 테두리·체크·키보드 초점과 자동 스크롤을 제공한다. 닉네임은 Auth metadata workspace_nickname에 공백을 정리한 40자 이하 한 줄 텍스트로 저장한다. 비어 있으면 공급자의 계정 이름, 그 값도 없으면 내 계정으로 표시하며 드로어에 이메일·로그인 상태를 반복하지 않는다. 표시 시간대는 Auth metadata workspace_timezone에 IANA 시간대 ID로 저장한다. 기기 시간대 사용은 null이며 알 수 없는 값도 기기 시간대로 표시한다. 표시 시간대 저장에도 아이콘과 같은 격리 쓰기·정본 조회·계정 변경·다른 탭 동기화·미저장 이동 보호를 적용한다. 아이콘의 안정 ID만 Auth metadata workspace_avatar_id에 저장하고 기존 공급자 metadata를 보존한다. 알 수 없는 ID는 기본값으로 표시하고 저장 성공 응답 뒤 하단 아이콘을 반영한다. 실패 초안·미저장 이동/로그아웃 폐기 확인·저장 중 중복 요청과 이동 차단을 제공한다. 계정 변경/로그아웃은 이전 계정 표시와 초안을 지운다. 이름·아이콘 metadata는 권한 근거가 아니다.

개인 표시 설정(닉네임·아이콘·표시 시간대·화면 배율)은 기존 Supabase Auth의 사용자 metadata JSON을 사용하며 설정마다 업무 테이블·컬럼을 추가하지 않는다. `src/features/settings/account-preferences.ts`가 저장 키·타입·기본값·검증·metadata 변환을 함께 소유하고 UI와 Auth는 이 계약을 사용한다. 저장은 변경한 필드만 보내 기존 공급자 정보와 다른 설정을 보존한다. 새 개인 설정도 같은 계약과 저장 경로에 추가하며 별도 저장 로직을 복제하지 않는다. 권한·조직 공유 정책·업무 데이터는 서버가 강제하는 해당 도메인 저장소에, 비밀값은 환경별 비밀 관리에 둔다. 개인 metadata를 범용 권한/업무 설정 저장소로 사용하지 않는다.

화면 배율은 설정의 화면 표시 구획에서 모바일·데스크톱 각각 100%(기본)·110%·125%·150%를 선택한다. 화면 폭 1024px 미만은 모바일 배율, 1024px 이상은 데스크톱 배율을 적용한다. 기준은 선택한 배율과 독립적이며 기기 이름이나 UA로 판단하지 않는다. 기존 `workspace_display_scale` 값은 데스크톱 값으로 유지하고 새 `workspace_mobile_display_scale` 값은 기본 100%다. 해상도나 브라우저 확대 값을 바꾸지 않고 공통 글자·간격과 보조 아이콘 크기를 함께 조절한다. 현재 화면에 해당하는 선택을 즉시 미리 적용하고 창 크기를 바꾸면 다른 선택을 미리 보며 저장 승인 뒤 계정 metadata의 확정값을 사용한다. 변경 취소·미저장 이탈 승인은 두 값을 최신 저장 배율로 복원하며 실패는 선택과 미리보기를 보존한다. 새로고침·재로그인은 서버 정본을 읽고 계정 전환·로그아웃은 이전 계정의 배율과 미리보기를 남기지 않는다. 다른 탭의 확정값이 갱신되어도 수정 중 선택은 유지하고 변경 취소는 최신값으로 돌아간다. 브라우저 자체 확대와 기기의 기본 글자 크기를 제한하지 않는다.

같은 계정의 외부 프로필 갱신은 저장값과 하단 표시만 갱신하며 미저장 선택은 유지한다. 깨끗한 선택은 최신 저장값을 따르고, 명시적 변경 취소는 최신값으로 돌아간다. 로컬 저장 성공은 확인한 서버 정본을 선택값으로 채택하고 계정 변경은 설정을 새로 만든다. 프로필 쓰기의 늦은 응답은 provider와 SDK 세션 저장소 양쪽에서 이전 계정을 복원하지 않아야 한다. 장식용 쓰기는 공유 세션과 격리한 SDK 메모리 세션에서 실행한다. 프로필 흐름은 공유 SDK의 세션 조회·refresh·세션 저장을 호출하지 않는다. 표시 정본은 별도 SDK의 명시적 access token 조회로 읽고, 계정 세대·조회 순서와 현재 토큰이 유지될 때 provider의 표시용 닉네임·아이콘·시간대·화면 배율 필드만 갱신한다. 저장 후 조회와 외부 hydration은 같은 조회 순서를 사용한다. 오래된 저장 조회의 성공·실패가 더 최신 조회를 덮어쓰거나 무효화하지 않으며, 저장 완료는 진행 중인 최신 조회까지 기다려 확인된 최신값을 설정의 선택값으로 돌려준다. 최신 조회 실패는 오래된 성공값을 채택하지 않고 표시 재조회 실패로 안내한다. SDK 세션 metadata와 표시 정본은 다를 수 있으며 새로고침·재로그인·Auth 이벤트 때도 서버 표시를 조회한다. 다른 탭에는 계정 ID만 알리고 수신 탭이 자기 토큰으로 다시 읽는다. 원본 저장 성공과 표시 재조회 실패는 구분해 알린다. 태그 편집 중 설정으로 이동하는 단계와 드로어에서 로그아웃하는 단계도 각각 초안 보호를 따른다.

할 일과 기록은 각각의 탭에서 표시한다. 기록은 일반 자료·수행 결과·로그성 메모의 통합 조회이며 별도 활동 탭은 없다. 이전 /tasks·/records의 혼합 화면은 새 경로 의미와 호환 전환을 검증한 뒤 대체한다. 각 목록의 cursor·더 보기·오류와 조건별 적용 범위를 독립적으로 관리한다. 최초 데이터가 없는 엔터티·할 일·기록은 허용된 작성 행동과 사용 가이드 진입을 제공한다. 조건 결과 없음은 최초 빈 상태와 구분한다.

관련 목록의 `entity_id` URL은 일반 선택 필터와 별개로 기존 관련 조회 범위를 보존한다. 해당 관련 목록과 검색에 같은 범위를 적용하고 owner GET으로 확인한 이름·범위 해제를 짧게 표시한다. 이름을 URL 값으로 신뢰하지 않으며 UUID/조회 실패를 안내한다. 명시 해제 전에는 전역 목록으로 넓히지 않는다. 범위 변경은 해당 cursor·목록 위치를 초기화하고 이전 범위 응답을 무시한다. 검색어·태그·날짜는 해제 후에도 보존한다.

보조 메뉴에서 초안이 있는 화면을 떠나려 하면 확인창이 활성화된 동안 진입 링크를 보존한다. 확인창 안으로 초점을 옮기거나 취소 버튼을 누르는 행동은 메뉴의 일반 바깥 조작으로 취급하지 않는다. 취소하면 같은 메뉴 링크로 초점을 돌리고, 이동을 승인하면 새 경로에서 메뉴를 닫는다.

사용 가이드는 엔터티 → 할 일/기록 → 제품 플러그인 → 검색/원문 → 명시 저장/웹 확인 순서로 제공한다. 엔터티 연결은 선택임을 알리고 MCP OAuth와 제품 스킬 설치를 구분한다. 공개 설정에서 연결 주소와 문서 링크를 생성하고 미설정·복사 실패를 텍스트로 안내한다. 복사가 실패해도 주소를 선택할 수 있다. 클라이언트별 설치는 해당 앱의 검증된 플러그인·배포 문서로 연결하며 웹·desktop·모바일 지원을 추측하지 않는다.

## 필터와 목록

주요 목록 탭은 페이지 제목 → 항상 보이는 검색 입력과 필터 아이콘 → 아래로 펼쳐지는 필터 박스 → 목록 제목·보기 선택·오른쪽 작성 버튼 → 목록 순서다. 자료 종류 선택은 검색 입력 위에 두며 보이는 종류 라벨·선택된 종류 이름·자료 설정 링크를 반복하지 않는다. 종류 선택의 접근성 이름은 유지한다.

검색/필터와 결과 목록은 페이지 루트의 서로 다른 구획이며, 필터가 접혀 있거나 결과가 없어도 구획 간격을 유지한다. 목록 도구와 빈 안내/항목은 같은 목록 구획 안에 둔다. 자료 설정의 페이지 제목·탭·현재 탭 설명은 하나의 공통 헤더로 묶고 다음 편집 구획과 구분한다. 간격 값과 소유권은 [시각 규격](visual-spec.md#간격곡률크기)을 따른다.

필터는 검색창 옆의 공식 Button과 Lucide 조절 아이콘으로 제공하며 입력과 같은 조작 높이를 유지한다. 열림은 강조색·옅은 면과 `aria-expanded`·`aria-controls`로 표시한다. `filters=1`은 펼침만 보존한다. 열기/닫기는 조건·검색 초안·조회·페이지·스크롤·앵커를 바꾸거나 이력을 추가하지 않는다. 접어도 편집 중인 필터 초안은 유지하며, 닫힌 상태의 보조 요약과 적용 중 표시는 실제 적용된 조건을 설명한다.

**필터 박스 안의 모든 조회 조건은 초안으로 편집하고, 태그 영역 아래 맨 마지막의 공통 `필터 적용` 한 번으로 함께 반영한다.** 정렬·종류·상태·대상·기간·태그·속성 조건의 적용 시점을 섞지 않는다. 자료·할 일·기록·통합검색에 같은 규칙을 사용하며 검색 결과·합계·URL은 적용 전까지 기존 조건을 유지한다. 속성 조건만의 적용 버튼은 두지 않는다. 미적용 변경이 있을 때만 푸터에 짧은 대기 상태를 표시한다. 박스 안 제목 줄 오른쪽의 작은 `조건 초기화`는 검색어·자료 종류·보기·펼침을 보존하고 필터 초안만 비운다. 초기화도 공통 적용을 거친다. 빈 결과에서 전체 조회로 돌아가는 `검색 조건 해제`는 검색어와 적용 조건을 함께 푸는 별도의 복귀 행동이다.

박스 밖 검색어는 기존 입력 지연·IME 처리를 유지한다. 주요 목록 탭은 검색 버튼 없이 마지막 입력/조합 완료 뒤 300ms 자동 검색하고, 입력 안 ×는 검색어를 즉시 지우며 초점을 유지한다. 검색어 변경은 적용된 필터로 검색하며 편집 중인 필터 초안을 적용하거나 덮어쓰지 않는다. 통합검색의 명시적 검색 실행도 같은 필터 초안 분리를 지킨다. 필터 적용은 가장 최근 검색어·보기·자료 종류를 유지하며 기존 계약에 맞게 페이지·읽기 위치를 초기화한다. 외부 이력 이동·목록/종류 문맥 변경에서는 해당 URL의 적용 조건으로 편집 상태를 맞추고 다른 문맥의 초안이 섞이지 않게 한다. 긴 자료 속성 조건의 fragment도 검색·펼침·적용·직접 주소 복귀에서 유지한다.

잘못된 기간·속성 값은 적용을 막고 해당 입력 가까이에 오류를 표시한다. 현재 결과와 초안을 유지하며 조용히 조건을 빼거나 전체 조회로 넓히지 않는다. 필터 이름·선택 한도·단일/다중·AND/OR·범위·시간대 등 조회 의미는 기존 도메인 계약을 따른다. 자료는 최신 속성 조회, 기록은 과거 자료 검색을 사용하고 할 일의 최신 상태와 과거 기록을 구별한다.

속성 조건은 번호 없는 연속 목록이다. 데스크탑은 `속성 → 비교 → 값 → 삭제`를 한 줄에 정렬한다. 모바일은 같은 항목 안에서 첫 줄 `속성 → 비교 → 삭제`, 둘째 줄 값으로 배치하고 항목 사이 얇은 경계로 묶음을 구분한다. 입력·삭제는 같은 항목 안에 두고 별도 제거 행·반복된 큰 라벨·모바일 전용 번호·표시선을 만들지 않는다. 보이는 열 라벨은 공유하고 입력별 접근성 이름은 유지한다. 글자 확대나 매우 좁은 컨테이너에서 입력이 겹치면 같은 목록 항목 안에서 속성·삭제 → 비교 → 값 순서로 더 재배치한다. 이때 공유 열 라벨은 순서를 안내하는 작은 한 줄로 두고 번호나 별도 삭제 행을 만들지 않는다. 항목 추가는 목록 끝의 작은 보조 행동이다. 정렬 등 짧은 필드는 내용에 맞는 폭을 쓰고 속성 목록·태그 구역은 전체 폭을 사용한다. 태그 선택은 아래 [태그](#태그)의 공통 중앙 모달을 사용한다.

데이터 행·제목·본문은 선택·복사·스크롤할 수 있게 유지한다. 엔터티·할 일·기록의 메인 목록과 상세 연결 목록은 제목 링크로 펼치기 전부터 보기를 연다. 접힌 행에는 공통 목록 규격의 제목·목록별 공통 정보·독립 화살표를 두고, 화살표로 같은 자리에서 미리보기를 펼쳐 읽는다. 연결 관리·할 일 완료·회차 결과 작성과 편집은 보기 안에서 제공한다. 목록에서 직접 편집과 중복된 상세 진입은 제공하지 않는다. 수행 결과는 내용 편집, 변경 기록은 메모 편집을 제공하며 사건 정보는 읽기 전용이다. 같은 자리의 전환은 button, 실제 URL 이동은 link를 사용하고 접근성 이름에는 행동과 대상을 포함한다.

할 일은 제목·본문, 기록은 본문 하나를 표시·입력한다. 할 일 목록의 상태·기한과 원문 태그·속성은 펼친 영역에만 표시한다. 기록의 대표 문구는 마크다운·개행을 읽기 좋게 정리해 목록·연결에서만 계산하며 최대 두 줄과 말줄임으로 표시한다. 펼친 영역과 상세에서는 원문 전체를 읽는다. 상세 shell 제목은 “기록”이며 원문을 한 번 표시한다. 메인 탭 검색도 같은 목록 패턴을 사용하며 일치 구간은 펼친 영역에 표시한다. 기존 혼합 검색 화면은 상세 링크를 유지한다. 비어 있는 태그·본문에는 빈 구획을 만들지 않는다. 입력 라벨·접근성 구획 이름은 유지한다.

상세의 관계는 종류별 ‘엔터티 / 할 일 / 기록’으로 표시한다. 기록의 사건 대상도 해당 종류의 연결 목록에 합치며 같은 종류·ID는 카드와 개수에 한 번만 포함한다. 별도의 ‘변경 대상’ 구획은 만들지 않는다. 해당 카드에 등록·수정·삭제·중단·재개를 보조 정보로 표시하고 수행 결과의 할 일 상태·회차를 유지한다. 사건 대상은 당시 이름을 보존하며 현재 조회 성공 뒤에만 이동 링크를 활성화한다. 삭제/접근 불가와 조회 실패·재시도를 구분한다. 표시 통합은 저장된 관계·사건 식별정보를 바꾸지 않는다.

조작 묶음은 제목 뒤 같은 기준선에 이어지고 공간이 부족하면 묶음 전체가 다음 줄로 간다. 터치 영역은 정상 레이아웃 안에 확보하며 투명 영역을 다른 내용 위에 겹치지 않는다. 스크롤을 시작한 터치가 의도하지 않은 상세 열기로 실행되지 않아야 한다. 본문이 이미 펼쳐진 화면에는 불필요한 보기 단계를 추가하지 않는다.

상세를 닫으면 필터·페이지·스크롤·초점을 복원한다. 저장 후 대상이 목록에서 빠지면 다음 유효 항목이나 목록 제목으로 초점을 옮긴다. 더 보기 실패는 기존 목록을 유지하고 실패 구간에서 재시도하게 한다. 소유자/작업 영역 전환 시 이전 대상의 초안과 조회 응답이 섞이지 않게 한다.

긴 자동 복원은 첫 결과·일정 간격·종료 때 누적 행을 표시해 매 응답마다 전체 행의 렌더를 반복하지 않는다. 실패 시에는 아직 화면에 반영하지 않은 묶음까지 정상 수신한 모든 행을 표시하고, 취소·범위 전환 뒤 응답은 무시한다. 요청 cursor 순서·자동 250페이지 상한·그 이후 수동 추가·상세 복귀 초점은 그대로 유지한다.

## 데이터 표시와 모드 일치

데이터를 보여주는 목록·보기·편집과 설정·검색·연결 후보·확인창에 같은 키–값 표현 원칙을 적용한다. 자료 이름·제목·본문·번호·상태·시각·태그처럼 표시하는 값에는 의미를 식별하는 키를 결합한다. 자료 제목은 종류별 제목 템플릿으로 계산하여 강조하고, 제목에 참여한 속성도 전체 속성의 키–값에 포함한다. 긴 본문은 키에 대응하는 값 영역에서 원문을 읽고 편집한다. 배치는 [키–값과 반응형 데이터 그리드](visual-spec.md#키값과-반응형-데이터-그리드)를 따른다.

- **목록:** 자료 종류별 제목 템플릿으로 만든 제목을 접힌 목록의 식별값으로 표시한다. 카드·테이블·검색·선택·연결·상세가 같은 현재 제목을 사용한다. 행을 펼치면 제목에 포함한 속성을 포함한 모든 현재 속성을 키–값으로 제공한다. 업무상 필요한 공통 식별·상태·시각은 해당 목록 계약대로 키와 함께 제공한다.
- **보기·편집:** 사용자에게 제공하는 전체 속성 집합을 같은 순서·그룹·위치로 제공한다. 자료 제목 템플릿은 펼친 목록·상세·편집의 속성을 숨기는 조건이 아니다. 읽기 전용·사용 중지 속성·번호·상태·사건 정보·연결·태그가 편집 전환으로 사라지지 않게 한다. 내부 저장 필드까지 무조건 노출한다는 뜻은 아니며 값의 현재/당시 문맥과 권한은 유지한다. 빈 값은 미입력 등 실제 상태로 구분하고 0·false를 누락하지 않는다.
- **모드 전환:** 같은 폭에서는 값 영역의 읽기 전용/수정 가능 상태와 관련 행동만 바꾼다. 수정할 수 없는 필드와 연결은 같은 자리에서 정적으로 읽으며 편집 중 별도 원문 편집·연결 작업을 시작하지 않는다. 저장·취소는 같은 보기로 돌아가고 기존 초안·초점·스크롤 보호를 유지한다.
- **태그:** 데이터 영역 마지막에 전체 폭으로 표시한다. 태그 연결·해제는 저장된 대상 보기의 독립 작업이며 신규 작성·본문·속성 편집에 태그 선택기를 넣지 않는다. 신규 대상은 먼저 저장한 뒤 `태그 연결`로 진행한다. 편집에서는 같은 태그를 읽기 전용으로 제공하고 일반 생성·수정 요청에 `tag_ids`를 포함하지 않는다. 독립적으로 확정한 태그 연결을 본문 편집의 저장·취소가 되돌리지 않는다. 변경 기록 확인의 기록 태그는 새 자동 변경 기록의 메타데이터이며 원본 대상의 태그 연결과 구분한다.

보기의 태그 연결·해제는 변경이 허용된 대상에만 제공하며 현재 대상과 같은 범위의 태그 사전에서 선택한다. 변경 기록처럼 태그가 고정된 대상은 보기·편집 모두 읽기 전용을 유지한다. 선택 중에는 초안이며 명시적 완료/적용 행동으로 태그 연결만 확정한다. 개별 해제도 그 연결만 바꾸고 태그 이름이나 원문을 삭제하지 않는다. 태그 사전의 추가·이름 변경·삭제는 기존 태그 관리에서 수행한다. 같은 작업의 중복 실행·실패·결과 미확정·버전 충돌을 구분하고 초안을 보존한다. 웹·HTTP·MCP는 독립 태그 연결·해제 계약을 사용하고 일반 데이터 수정 API의 태그 부분 수정으로 대체하지 않는다. 기존 권한·버전·요청 키·업무 변경 기록 계약을 우회하지 않으며, 별도 연결 저장에 필요한 서버 동작과 호출자 전환은 구현 티켓에서 검증한다. 이 문서 갱신은 해당 동작의 구현 완료 증거가 아니다.

## 읽기·편집과 모달

### 한 대상의 편집 작업

하나의 모델 정의나 업무 대상은 하나의 논리적 작업 화면에서 편집을 끝낸다. 자료 종류의 기본 정보·자료 번호·입력 항목·표시·변경 이력처럼 같은 대상에 속한 설정은 같은 화면의 섹션으로 구성한다. 일반 편집은 해당 입력·행에서 변경을 구분하고 적용→결과 확인으로 이어간다. 데이터 손실·기존 연결 교체·값 변환 등 추가 판단이 필요한 경우에만 검토·확인을 제공하며 같은 입력을 반복하지 않는다. 섹션 이동에는 펼치기·탭·화면 안 이동을 사용한다. 같은 대상의 일부 설정을 고치려고 별도 페이지를 왕복하는 흐름을 기본값으로 만들지 않는다. 상세한 경계는 [UI·UX 정돈 방향](ui-refinement-direction.md)을 따른다.

독립적으로 저장되는 설정은 섹션별 저장을 제공하고, 하나의 편집 초안에 속한 입력은 함께 저장한다. 태그·연결 대상 선택과 조회는 부모 초안을 유지하는 보조 작업으로 열며, 다른 대상의 원본 편집은 별도 대상으로 구분하고 원래 작업의 초안·선택·위치를 보존한다. 직접 링크와 뒤로가기는 같은 작업 화면의 대상·섹션·단계를 가리키며, 읽기나 섹션 이동만으로 쓰기를 실행하지 않는다.

### 편집과 실행 확인

편집은 초안을 만드는 단계이고, 실행 확인(컨펌)은 추가 판단이 필요한 작업의 실행 여부를 결정하는 단계다. 일반 편집은 입력 위치의 변경 표시와 적용으로 끝낸다. 데이터 손실 등 영향이나 기존 저장·변경 기록 계약에 따라 확인이 필요하면 편집→확인→결과로 진행하고, 확인은 편집 화면 위의 작은 중앙 모달로 연다. 원래 편집 화면·입력·스크롤은 그대로 유지하고 확인창만 딤드 배경 위에 표시한다. 일반 모달을 여러 겹 쌓기보다 하나의 보조 화면에서 보기·선택·편집 모드를 전환한다. 서버 검증·기록·원자적 저장 계약은 유지한다.

| 편집 | 데이터 입력·설정·필드 오류. 저장·변경 검토 | 같은 대상의 보기/진입 문맥으로 복귀하며 미저장 변경은 폐기 확인 |
| 실행 확인 | 대상·행동·영향 및 필요한 변경 메모. 저장·삭제·변경 적용처럼 구체적인 실행 이름 | 실행하지 않고 편집으로 복귀. 초안·메모·선택·스크롤을 보존하고 실행 버튼으로 초점 복원 |
| 완료 | 확인한 결과를 같은 대상의 보기나 작업 화면에 반영 | 목록·설정의 현재 문맥 유지 |

저장·검토 시 먼저 입력을 검사하고, 오류는 편집 화면의 해당 항목을 펼쳐 초점을 옮긴다. 긴 영향 분석·값 변환 결과 검토는 작업 화면에서 진행하고 짧은 확인 단계는 마지막 실행 결정에 집중한다. 처리 중에는 중복 실행과 닫기를 막고, 실패 시 입력·확인 내용을 유지해 오류와 가능한 재시도를 제공한다. 응답 미확정은 결과 확인/같은 시도의 재확인 상태로 표시하며 새 실행이나 입력 변경을 자동으로 허용하지 않는다. 원본 저장 성공 후의 조회 실패는 확인한 성공과 분리한다.

편집의 ×·Escape는 편집 취소, 확인의 ×·Escape는 확인 취소와 같은 의미다. 배경 클릭으로 편집/확인 단계를 우발적으로 종료하지 않는다. 화면 크기를 바꿀 때는 배치만 조절하고 초안·선택·펼침·현재 단계를 유지한다. 모달이 열린 동안 배경은 비활성화하고 닫으면 진입 위치·초점을 복원한다. 상세 탭 패널은 일반 작업 화면이므로 목록과의 병행 조작 규칙을 유지한다.

화면 폭·높이, 전체 화면/중앙 모달/상세 패널 전환과 크기는 [반응형과 레이아웃](visual-spec.md#반응형과-레이아웃)을 따른다. 편집/보조 모달은 해당 가용 공간에 맞춰 배치하고 짧은 확인창은 모든 폭에서 중앙에 둔다. 긴 모달은 헤더·푸터를 유지하고 본문만 스크롤하며 동적 viewport·키보드·safe-area를 반영한다.

### 넓은 화면의 상세 작업 영역

100% 배율에서 폭 1280px 이상·높이 480px 이상(다른 배율에서는 두 기준에 배율을 곱한다)에서 엔터티·할 일·기록의 상세는 메인 목록 오른쪽 탭 패널로 열린다. 왼쪽 목록·필터·보기 방식은 계속 사용할 수 있고, 탐색 메뉴의 현재 위치는 왼쪽에 보이는 목록을 따른다. 관련 항목은 먼저 제자리에서 펼쳐 읽고 `상세`를 눌러 새 탭을 열거나 기존 탭을 선택한다. 종류와 ID가 같은 대상은 중복 탭을 만들지 않으며 기존 편집 초안과 모드를 유지한다. 현재 상세 URL은 선택된 탭을 가리키고 직접 링크는 해당 대상의 목록과 상세 탭을 연다.

각 탭은 보기·편집·관련 작성 모드와 본문 스크롤을 유지한다. 저장·취소는 같은 탭의 보기로 돌아가고, 삭제 성공은 해당 탭을 닫는다. 탭의 ×는 해당 대상만 닫으며 인접한 탭을 선택한다. 마지막 탭을 닫으면 목록이 전체 폭을 사용한다. 패널 오른쪽 ×는 탭과 초안을 보존한 채 패널만 숨기며 `상세 탭 보기`로 다시 연다. 목록과 패널은 각각 스크롤하고 패널 숨김·마지막 탭 닫기에도 목록 위치를 보존한다. 탭 선택은 방향키·Home·End, 선택한 탭 닫기는 Delete로 제공하며 닫은 뒤 남은 탭이나 목록 제목으로 초점을 옮긴다.

탭 제목을 좌우로 드래그해 순서를 바꾼다. 놓을 위치는 가는 선으로 표시하고, 실제 drop 때만 배열을 바꾼다. 선택한 탭·URL·초안·본문 스크롤은 유지하며 바깥 drop·취소는 순서를 바꾸지 않는다. 닫기 버튼은 드래그 출발점이 아니다. 키보드에서는 Ctrl+Shift+좌우 방향키(또는 Cmd+Shift+좌우 방향키)로 선택 탭을 이동하며 순서를 안내한다. 탭 닫기의 인접 대상도 변경한 순서를 따른다. 넘치는 탭 줄은 가로 스크롤하며 가장자리 드래그로 숨겨진 위치에 접근한다. 저장 중에는 재정렬을 막는다.

1024px 이상·높이 320px 이상에서는 왼쪽 탐색 메뉴와 목록 사이에도 같은 손잡이를 제공한다. 탐색 메뉴는 기본 13rem, 최소 13rem·최대 20rem 안에서 남은 목록·상세 폭을 고려해 조절한다. 글자 확대 때문에 탐색 메뉴 최소 폭과 작업 화면의 기본 최소 폭 28rem이 함께 들어가지 않으면, 작업 화면의 최소 폭을 손잡이와 탐색 메뉴 13rem을 제외한 가용 폭으로 줄여 내용을 재배치한다. 이때 조절 가능한 범위가 최소 탐색 폭 하나로 제한될 수 있다. 좌우 방향키·Home/End와 더블클릭 초기화는 상세 손잡이와 같은 규칙이다. 메뉴 버튼과 조절 손잡이의 누름 영역이 겹치지 않게 여백을 확보한다. 조절한 폭은 계정별 앱 메모리에만 유지하고 모바일 왕복·배율 변경에도 보존하되 계정 변경에는 기본값을 사용한다. 모바일에서는 헤더의 주 메뉴 버튼으로 Sheet를 연다.

목록과 상세 사이 손잡이를 좌우로 드래그해 너비를 조절한다. 손잡이에 초점을 두고 좌우 방향키로 조절하며, 공식 Resizable의 Home/End는 손잡이 앞 영역의 최소/최대 폭으로 이동한다. 따라서 왼쪽 목록과 오른쪽 상세 사이에서는 Home이 상세를 넓히고 End가 좁힌다. 두 번 클릭은 현재 최소·최대 폭 안에서 기본 비율을 복원한다. 목록·상세의 기본 최소 폭은 각각 28rem·27rem이며, 글자 확대나 가용 폭 감소로 두 최소 폭의 합이 들어가지 않으면 각 최소 폭을 손잡이를 제외한 가용 폭의 절반 이하로 제한한다. 조절한 비율과 편집 초안은 현재 작업 영역에서 탭 전환·패널 숨김/복원·모바일 왕복에도 유지하고 창 크기가 바뀌면 이 범위 안에서 맞춘다. 모바일에는 손잡이를 표시하지 않으며 너비를 DB나 localStorage에 저장하지 않는다.

자료·할 일·기록·검색·설정·가이드·태그·상태 화면 사이의 메뉴 이동은 오른쪽 상세 탭·초안·본문 스크롤과 패널 표시 상태를 유지한다. 메뉴 이동으로 패널을 자동 숨기거나 탭을 초기화하지 않는다. 상세 탭 선택은 왼쪽 작업 화면을 바꾸지 않으며 왼쪽 설정의 미저장 입력도 유지한다. 왼쪽의 다른 화면 이동으로 그 설정이 사라질 때만 해당 초안의 폐기를 확인한다. 탭 전환·주 목록 이동은 초안을 지우지 않는다. 탭 닫기는 그 탭의 미저장 변경을 확인하며, 로그아웃 등 작업 영역을 떠나는 이동은 숨긴 탭을 포함한 모든 초안을 한 번에 보호한다. 양쪽 화면의 이동 보호는 하나의 라우터 차단 지점에서 조정하며, 어느 쪽이든 저장 중이면 이동을 막고 중복 폐기 확인을 열지 않는다. 저장 중에는 탭 선택·닫기·패널 숨김·탐색을 막는다. 변경 메모·삭제·변경 버리기 확인은 작은 중앙 shadcn Dialog를 사용하며 승인할 때만 서버에 쓴다. 저장 뒤 기존 목록을 새로 읽을 때는 받아 둔 행을 유지하고 전체 결과가 준비되면 교체한다. 조회 실패는 저장 실패와 구분하며 목록 재시도로 복구한다.

탭은 계정별 앱 메모리에만 유지한다. 새로고침·로그아웃·계정 전환 뒤에는 이전 탭과 초안을 복원하지 않으며 DB·localStorage에 저장하지 않는다. 열린 데스크톱 탭을 좁은 화면으로 줄이면 활성 대상만 모달로 표시하고, 다시 넓혀도 탭·초안을 유지한다. 처음부터 모바일에서 연 모달은 편집 도중 화면을 넓혀도 그대로 유지하며 닫은 다음부터 패널을 사용한다. 아래 모달의 이전·전체 닫기 규칙은 이 탭 패널을 사용하지 않는 화면에 적용한다.

| 상황 | 기본 패턴 |
| --- | --- |
| 한 대상의 읽기/편집 | 같은 작업 화면에서 모드 전환. 배치에 따라 페이지·상세 패널·1차 모달 사용 |
| 일반 편집의 작은 화면 | 전체 화면, 본문 스크롤과 하단 액션 |
| 넓은 작업 영역의 상세·편집 | 오른쪽 탭 패널, 같은 대상 안에서 모드 전환 |
| 그 외 일반 편집의 넓은 화면 | 중앙 모달, 규격에 따른 폭과 화면 내 높이 |
| 짧은 삭제·변경 버리기 확인 | 모바일에서도 내용 크기의 중앙 확인창 |
| 필수 열 비교를 위한 표 편집 | 명시적인 전체 화면 편집 |

헤더에는 제목과 닫기, 본문에는 현재 대상, 하단에는 취소/저장을 둔다. 조회 전용에 빈 저장 footer를 만들지 않는다. 같은 대상의 속성마다 편집 모달이나 저장 버튼을 따로 만들지 않는다.

모달 푸터의 실행은 밑줄 텍스트가 아닌 공통 버튼 형태를 사용한다. 저장·주요 실행은 강조 버튼, 취소·보조 실행은 기본 테두리 버튼, 삭제는 위험 버튼으로 구분한다. 일반 편집과 변경 기록·삭제 확인 단계 모두 같은 기준을 따른다. 헤더의 이전·닫기 아이콘과 본문의 탐색 링크는 각 역할을 유지한다.

등록·보기·편집은 시각 규격의 화면 크기별 배치를 따르는 같은 shell을 쓴다. 헤더와 footer는 surface 안에 고정하고 본문만 스크롤한다. 짧은 확인창은 모든 폭에서 중앙에 둔다. 동적 viewport·키보드에 따라 가용 높이를 계산하고 safe-area 여백을 둔다. 읽기와 편집은 한 shadcn Dialog를 유지하며 모드만 바꾼다. URL의 `create`와 `edit` 상태를 새로고침·직접 링크·뒤로가기·앞으로가기에 반영한다. 엔터티의 관련 할 일 작성과 할 일 완료·회차 결과 작성도 이 shell의 작성 모드로 전환한다. 일반 취소·폐기 승인으로 닫으면 작성 query를 제거해 새로고침이 취소된 폼을 다시 열지 않게 하며 기존 상세 조건을 유지한다.

상세 보기는 기본 정보·본문·관련 정보를 정렬과 여백으로 나누어 읽는다. 구분선은 헤더·푸터 경계와 목록 행 사이에만 사용한다. 짧은 속성은 항목명과 값을 정렬하고 태그는 작은 칩, 연결된 데이터는 제목 중심의 목록으로 표시한다. 엔터티 보기는 속성과 태그, 관련 할 일·기록을 제공한다. 관련 작성은 해당 구획에, 반복 회차 기록과 기간 이동은 회차 목록에 둔다. 일회성 완료·반복 중단/재개는 보기 푸터에 둔다. 편집에서도 보기의 전체 속성·태그·관계 정보를 같은 자리에 유지하고 수정할 수 없는 값은 읽기 전용으로 둔다. 삭제는 편집 푸터 왼쪽, 저장 진행 버튼은 오른쪽에 둔다. 헤더는 제목과 공통 닫기를 제공한다. 관련 항목의 보기에는 처음 상세로 돌아가는 왼쪽 이전을 제공한다. 편집 중에는 이전을 숨기며 취소로 같은 보기로 돌아온다. 편집의 취소·저장은 진입한 같은 보기로 돌아간다. 목록은 제목 링크로 보기를 열며 편집은 보기 안에서 시작한다. 보기 모드의 ×·Escape는 처음 목록·검색 문맥으로 상세 전체를 닫는다. 편집·실행 확인에서는 위의 단계별 취소 규칙을 따른다. 직접 편집 URL에서도 취소는 같은 대상을 보기 모드로 표시한다. URL과 브라우저 뒤로가기·앞으로가기도 이 진입 문맥을 유지한다. 편집 제거를 반영한 뒤 이동해 미저장 보호와 충돌하지 않게 한다.

### 목록 펼침과 보기·편집

메인 목록과 상세의 연결 목록은 공통 행을 사용하고 경계·펼침 조작·정렬은 [목록 보기별 정렬](visual-spec.md#목록-보기별-정렬)을 따른다. 펼친 속성은 공통 키–값 정렬 축을 사용하며 행 내부에 별도 박스·왼쪽 표시선을 반복하지 않는다. 제목·값·보조 정보의 위계를 유지하고 아이콘 조작 영역은 최소 44×44px이다.

별도 상세가 있는 항목은 제목을 링크로 제공하며 펼치기 전부터 바로 상세를 연다. 제목 왼쪽의 독립 화살표만 미리보기를 펼치고 접으며 aria-expanded·aria-controls와 대상 이름·미리보기 설명을 제공하고 Enter·Space로 조작한다. 테이블·카드·모바일에서 같은 규칙을 쓰며 화살표와 제목의 44px 조작 영역을 겹치지 않게 한다. 별도 눈 아이콘·`상세` 줄은 만들지 않고 허용된 해제 행동은 펼친 행에만 제공한다. 별도 상세가 없는 설정·변경 항목의 제목 펼침과 작성/선택 후보의 독립 조작은 유지한다. 제목 오른쪽 빈 공간·메타데이터·해제는 펼침을 실행하지 않는다. 목록과 모달의 항목은 각각 독립적으로 펼치고 접으며 여러 항목을 동시에 열 수 있다. 보기 선택기 왼쪽의 이중 꺾쇠 아이콘 하나로 해당 구획에서 현재 표시된 항목을 전체 열기/닫기 한다. 하나라도 닫혔으면 아래 방향으로 전체 열기, 모두 열렸으면 위 방향으로 전체 닫기이며 다른 구획에는 영향을 주지 않는다. 다른 항목을 열어도 기존 항목은 자동으로 닫지 않는다. 메인 목록은 반복된 `open` query로 모든 펼침 선택을 보존하되 현재 history entry를 교체하며 필터 변경 시 초기화한다. 상세에서 복귀할 때 펼친 항목들의 내용이 준비된 뒤 스크롤을 복원한다. 모달은 해당 entry의 메모리 보기 상태를 사용한다. 둘 다 업무 데이터를 쓰거나 탐색 이력을 늘리지 않는다. 연결 기록 행에는 종류·날짜·회차를 반복하지 않으며 메인 기록의 시각·사건 정보는 펼친 영역에 표시한다.

펼친 영역은 현재 본문·필요한 속성만 제공하며 또 다른 연결 목록을 넣지 않는다. 기존 기록의 당시 제목과 현재 원문의 내용은 서로 덮어쓰지 않는다. 제목 링크는 미리보기 조회를 선행 조건으로 요구하지 않으며 상세가 현재 원문·권한을 다시 확인한다. 미리보기에서 삭제·접근 불가·조회 실패가 확인되거나 당시 fallback만 있는 대상은 제목을 정적으로 표시한다. 삭제·접근 불가에는 편집을 제공하지 않는다. 제목 링크는 보기 모달이나 기존 상세 작업 영역을 열며, 편집은 그 모달의 편집 버튼으로 전환한다. 목록의 직접 편집과 중복된 상세 진입은 제공하지 않는다. 편집 화면도 현재 원문·권한·버전을 다시 확인한다. 조회 실패는 같은 자리에서 재시도하고 늦은 응답을 다른 항목에 적용하지 않는다. 편집 화면의 역사 관계 정보는 정적 표시로 유지하며 다른 편집 탐색을 시작하지 않는다.

| 행동 | 결과 |
| --- | --- |
| 메인 목록의 제목 링크 | 보기 모달. 연결·작성·완료·편집 기능 제공. 닫으면 같은 목록의 조건·페이지·기존 펼침 상태·스크롤·초점 복원 |
| 연결 행의 제목 링크 | 관련 대상의 보기로 전환. 상세 모달을 중첩하지 않음 |
| 보기의 편집 → 저장·취소 | 같은 모달에서 같은 대상의 보기로 복귀. 현재 데이터 재조회 |
| 관련 보기의 ←·브라우저 뒤로가기 | 처음 상세로 복귀. 펼침·스크롤·제목 링크 진입 초점 복원 |
| 보기 모드의 ×·Escape | 처음 목록 또는 검색 결과로 전체 탐색 종료. 조건·페이지·스크롤·초점 유지 |
| 브라우저 앞으로가기 | 뒤로가기로 돌아온 편집은 현재 권한·버전으로 다시 읽음. ×·Escape로 종료한 편집은 다시 열지 않음 |
| 직접 상세·편집 링크 | 추측한 이전을 만들지 않음. 편집 취소·저장·닫기는 같은 보기, 보기 닫기는 소속 목록 |
| 삭제 | 관련 보기에서 삭제하면 처음 상세로 복귀하고 사라진 대상의 제목 링크 제거. 직접 편집이면 목록 복귀 |
| 미저장·변경 기록 확인의 취소 | 초안·현재 화면·초점 유지 |

엔터티 목록 → 제목 링크로 엔터티 A 보기 → 연결 할 일 B의 제목 링크로 B 보기 → 편집 → 저장 → B 보기 → 이전 → A → 닫기 → 엔터티 목록 순서다. 연결 목록의 화살표로 같은 자리에서 미리보기를 읽을 수 있으며, 제목 링크로 이동하더라도 처음 상세와 현재 대상 한 단계만 유지한다. 검색·관계 검색 후보에서 상세를 열 때도 현재 대상은 교체하고 처음 복귀 문맥을 보존한다.

구현 정본은 src/lib/detail-exploration.tsx와 공통 RelatedItem/RelatedPreviewItem이다. 계정 범위의 메모리에는 경로·제목·스크롤·초점과 펼침 선택만 저장하고 업무 객체·버전·초안·dialog DOM을 넣지 않는다. DB·localStorage·별도 라우터를 만들지 않는다. 브라우저 이력에 같은 최초 상세를 반복 추가하지 않으며, 전체 닫기는 관련 보기와 최초 상세를 종료해 뒤로가기·앞으로가기로 닫은 편집을 반복 재생하지 않는다. 이전 탐색 정책의 history state는 재사용하지 않는다.

새 상세와 연결 목록도 공통 모듈을 사용한다. 화면별 스택·닫기·펼침 구현을 만들지 않는다. 계정 변경은 모든 이전 보기 선택과 복귀 문맥을 폐기한다. 저장 중 이동은 차단하고 미저장 이동은 기존 변경 폐기 확인을 거친다. 삭제된 항목의 초점은 유효한 구획 제목이나 모달 제목으로 복귀한다. 자동 초점용 모달 제목은 초점과 화면 읽기 도구의 진입 위치를 유지하되 테두리를 표시하지 않는다. 버튼·링크·입력칸의 키보드 초점 표시는 유지한다.

읽기에서 편집으로 바꿀 때 두 편집 모달을 겹치지 않는다. 편집 완료/취소 후에는 진입한 읽기 또는 목록으로 돌아간다. 변경 기록이 필요한 등록·수정·삭제·중단·재개는 데이터 입력 뒤 작은 중앙 확인 단계로 전환한다. 편집 shadcn Dialog의 내용·제목·크기를 바꾸지 않고 그 위에 별도의 작은 중앙 shadcn Dialog를 띄운다. 데스크톱 상세 탭도 기존 패널을 유지한 채 확인창을 연다. 확인 중에는 뒤의 편집 화면과 나머지 배경을 비활성화하고 초점은 최상단 확인창 안에 유지한다. 확인 단계에는 대상·행동, 기록 메모와 기록 태그, 취소와 행동별 확인 버튼을 둔다. 삭제의 별도 이유 입력과 버튼 2회 확인은 사용하지 않는다. 확인 중 편집 저장과 내용 변경, 요청 중 이동·중복 실행을 막는다. 실패 시 입력과 확인 상태를 유지하며 응답 미확정은 같은 입력·버전으로 재시도한다. 일반 편집 위의 2차 모달은 실행 확인과 미저장 폐기 의사 확인에 한정한다. 취소·×·Escape는 확인창만 닫고 원래 실행 버튼으로 초점을 돌리며, 필드 오류 보완이 필요한 경우 해당 편집 입력으로 초점을 돌린다. 실패·응답 미확정 시 확인창을 유지하고 완료된 실행의 후속 조회 실패는 저장 실패로 되돌리지 않는다. 태그 관리·관련 대상 탐색 같은 일반 폼을 2차에 넣지 않으며 3차 모달은 만들지 않는다. 수행 결과 저장·기록 자체 편집·태그 이름 등록/변경·설정 저장에는 변경 기록 확인 단계를 추가하지 않는다.

기록 상세는 본문 → 사건 종류·출처·수행 시각 → 종류별 연결 항목 순서로 읽는다. 본문은 일반 본문 크기와 대비를 사용하며 종류·시각은 작은 보조 글자, 연결 제목은 명확한 링크로 구분한다. 할 일은 상태·기한·반복 규칙·완료 시각 같은 업무 정보와 본문, 연결 항목을 제공한다. 포괄적인 ‘관련 정보’ 제목이나 생성·수정 시각의 ‘저장 정보’ 구획을 만들지 않는다. 공통 연결 엔터티 카드에는 저장된 당시 이름을 표시하고, 캡처 시각·저장 경위의 ‘연결 당시 정보’ 펼침 영역을 넣지 않는다. 내부 저장 데이터는 유지한다. 기록의 삭제가 원래 대상의 업무 상태를 되돌리지 않는다는 설명은 삭제 확인 시 제공한다. 빈 연결 구획은 [공통 화면 패턴](#공통-화면-패턴)의 빈 관련 자료 표현을 사용한다.

최상위 대화상자 하나만 키보드와 접근성 트리에서 활성화한다. 뒤 화면은 inert 처리하고 초안·스크롤을 보존한다. Escape·닫기·뒤로가기는 같은 미저장 보호를 거치며 배경 클릭으로 초안을 버리지 않는다. 확인 취소는 원래 초점과 초안으로 돌아간다.

앱은 지원되는 data router를 사용하고 편집 영역의 `useBlocker`로 링크·브라우저 뒤로가기 등 경로 이동도 같은 초안 보호에 연결한다. 로그아웃은 먼저 보호 가능한 경로 이동을 거친 뒤 인증 세션을 해제하며 직접 세션 해제로 초안을 제거하지 않는다. 새로고침·탭 닫기는 `beforeunload`로 보호하되 브라우저가 허용하는 기본 확인창과 사용자 상호작용 조건에 의존하므로 앱 확인창과 같은 표시를 보장하지 않는다.

경로의 검색 조건 변경·뒤로가기·앞으로가기도 초안이 있으면 같은 확인을 거친다. 확인 취소는 현재 URL·초안·초점을 유지한다. 열린 1차 편집 영역이 blocker를 소유하며 닫힌 모달·그 위의 짧은 확인창은 추가 blocker를 등록하지 않는다. 일반 shell 없이 목록에서 실행하는 단독 삭제는 요청의 pending ref를 읽는 busy guard 하나로 경로·POP·beforeunload를 보호한다. 이 guard는 요청 완료 전 이동을 취소하며 초안 폐기 확인을 만들지 않는다. 저장 중 경로 이동 시도는 취소해 저장이 끝난 뒤 이전 이동 의도가 실행되지 않게 한다. 저장 성공과 확인된 취소 뒤의 의도된 이동은 편집 영역이 제거된 다음 실행하며 사용자 이동 보호를 우회하는 공개 상태 플래그를 만들지 않는다.

경로 이동의 폐기 확인은 같은 컴포넌트를 재사용하는 검색 조건 변경에서도 편집 영역을 닫거나 초안을 초기화한 뒤 의도된 경로로 진행한다. `onRouteDiscard`는 편집 영역만 닫는 콜백이며 별도 이동을 실행하지 않는다. 일반 `onClose`가 목록 복귀를 예약하는 화면은 순수 닫기 콜백을 반드시 별도로 제공해 폐기 확인의 목적지와 경쟁하지 않게 한다. 이동이 없는 단순 닫기만 `onClose`를 공용으로 쓴다.

복귀는 공통 header의 이전·닫기 규칙으로 제공하고 `← 목록`·`목록으로` 같은 중복 목록 복귀 조작을 만들지 않는다. 편집 footer의 취소는 상세 전체 닫기와 구분하며 같은 보기로 돌아간다. 저장·삭제 확인·미저장 확인 취소 등 업무 조작은 유지한다. 닫기는 `ModalShell`의 보호된 요청을 사용하며 기능의 `onClose`를 직접 호출해 미저장 보호를 우회하지 않는다. 조건부 렌더링으로 모달을 제거할 때도 닫기 정리와 진입 버튼 초점 복귀를 수행한다. 확인창은 숨긴 읽기 영역과 별개로 표시하고 취소하면 편집 초안과 원래 버튼 초점으로 돌아간다. 연결 작성 뒤 엔터티 보기를 다시 준비할 때는 준비가 끝난 뒤 원래 작성 버튼에 초점을 돌린다.

모달 본문의 바깥 panel/card 테두리·배경·그림자는 제거하고 입력 경계와 코드/표 영역만 유지한다. 공식 ScrollArea 또는 브라우저 기본 스크롤바를 사용하며 기존 외형을 유지하려고 강제로 숨기지 않는다. 프로필 아이콘 선택창처럼 높이가 제한된 영역은 내부 스크롤로 나머지 선택지에 접근한다. 세로 wheel·PageDown·터치와 긴 코드/GFM 표의 내부 가로 스크롤을 제공하며 페이지 전체 넘침을 숨기지 않는다. MarkdownContent는 GFM 표·읽기 전용 체크리스트를 지원하고 raw HTML 실행·위험 URL·외부 이미지 자동 요청을 차단한다.

저장 중에는 중복 제출과 안전하지 않은 닫기를 막고 진행 상태를 보인다. 실패 시 초안을 유지한다. 응답 유실·시간 초과는 성공 여부 미확정 상태를 다룰 수 있어야 하며 영구적으로 화면을 잠그지 않는다. 재조회·재시도는 서버 멱등성 계약을 따른다. 네트워크 취소가 서버 rollback을 뜻한다고 표시하지 않는다.

모든 상세의 연결된 엔터티·할 일·기록은 같은 연결 목록 표현을 사용한다. 섹션 제목과 실제로 아는 전체 개수 → 제목/기록 대표 문구와 접힘 아이콘 → 펼친 본문·속성 순서다. 제목 링크는 펼치기 전부터 기존 보기를 열고, 독립 화살표는 미리보기만 펼치고 접는다. 메인 목록과 연결 목록에 중복된 상세 진입이나 직접 편집 조작을 반복하지 않는다. 연결 당시 엔터티 이름은 카드에서 읽으며 캡처 시각·출처는 화면에 노출하지 않는다. 페이지 조회만으로 전체 개수를 추측하지 않는다. 할 일 상세는 연결된 전체 수행/회차 기록을 별도 목록으로 읽고 현재 회차 기간으로 제한하지 않으며 더 보기·오류 재시도를 제공한다.

엔터티 상세는 속성·태그·연결된 할 일/기록을 읽고 현재 할 일 쓰기 권한이 있을 때 `할 일 작성`·`할 일 연결`을 제공한다. 기록은 원본 업무 변경에서 생성하며 이곳에 일반 기록 작성 행동을 두지 않는다. 전체 목록 링크, 저장/작성 성공 안내, 엔터티 수정 시각과 장식 구분선은 반복하지 않는다. 조회/저장 오류와 재시도는 유지한다.

## 폼

작성은 종류(필요한 경우) → 할 일의 제목·본문 또는 수행 결과 본문 → 일정·시각 → 해당 업무가 허용하는 연결 대상 순서이며 한 초안·한 저장을 유지한다. 초기 태그 선택은 제공하지 않고 대상 저장 후 보기의 독립 태그 연결로 이어진다. 기존 대상 편집은 [데이터 표시와 모드 일치](#데이터-표시와-모드-일치)에 따라 보기와 같은 전체 정보를 유지하고 태그 연결을 별도 작업으로 구분한다. 라벨 → 값 → 오류의 읽기 순서를 키–값 배치 안에서도 유지한다. 글자 수·숫자 범위·비우면 미지정 같은 상시 부연 설명은 제거하고 검증 실패 시 해당 필드에 안내한다. 필요한 예시는 placeholder로 제공한다. placeholder로 라벨을 대신하지 않는다. 짧은 읽기 전용 속성도 같은 라벨·높이·정렬을 사용하되 읽기 전용 상태를 알리고 선택·복사를 허용한다. disabled는 일시적 조작 불가와 구분한다. 긴 기록·설명은 입력칸 모양으로 감싸지 않고 본문으로 읽힌다. 업무 데이터 폼에는 변경 메모를 두지 않는다. 저장 버튼은 입력 검증 후 확인 단계로 전환하며 삭제 의사 확인·미저장 보호·불확실한 응답의 같은 시도 재전송을 유지한다.

할 일의 참고 자료 연결은 제목 검색 후 선택한다. 입력 전에는 전체 목록을 읽지 않고 대소문자를 구분하지 않는 부분 일치로 후보를 찾는다. 300ms 지연과 IME 조합 처리를 적용하고 결과를 페이지 단위로 추가한다. 이미 선택한 엔터티는 검색어·결과·조회 실패와 독립적으로 표시·해제한다. 기존 연결의 저장된 제목은 현재 자료 종류 읽기 권한이 있을 때 표시하고 이름이 없는 선택 ID는 따로 조회한다. 읽기 권한을 잃으면 캐시된 제목·종류·선택 개수와 검색 후보도 숨긴다. 오래된 검색 응답이 현재 후보를 바꾸지 않게 한다.

오류는 해당 필드 또는 폼 가까이 표시하고 label/aria-describedby로 연결한다. 필수 입력은 바로 보이게 한다. 선택 영역을 접었다면 값과 오류의 존재를 알리고 검증 실패 시 펼쳐 접근할 수 있게 한다. 늦은 조회나 저장 실패가 사용자의 입력을 덮어쓰지 않게 한다.

업무 변경의 기본 설명은 확인 단계의 기록 메모에 미리 채워 사용자에게 보여 주고 보충·수정할 수 있게 한다. 확인하면 최종 메모와 선택한 기록 태그를 업무 변경과 함께 저장한다. 빈 메모는 서버의 사실 기반 기본 설명을 사용한다. 기록 태그는 원본 데이터 태그와 별개이며 자동 복사하지 않는다. 확인 취소는 데이터 초안·메모·태그를 보존하고 실행 버튼으로 초점을 돌린다. 실패 시 확인 입력을 보존하며 응답 미확정은 입력을 고정해 같은 ID/version·내용으로 다시 시도한다. 수행 결과 저장과 기록의 편집·삭제는 추가 변경 기록을 만들지 않는다. 메모 길이 등 입력 한도는 새 서버 계약과 함께 확인하며 임의로 축소하지 않는다. 응답 유실 뒤에는 제출한 초안을 고정하고 같은 내용·ID/version으로 재시도한다. 버전 충돌은 초안을 유지하고 명시적으로 폐기한 뒤 최신 원문을 읽는다.

위험 행동은 일반 저장과 구분하며 확인창에 대상과 실제 영향을 적는다. 버튼 이름은 `확인`만 쓰기보다 `삭제`, `변경 버리기`처럼 결과를 표현한다.


### 라벨과 설명

설명 없이도 대상·입력·행동을 이해할 수 있는 구조를 기본값으로 사용한다.

각 화면은 제목 바로 아래에 무엇을 할 수 있는지 쉬운 말 한 문장으로 소개한다. `page-description`의 작은 보조 글씨를 쓰고 별도 박스나 반복 라벨은 붙이지 않는다. 소개는 화면의 역할을 설명하며 본문의 자명한 조작 안내를 반복하지 않는다. 상세와 작성·편집이 전환되면 현재 작업에 맞는 소개로 바꾼다. 실행 확인창은 대상·영향을 설명하는 기존 본문을 유지하고 일반 소개를 더하지 않는다.

- 페이지 제목·섹션명·선택창의 현재 값이 같은 대상을 반복하면 필요한 위치에 한 번만 표시한다. 문맥이 명확한 대상 선택창은 보이는 라벨을 생략할 수 있지만 연결된 숨김 라벨 또는 명확한 접근성 이름을 유지한다. placeholder만으로 입력의 의미를 대신하지 않는다.
- 펼친 목록 행에서 이름 자체를 편집할 때는 기존 제목 자리에 입력을 두어 같은 이름을 제목과 입력칸에 반복하지 않는다. 접힌 행은 이름과 필요한 상태만 표시한다.
- ‘아래에서 설정하세요’, ‘선택한 종류의 설정입니다’ 같은 자명한 상시 안내, 장식용 예시·미리보기, 이미 값으로 드러나는 정상 상태 문구는 추가하지 않는다. 설명이 필요해지는 원인을 먼저 정보 순서·그룹·컨트롤의 이름과 배치에서 해결한다.
- 저장 범위가 섹션이나 편집 행으로 명확하면 ‘저장’·‘취소’처럼 짧은 행동 이름을 쓴다. 범위가 모호하거나 검토·적용·폐기처럼 결과가 다른 행동에는 구분 가능한 이름을 유지한다.
- 입력 의미를 구분하는 라벨·단위·필수 여부, 오류의 원인과 해결 행동, 처리 중·응답 미확정 상태, 삭제 영향과 미저장 변경 확인은 필요한 위치에 유지한다. 정상 상태의 상시 도움말로 반복하지 않고 실제 상황에서 짧게 표시한다. 글자 제거를 이유로 접근성 이름·초점·검증 계약을 제거하지 않는다.


### 편집 날짜 선택기

자료 날짜 속성, 할 일의 기한·반복 시작일, 기록 수행 시각의 날짜, 자료 설정의 날짜 기본값·변환 보완값은 공통 `DateInput`을 사용한다. 공식 shadcn InputGroup·Popover·Calendar·ScrollArea를 조합하고 달력은 처음 열 때 지연 로딩한다. 달력 파일 로딩 실패는 팝업 안에서 안내하며, 바깥 편집 초안과 직접 날짜 입력·저장은 유지한다. 직접 입력은 `YYYY-MM-DD`이며 잘못된 입력도 부모 초안에 보존하고 필드 가까이 오류를 표시한다. 날짜만 있는 값은 시간대 변환 없이 유지한다. 수행 시각은 날짜와 시간 입력을 함께 제공하고 날짜 변경 시 기존 시간을 유지한다.

달력 선택은 초안만 바꾸며 서버 저장은 원래 편집 화면의 명시적 저장 행동이 담당한다. Escape는 달력만 닫고 날짜 입력으로 초점을 돌린다. 날짜 지우기와 빈 값·null의 의미는 호출한 폼이 소유하며 읽기 전용·비활성·저장 중에는 달력도 조작할 수 없다. 월 이동 버튼과 방향키, PageUp/PageDown으로 월 이동, Shift+PageUp/PageDown으로 연도 이동을 제공한다. 직접 입력과 달력의 연도 범위는 1–9999다.

배율·가용 폭·높이를 따르는 팝업 안에서 날짜 누름 영역을 44px 이상 유지한다. 좁은 화면은 달력 내부를 스크롤하고 초점 날짜를 보이는 위치로 이동한다. 검색·목록의 날짜 조건과 기록 목록 달력은 각각의 조회 계약을 유지한다.

## 태그

모든 태그 선택은 공통 중앙 선택 모달을 사용한다. 목록 필터·보기의 태그 연결·업무 변경 확인·기록 자동 완성 설정·디자인 샘플에서 같은 표현을 쓴다. 데이터 신규 작성에는 태그 선택을 제공하지 않고 기존 데이터 편집에서는 태그를 읽기 전용으로 유지한다. 본문에는 라벨 옆 작은 `태그 선택` 행동과 선택한 태그만 표시한다. 선택한 태그는 이름·× 해제를 한 조작으로 제공하며 긴 이름은 줄바꿈한다. 전체 후보를 칩으로 나열하거나 `더 보기`·체크박스 드롭다운·모바일 전용 하단 시트를 만들지 않는다. `전체 해제`는 선택이 있을 때 작은 보조 행동으로 제공하며, 버튼 안에 다른 버튼을 중첩하지 않는다.

선택창은 기존 실행 확인창 계열의 중앙 모달이며 모바일에서도 화면 가운데에 여백을 두고 뜬다. 제목·닫기, 이름 검색, 체크 가능한 후보 목록, 선택 개수·`선택 완료` 푸터로 구성한다. 검색어가 비면 전체 후보를 표시하며 검색은 현재 범위 사전의 이름을 기준으로 한다. 선택과 검색은 독립적이며 검색 때문에 선택을 잃지 않는다. 제목·검색·푸터를 유지하고 후보 목록만 스크롤한다. 검색 결과 없음·빈 사전·조회 중/실패는 구별한다. 관리·생성은 별도 태그 관리 화면의 책임이다.

체크는 호출한 작업의 선택 초안에만 반영한다. `선택 완료`·×·Escape는 선택창만 닫고 선택을 유지하며 호출한 `태그 선택` 행동으로 초점을 돌린다. 필터에서는 공통 `필터 적용`, 업무 변경 확인·기록 설정에서는 원래 저장·변경 확인이 실제 반영을 소유한다. 저장된 대상 보기에서는 태그 영역의 독립적인 `연결 적용`으로 태그 연결만 저장하고 `취소`하면 그 선택 초안만 버린다. 개별 해제 역시 명시적인 연결 해제 행동으로 확정한다. 선택 모달 안에는 별도의 필터 적용이나 서버 저장 버튼을 두지 않는다. 부모가 저장 중이면 선택·해제도 잠그며, 부모 모달 위에서 열어도 원래 입력·변경 확인·초점을 잃거나 부모를 함께 닫지 않는다. 키보드 초점은 최상단 선택창 안에 머물고 너비·높이·배율·가상 키보드 변화에서 검색과 완료 행동에 접근할 수 있어야 한다.

기존 ID와 선택 한도를 보존한다. 단일 태그 필터는 다른 후보를 고르면 이전 선택을 교체하며, 다중 선택은 최대 10개에서 미선택 후보만 비활성화하고 선택 해제는 계속 허용한다. 사전 조회 중·실패에도 기존 선택을 표시하고 개별/전체 해제할 수 있다. 이름을 확인할 수 없는 선택은 삭제로 단정하지 않고 `태그 확인 필요`로 표시하며 해제 행동에 구별 가능한 이름을 제공한다. 제외 대상은 새로 고르는 후보에서 빼되 이미 전달된 선택을 조용히 삭제하지 않는다. 태그가 없으면 관리 안내를 제공하고 가짜 해제 칩을 만들지 않는다.

엔터티·할 일·기록 태그는 서로 다른 사전이다. 같은 이름이 각 범위에 있어도 ID·선택·필터를 혼용하지 않는다. 관리 URL은 `/tags/entity`, `/tags/task`, `/tags/record`이며 `/tags`의 기본 범위는 기록이다.

읽기 정보, 선택/필터, 사전 관리를 구분한다. 읽기 칩은 조작 버튼처럼 보이지 않게 하고 누른다고 임의로 필터를 바꾸지 않는다. 행의 주 대상 이름이라면 작은 칩 대신 제목 역할을 사용한다.

선택 칩은 고정 곡률과 줄바꿈 배치를 사용하고 모달의 체크박스는 라벨까지 포함하는 44px 이상 조작 영역·그룹 이름·선택 상태·키보드 초점을 제공한다. 선택은 경계·면·체크로 구별하며 hover가 선택 상태를 덮어쓰지 않는다. 활동 필터는 최대 10개 복수 OR, 자료 필터와 통합검색의 기존 단일 태그 조회는 최대 1개다. 한도를 넘는 기존 활동 URL은 처음 조회부터 10개만 적용하고 URL 정규화·변경 안내를 유지한다. 선택 UI 전환으로 조회의 AND/OR나 서버 계약을 바꾸지 않는다.

목록은 최초 태그 사전 응답 뒤 읽기 위치를 복원하고, 실패 재시도 중 기존 행을 유지한다. 화면 복귀·목록 탐색·업무 저장과 태그 저장 성공 시 해당 범위 사전을 재조회하며, 응답이 늦어도 이전 조회가 최신 이름을 덮어쓰지 않는다. 조회 사전에서 찾지 못한 ID는 삭제로 단정하지 않고 확인 중·확인 필요로 표시한다. 공유 사전은 같은 범위에만 사용하며 혼합 검색에서만 종류를 명시한 통합 사전을 사용한다. 목록 사전 오류와 재시도는 필터 구획에서 안내하고 행에는 짧은 읽기 상태만 표시한다. 응답으로 이름 줄바꿈이 바뀌면 현재 읽던 행의 화면 위치와 초점을 유지한다.

ID로 선택을 유지하고 이름 변경으로 선택을 잃지 않는다. 긴 이름은 줄바꿈하며 tooltip만으로 전체 이름을 제공하지 않는다. 연결 선택은 부모 초안에 반영하고, 태그 생성·이름 변경·삭제는 별도의 1차 관리 화면에서 다룬다. 버튼 안에 삭제 버튼을 중첩하지 않는다. 태그 수가 늘어도 본문은 선택한 태그만 유지하고 후보 탐색은 공통 선택 모달에서 완료한다.

이전 태그 직접 주소는 호환용 공통 모달 shell로 열고 닫기·Escape는 진입한 목록/설정의 조건·읽기 위치·초점으로 돌아간다. 직접 URL 진입은 엔터티 태그는 엔터티 목록, 할 일 태그는 할 일 목록, 기록 태그는 기록 목록으로 닫는다. 새 태그 입력란에서 바로 추가하고 선택한 행에서 이름을 변경한다. 별도 보기·등록·이름 변경 모달은 만들지 않고 한 초안·한 저장을 유지한다. 선택 전환·취소는 미저장 보호를 공유하고 삭제는 현재 화면 안에서 두 단계로 확인한다. 삭제 실패 후에는 확인 상태·입력·버전을 유지하며 자동 목록 재조회로 실패한 행을 제거하지 않는다. 불확정 생성은 같은 내용과 요청 ID로 재시도하며 확인 전 입력 변경을 막는다. 이름 변경의 불확정 응답은 ID로 최신 목록을 확인하고 충돌에는 초안을 유지한다. 저장 성공과 후속 목록 조회 실패를 별도로 표시하며 조회 실패가 저장 성공을 실패로 바꾸거나 기존 목록을 지우지 않게 한다.

중복 이름과 버전 변경은 같은 오류 코드라도 구분한다. 중복 이름은 이름을 정정한 뒤 같은 초안에서 저장할 수 있으며 버전이 실제로 달라졌을 때만 최신 태그를 다시 선택하게 한다. 저장·삭제 뒤 재조회가 시작되면 이전 더 보기 응답은 취소하거나 무시해 새 정렬 경계·커서를 덮지 않게 한다.

## 자료 설정 작업 화면

자료 설정은 기존 앱 탐색 하나와 상단의 종류 선택·종류 추가으로 구성한다. 자료 종류 전용 두 번째 탐색 열이나 전체 저장은 두지 않는다. 종류 선택은 별도 검색창 없이 드롭다운에서 바로 선택하며 빈 상태·보관 종류·긴 이름을 구분한다. 기본 정보·자료 번호·입력 항목·변경 이력은 기본으로 접고 제목과 필요한 상태를 표시한다. 현재 종류는 상단 선택값으로 표시하고 이름·아이콘을 아래 제목으로 반복하지 않는다.

처음 자료 종류를 만들 때는 선택할 기존 종류가 없으므로 종류 선택·추가 툴바와 중복 안내를 생략하고 생성 폼을 바로 표시한다. 기존 종류가 있으면 생성 중에도 선택창으로 돌아갈 수 있게 하되 같은 생성 화면을 여는 추가 링크는 두지 않는다. 종류 편집 중에는 선택창에 기존 종류만 표시하고 추가는 옆 버튼으로 구별한다. 편집 화면의 종류 추가로 진입하면 새 종류 이름에 초점을 옮기며 종류 전환의 미저장 확인·취소와 입력 보존을 유지한다.

제목 템플릿·속성·순서는 입력 항목 섹션 안에 통합하며 같은 변경안을 공유한다. 별도 화면 표시 섹션이나 속성·표시 외부 패널을 두지 않는다. 입력 항목을 접으면 설명·변경 취소·변경 검토를 숨기고 초안은 유지한다. 소속 헤더의 항목 추가는 유지하며 누르면 섹션과 새 행을 함께 연다. 수정 중·처리 중·결과 확인 필요는 접힌 제목에도 남긴다. 접힌 행 제목이나 오른쪽 펼침 버튼으로 열고, 오른쪽 접기 버튼으로 접으며 입력을 보존한다. 제목 버튼이 이름 입력으로 바뀔 때는 새 입력으로 초점을 옮긴다. ‘항목 추가’는 새 행을 즉시 열고 항목 이름·데이터 타입을 입력받는다. 필수 여부·설명·조건·생성 기본값과 관리는 추가 설정에 둔다. 내부 속성 키·기술 정보·값 없음 허용·행별 접기/완료 버튼을 표시하지 않는다. 선택 항목은 행으로 이름을 편집·추가·제거하며 이름 변경으로 기존 코드를 바꾸지 않는다. 새 선택 항목의 표시 이름은 검토에서 키를 발급받은 뒤 설정할 수 있고 이유를 안내한다.

제목 템플릿은 기록 문구와 같은 변수 칩 편집기로 설정한다. 속성 선택으로 변수를 넣고 일반 문자와 조합하며 예시 제목으로 확인한다. 변수는 속성 이름으로 보이고 저장값은 안정된 속성 키를 참조한다. 속성 순서는 행 제목 옆 위/아래 버튼으로 조정하며 입력·상세의 키–값 순서에 적용한다. 순서 경계에서 조작이 비활성화되면 같은 항목의 다른 순서 조작이나 제목으로 키보드 초점을 유지한다. 추가 버튼은 입력 항목 목록 헤더 오른쪽, 사용 중지·항목 삭제는 항목 내부 오른쪽, 변경 취소·변경 검토는 입력 항목 섹션 내부 하단 오른쪽에 둔다. 페이지 전체의 별도 액션 footer는 두지 않는다. 삭제는 위험 버튼과 영향 설명·취소 가능한 확인창을 제공하며 실제 삭제는 검토·적용 뒤에 이루어진다. 사용 중지는 기존 값을 보존하면서 필수 여부를 해제한다. 제목에서 참조하는 속성의 중지·삭제는 제목 템플릿도 함께 고쳐 검토한다.

새 선택 입력과 사용자가 필수 여부·데이터 타입을 바꾼 선택 입력은 null을 허용하며 필수 입력은 null과 빈 일반 텍스트를 금지하는 정의를 만든다. 자료 입력 폼은 미입력(키 생략)과 정의가 허용한 명시적 null을 구분한다. oneOf의 null 분기도 해당 title과 배열의 표시 순서를 따르며 문자열 코드 "null"과 구별한다. 가져온 정의의 required는 키 존재 여부이고 nullable이면 명시적 null도 허용한다. 필수 일반 텍스트의 빈 값과 공백은 minLength·pattern 등 실제 속성 제약을 따른다. 제목 조합 결과가 공백뿐이면 자료 번호를 제목으로 사용한다. 값을 지우면 실제 정의가 허용할 때 null로 처리하고 null 불가 정의의 선택 항목은 키를 생략한다. 0과 거짓은 실제 값으로 보존한다. 읽기만으로 기존 정의·자료를 변환하지 않으며 API/MCP 부분 수정의 키 생략 의미는 유지한다.

입력 항목과 변경 이력은 공통 CollectionList의 공식 Table 조합으로 연속 행과 행 경계를 표시한다. 펼친 입력은 해당 행 바로 아래에 이어지며 제목과 속성 열의 위치를 유지한다. 입력 항목의 펼치기/접기는 공통 목록 기준에 따라 제목 앞의 별도 조작 열에 둔다. 위/아래 이동은 작은 outline 아이콘과 충분한 터치 영역을 사용하고 제목·필드의 기준선을 밀지 않는 별도 행동 영역에 둔다. 좁은 화면의 요약과 펼친 내용은 [목록 보기별 정렬](visual-spec.md#목록-보기별-정렬)의 같은 내용 시작선을 사용한다. 자료 종류 선택 아래 이름을 반복하지 않고, 종류별 기록 자동 완성은 기록 설정에서 중첩 박스나 제목 없이 입력과 저장을 제공한다. 액션 아래에 종류 이름·속성 버전을 반복하지 않는다. 변수 삽입은 메모 템플릿 위에 두고 예시 출력은 제공하지 않는다. 기본 문구 사용 상태는 반복하지 않고, 사용자 문구가 있을 때만 템플릿 아래 오른쪽에 되돌리기를 둔다. 버튼은 [버튼의 문맥과 크기](visual-spec.md#버튼의-문맥과-크기)를 따른다. 종류 선택 옆 종류 추가와 선택값 입력 옆 제거는 이웃 입력과 짝을 이루는 일반 버튼이며, 독립적인 항목 추가·되돌리기·이력 조회/더 보기는 작은 보조 행동이다. 섹션 하단의 확정/취소와 확인창은 작업 푸터다. 공유 변경 기록 설정도 같은 문맥 기준을 사용하며 기존 구조와 저장·충돌·응답 불명 보호를 유지한다.

변경 검토는 현재 입력을 포함하여 변경안을 저장하고 성공을 확인한 같은 변경안에만 영향 분석을 접수한다. 저장 성공 뒤 입력 항목을 유지하고 같은 위치에서 검토·적용한다. 변경 이력은 필요할 때 펼쳐 조회한다. 별도 검토 영역이나 저장한 변경안 목록은 두지 않는다. 행 안에서 변경 전후·검토 진행·문제 수·자료별 결과·보완 입력을 확인한다. 직접 링크·읽기만으로 분석을 시작하지 않는다. 입력 항목 제목을 눌러 같은 변경안을 편집할 수 있으며 오류는 해당 입력 행·추가 설정을 열고 초안을 보존한다.

미적용 변경 행의 하단에는 폐기와 상태별 주요 행동을 오른쪽 정렬한다. 성공 검토는 변경 적용, 미검토 저장안은 변경 검토, 실패는 검토 재시도, 보완 입력은 보완 내용 검토, 결과 불명은 같은 요청 다시 확인을 제공한다. 값 변환은 최신 성공 검토와 보완 저장을 마친 뒤에만 실행한다. 적용 완료·폐기된 변경은 읽기 전용이며 입력 항목을 열 때 최신 설정을 확인하고 새 변경을 시작한다. 오래되어 적용할 수 없는 미적용 변경도 폐기할 수 있다. 폐기는 확인창 후 변경안을 종료하고 이력·현재 자료·정의는 보존한다. 이미 적용한 변경은 폐기하지 않으며 활성 값 변환은 먼저 취소해야 한다. 변경안 폐기와 미저장 편집 취소, 값 변환 작업 취소를 구분한다. 실패 행·값 변환·복구가 필요한 변경에서만 변환 준비를 제공한다.

명확한 섹션 안에서는 저장·취소로 표시하고, 변경 검토·적용·폐기처럼 결과가 다른 행동은 구분한다. 독립 섹션의 저장/취소는 다른 초안을 덮지 않으며 접힌 섹션에도 미저장·오류·진행 상태를 표시한다. 새 속성 참조 등 적용 순서가 필요한 설정은 입력 옆에 안내한다. 접기/이력 확인/공통 영역 열기는 입력을 폐기하지 않는다. 종류 전환과 화면 이탈에는 미저장·처리 중·불확정 응답 보호를 적용한다.

속성 검토·영향 분석·게시와 필요한 값 변환 규칙/전후 미리보기/실패 보완/진행/취소/재시도는 같은 작업 화면에서 이어간다. 변경 이력은 변경안·값 변환·적용 버전을 하나의 시간순 행 목록으로 표시한다. 최초 버전은 최초 생성이며 이후 버전은 해당 변경 행의 버전 N · 적용됨 상태로 표시한다. 별도 값 변환 작업 구획과 게시 버전 목록은 두지 않는다. 변경 이력은 공통 CollectionList의 행 정렬과 경계를 사용하며 별도 왼쪽 표시선·내부 박스를 중첩하지 않는다. 변경 제목 아래에 날짜를 보조 글자로 표시하고, 버전·상태는 오른쪽 열에 둔다. 펼침 화살표는 공통 목록 기준에 따라 제목 앞의 별도 고정 폭 열에 두며 긴 날짜·상태·확대에서도 제목과 조작 위치가 움직이지 않게 한다. 좁은 화면은 가로 스크롤 없이 라벨과 값을 한 쌍씩 세로로 배치하고 제목·라벨·펼친 본문의 시작선을 맞춘다. 목록 아래 다시 조회는 왼쪽 정렬의 작은 본문 행동이다. 행을 열면 해당 변경안 또는 불변 버전의 입력 정의를 읽기 전용으로 표시하며 모든 속성의 라벨/값 기준선을 같은 위치에 맞춘다. 아래 변경 결과는 버전·상태를 한 번만 표시하고 중복 버전 차이 제목이나 항목명만의 굵은 강조를 두지 않는다. 변경 목록은 같은 본문 글자 규격으로 표시한다. 해당 변경의 출발/완료 버전을 비교하며 현재 최신 버전과의 비교나 같은 버전끼리의 비교를 표시하지 않는다. 역사 정의를 입력 초안으로 채택하지 않는다. 각 변경 행을 펼치면 버전 차이·여러 변환 실행·진행/실패/취소/재시도·원본 복구 가능 여부와 복구안 검토/실행을 확인한다. 변환 작업 직접 링크도 같은 변경 행을 열며 활성 변환에는 중복 실행·폐기·규칙 편집을 제공하지 않는다. 진행/실패 상태는 접힌 이력에만 숨기지 않는다. 기존 서버의 분석/적용/복구 계약과 원본 보존·버전·동일 요청 재시도를 유지한다.

태그 관리는 일반 설정의 태그 관리 링크 하나로 진입하는 통합 화면이다. 자료 설정처럼 상단 관리 대상 선택창에서 자료·할 일·기록을 전환하고 같은 태그 섹션에서 추가·이름 변경·삭제한다. 사전은 대상별로 독립적으로 유지하며 미저장 변경에는 대상 전환과 화면 이탈 보호를 적용하고 저장·삭제 중에는 대상 전환을 막는다. 브라우저 뒤로 가기로 설정에 복귀한다. 번호 출처와 번호 종류는 자료 설정의 번호 설정에서, 종류별 자료 번호 연결은 자료 설정에서 편집한다. 종류별 기록 문구는 기록 설정에서 관리하며 미설정/null이면 고정 기본 문구를 표시한다. 보조 영역을 겹겹이 열지 않는다. 직접 주소와 새로고침은 같은 통합 화면에서 정확한 종류·변경안·작업을 표시하고 브라우저 이력도 실제 사용자 작업을 따라간다. 입력 본문을 브라우저 영구 저장소에 보관하지 않는다.

## 관련 자료와 활동 기록

기록 화면은 수행 결과·자동 변경 메모의 읽기와 검색을 제공한다. 직접 메모·참고 문서는 자료로 작성한다. 완료·회차 결과는 할 일 상세에서 본문·수행 시각을 입력하며 일반 기록 작성 진입은 제공하지 않는다. 결과와 변경 메모의 편집·삭제는 추가 변경 기록을 만들지 않는다. 자동 변경 기록의 사건 시각·대상·행동은 읽기 전용이며 메모 수정으로 원래 업무 상태를 되돌리지 않는다. 내용 수정과 검색 반영의 상태는 구분해 확인한다.

변경 기록의 저장된 경로·대상 이름은 당시 정보이며 현재 존재나 접근 권한을 보증하지 않는다. 기록의 관계 구획은 실제 고정 부모 하나를 기준으로 표시하고 과거 사건 대상을 별도 부모로 추가하지 않는다. 당시 제목·행동은 사건 정보로 읽되 현재 부모 원문 GET이 성공한 경우에만 상세 진입을 제공한다. 소프트 삭제된 할 일도 현재 권한으로 읽을 수 있으면 삭제 상태를 표시하고 보존된 상세로 이동한다. 404 not_found는 삭제와 권한에 따른 비공개를 구분하지 않고 “삭제된 대상 또는 접근할 수 없는 대상”으로 표시한다. 다른 조회 실패는 재시도를 제공하며 삭제로 단정하지 않는다. 당시 사건 정보는 이 조회로 수정하지 않으며 늦은 응답은 다음 대상에 반영하지 않는다.

## 타임라인과 긴 본문

시간순 기록에만 날짜 그룹을 사용한다. 날짜 제목 아래 기록은 공통 목록의 옅은 면과 전체 높이 세로선으로 묶고 행 사이에는 공통 목록의 옅은 구분선을 두고 마지막 행은 생략한다. 접힌 기록은 두 줄 대표 문구만 표시하고 펼치면 전문 → 검색 일치 구간(검색 결과일 때) → 종류·시각·관련 정보·태그 순서로 읽는다. 제목/본문 대표 문구 링크로 펼침 전부터 상세를 열며 화살표만 미리보기를 조작한다. 장식 세로선은 접근성 트리에 포함하지 않는다.

그룹 날짜와 시각은 업무 시간대로 표시하며 서버의 안정 정렬을 유지한다. 템플릿 기록에는 별도 시간대 필드가 없으므로 설정의 표시 시간대(기본값: 기기 시간대)를 웹 시각 표시·날짜 그룹·기록 기간 검색·기록 시각 입력에 함께 적용한다. 목록 필터에는 시간대 안내를 반복하지 않는다. 저장된 UTC 시각과 기존 반복 할 일의 일정 시간대는 변경하지 않고 새 반복 할 일의 초기 시간대에만 설정값을 사용한다. 기록 편집을 시작한 시간대를 초안 동안 유지하고, 시각을 바꾸지 않았으면 원래 UTC 값을 그대로 보존한다. 서머타임으로 존재하지 않는 입력 시각은 오류로 표시하고 중복 시각은 이른 시각을 선택한다. 기간은 해당 지역 날짜의 시작부터 다음 날짜 시작 직전까지로 계산하여 23/25시간인 날도 포함한다. 연결된 반복 할 일의 시간대는 그 할 일의 회차 날짜만 결정하며 기록 그룹에 적용하지 않는다. 페이지가 같은 날짜로 이어지면 기존 그룹에 합치고 항목 중복·접힘 초기화를 방지한다. 일부만 받은 그룹의 개수를 전체 건수처럼 표시하지 않는다. 날짜 그룹은 항상 펼쳐 표시하고 날짜 접기 조작은 제공하지 않는다. 검색은 관련도 기반으로 페이지를 회수하고 회수한 항목만 발생/저장 날짜별로 표시한다. 화면의 날짜 정렬이 검색 전체를 날짜순으로 회수한다는 뜻은 아니다.

마크다운은 공통 렌더러로 문단·제목·목록·인용·링크·표·코드를 표시한다. raw HTML과 실행 가능한 URL을 실행하지 않는다. 초기 기본은 외부 이미지를 자동 로딩하지 않고 대체 텍스트/안전한 링크로 제공한다. 코드와 넓은 표만 내부 가로 스크롤을 허용한다. 줄임은 목록 미리보기에 한정하고 원문 자체는 변경하지 않는다.

## 상태 표현

### 업무 설정과 기록 자동 완성

기록 자동 완성은 기록 설정에서, 종류별 자료 번호는 자료 설정에서 편집한다. 번호 출처와 번호 종류는 자료 설정의 번호 설정에서 재사용하며 자료 설정 안에서도 초안을 유지한 채 연결·편집한다. 표시 설정과 별도로 저장하며 각 구획의 초안·저장 상태를 이동 보호에 포함한다. 다른 구획 저장이 미저장 입력을 덮어쓰지 않는다. 같은 설정 ID의 버전 충돌 때 최신 설정을 읽어도 초안 전체를 보존하며 자동 병합하지 않는다. 충돌 중에는 저장을 막고, 최신값 읽기가 성공한 뒤 기존 취소 버튼을 ‘최신값으로 다시 편집’으로 표시한다. 이를 선택하면 최신값을 초안에 적용하여 다시 편집·저장할 수 있다. 읽기 실패나 진행 중에는 이 버튼을 비활성화한다.

기록 템플릿은 자료 종류·할 일과 행동별 메모·기록 태그를 설정한다. 변수 삽입은 메모 입력 위에 두고 속성의 이름으로 표시하며 내부 속성 키와 장식용 예제를 반복하지 않는다. 자료 문구가 미설정이면 고정 기본 문구를 사용하고, 사용자 문구가 있을 때만 기본 문구로 되돌리는 행동을 제공한다. 유효하지 않은 변수나 문법은 해당 문자 위치·이유를 입력 옆에 표시하고 저장을 거부한다. 변경 확인창은 서버가 실제 입력으로 준비한 메모·태그를 기본값으로 채우며 사용자가 각각 수정할 수 있다. 확인 취소는 본래 입력과 수정한 메모·태그를 유지한다. 확인창에는 템플릿 다시 적용 버튼을 두지 않으며 직접 수정한 메모·태그는 취소 후 재진입과 동일 재시도에도 유지한다. 세부 계약은 [ADR-0015](../adr/0015-change-record-templates.md)를 따른다.

메모 입력은 서식 없는 문장과 변수 토큰만 편집하며 브라우저의 굵게·기울임·밑줄 서식을 저장 가능한 기능처럼 제공하지 않는다. 속성 정의를 읽기 전이나 읽기에 실패했을 때는 내부 키를 노출하는 입력 대신 상태와 재조회를 제공하고 관련 변수 삽입·저장을 막되 초안 원문은 유지한다. 메모 안의 알려진 변수도 이름으로 읽는 작은 토큰으로 표시한다. 토큰은 내부 정본 변수에 결속하며 표시 이름 변경·동명 속성·특수문자가 저장 대상을 바꾸지 않는다. 일반 문장과 토큰은 한 입력에서 키보드로 편집하고 선택 위치에 삽입하며 복사·잘라내기·붙여넣기와 실행 취소를 지원한다. 복사할 때는 정본 변수 표기를 유지해 다른 템플릿에 붙여넣어도 같은 속성을 가리킨다. 알 수 없는 변수·미완성 표기·달러 이스케이프를 임의 별칭으로 고치거나 버리지 않는다.

엔터티 작성은 번호 출처·발급 모드·설정 버전을 준비한 다음 값을 입력한다. 자동 발급은 외부 자료 번호를 생략하고 생성 성공 응답의 정본 ID를 사용하며, 직접 입력한 외부 자료 번호는 대소문자·앞자리 0을 보존한다. 동일 조합이 삭제 상태이면 보관값과 복원 의도를 먼저 보여주고 현재 버전으로 확인한다. 활성 중복을 일반 편집으로 덮어쓰지 않는다. 등록한 자료 종류·번호 출처·번호는 불변이며 보기·편집에서 읽기 전용 값으로 제공한다. 종류 이름이 이미 모달 제목에 있으면 본문에서 반복하지 않는다. 소프트 삭제 대상의 기존 연결은 유지하고 새 검색 후보에는 표시하지 않는다. 세부 계약은 [ADR-0021](../adr/0021-type-scoped-immutable-identity.md)을 따른다.

| 상태 | 표현과 복귀 |
| --- | --- |
| 최초 로딩 | 로딩 안내, 빈 데이터로 단정하지 않음 |
| 데이터 없음 | 무엇을 만들 수 있는지와 허용된 첫 행동 |
| 필터 결과 없음 | 조건을 유지하고 해제/변경 제공 |
| 조회 실패 | 원인 범주의 짧은 안내와 재시도. 기존 자료가 있으면 유지 |
| 저장 중/실패 | 진행·오류와 초안 유지. 중복 실행 제어 |
| 비동기 접수/처리/완료/실패 | 실제 서버 상태에 맞는 문구와 가능한 재시도 |
| 검색 지연/장애 | 색인 미반영 또는 대체 검색 여부를 표시 |

원본 저장 성공 뒤 최신 조회가 실패하면 저장 완료와 조회 실패를 함께 알리고 조회만 재시도한다. 이전 자료는 유지하며 재조회 응답이 편집 초안이나 더 최신의 저장 결과를 덮어쓰지 않게 한다.

일시 알림만으로 중요한 실패나 삭제 영향을 전달하지 않는다. 상태 문구의 크기는 시각 규격을 따르고 기능별로 임의의 배지 색·로딩 패턴을 만들지 않는다.

## 정보 묶음과 시각 위계

### 목록 보기 방식

엔터티·할 일·기록의 메인과 상세 안의 관계 목록은 기본 테이블과 카드 보기를 선택한다. 독립 리스트 선택지는 제공하지 않는다. 목록 이름과 회수한 개수를 같은 줄에 표시하고 바로 옆에 작은 아이콘 선택기를 둔다. 아직 다음 페이지가 있으면 개수 뒤에 +를 붙이며, 조회 전/실패를 0개로 단정하지 않는다. 전체 건수가 제공되는 관계 목록은 그 값을 사용한다. 작성·연결은 구획 오른쪽의 별도 행동이다. 검색 후보와 작성/편집 중 선택 입력에는 보기 선택기를 추가하지 않으며 같은 테이블 규격을 사용한다. Combobox·Select·Command의 옵션과 필드의 태그 Badge는 입력 부품의 의미를 유지한다.

카드는 같은 자료를 작은 면에 배치하고 제공된 속성을 보조 크기로 표시한다. 테이블은 제목/본문 대표 문구 앞에 펼침 조작 열을 두고 제공된 비교 속성을 머리글 아래에 정렬한다. 좁은 실제 작업 영역에서는 같은 셀을 제목 아래 라벨–값 한 쌍씩 세로로 재배치하며 제공하는 모든 속성을 유지한다. 자료의 접힌 항목은 계산한 제목을 표시하고 펼치면 제목에 참여한 속성까지 전체 키–값을 표시한다. 제목·라벨·펼친 본문의 시작선과 값 열을 맞추고 가로 스크롤을 만들지 않는다. 요약 관계 항목만 제공되는 목록은 내용을 얻기 위한 일괄 조회를 만들지 않으며 한 내용 열로 표시할 수 있다. 모든 보기의 펼침·상세·편집·해제는 기존 행동을 공유한다. 보기 전환은 서버 검색/목록 회수 조건을 바꾸거나 쓰기를 하지 않는다. 기록의 긴 대표 문구는 줄여 표시하고 원문은 상세/펼침에서 읽는다.

메인 보기 선택은 URL의 view에 저장하며 필터·페이지·열린 항목·스크롤과 함께 상세 왕복 후 복원한다. view가 없거나 예전 list·알 수 없는 값이면 테이블로 해석하며 유효한 카드·기록 캘린더는 유지한다. view·calendar_month·calendar_day는 서버 목록 조건이 아니며 필터 초기화도 view를 유지한다. 상세별 각 관계 구획의 보기 선택은 기존 상세 이동 상태에 보관한다. 접힘/펼침은 같은 항목이며 보기 전환으로 별도 상세/편집 진입을 만들지 않는다.

기록 메인은 캘린더 보기를 추가한다. 사용자 표시 시간대의 occurred_at 날짜로 월·날짜와 해당 날짜의 기록을 표시한다. 선택 월/일은 calendar_month·calendar_day에 보관한다. 달력은 검색/필터로 이미 회수한 기록을 투영하며 검색 결과의 회수 순서나 cursor를 바꾸지 않는다. 다음 페이지가 있으면 불러온 기록만 표시한다는 안내와 더 보기를 유지하고, 빈 날짜는 이 날짜에 불러온 기록이 없다는 의미다. 실패한 회수는 오류와 재시도를 유지하며 완전한 달력으로 표현하지 않는다. 방향키는 날짜/주 단위로 이동하고 월 경계를 넘을 수 있다.

상세는 핵심 내용 → 업무 속성·태그 → 연결·참고 항목 → 행동 순서다. 엔터티는 헤더 제목을 속성에 반복하지 않고 나머지 속성과 태그를 묶는다. 할 일은 본문과 상태·기한·반복 규칙을 같은 주요 구획에 둔다. 기록은 본문을 먼저 읽고 사건 종류·주체·시각은 작고 연한 보조 정보로 표시한다. 기록 본문까지 연하게 만들지 않는다.

간격 값은 [시각 규격](visual-spec.md#간격곡률크기)을 따르며 구획을 소유한 stack이 정한다. 형제 요소 선택자·페이지별 보정으로 구분선을 반복하지 않는다. 포괄적인 기본/관련 정보 제목과 내용 없는 장식 구획을 만들지 않는다. 연결 목록 제목은 상세 제목보다 작고 덜 진하게 표시하며 각 항목의 경계는 메인 목록과 같은 시각 규격을 따른다. 엔터티의 빈 연결 목록도 공통 빈 상태와 현재 권한이 허용하는 할 일 작성·연결 진입점을 유지한다. 조회 실패·로딩·빈 실제 목록은 여전히 구별한다.

목록은 접힌 제목/본문 대표 문구에서 시작해 펼친 본문·속성·시각·상태·태그로 읽는다. 자료의 현재 속성은 제목에 참여한 항목까지 키–값으로 표시하고 미입력·null·숫자 0·거짓을 구분한다. 보기는 제목/본문 대표 문구 링크, 편집은 상세 보기의 푸터에서 제공한다. 변경 전후 값은 펼침 정보로 둔다.

태그 관리의 등록·변경은 목록 안 입력과 행 행동이다. 설정은 최대 48rem에서 프로필·날짜와 시각·화면 표시·자료 관리를 간결한 구획으로 나누고 자료 관리 행동을 구획 왼쪽에 정렬한다. 가이드는 최대 56rem에서 번호·제목·본문·행동을 같은 구획에 묶는다. 태그 관리·설정·가이드·로그인·동의·검색·빈 상태·오류도 공통 색·글자·곡률·입력과 버튼 규격을 사용한다. 검색어·검색 행동을 강조하고 상세 조건은 펼침으로 관리하되 조건 적용 여부를 표시한다. 설정은 항목별 정보와 행동을 묶고 로그인·동의는 주된 행동을 강조한다. 동의 대상·권한·이동 주소, 저장 오류·불확실한 응답·검색 색인 상태처럼 판단에 필요한 정보는 제거하지 않는다. 일반 모바일 모달은 전체 높이, 짧은 변경 확인만 내용 크기로 중앙에 배치하며 작은 화면·키보드에서는 본문이 스크롤되고 행동은 남는다.

## 군더더기 없는 관계·편집 흐름

연결 목록은 제목·개수·현재 가능한 작성/연결 행동을 유지하고 [공통 화면 패턴](#공통-화면-패턴)의 짧은 빈 관련 자료 표현을 사용한다. 조회 중·조회 실패는 빈 상태로 단정하지 않고 필요한 안내·재시도를 유지한다. 페이지를 더 받을 수 있으면 받은 개수 뒤 +를 표시한다. 할 일 날짜 입력은 일회성의 기한 또는 반복 규칙 등 실제 필드 라벨만 두고 “일정” 같은 포괄 제목을 덧붙이지 않는다.

엔터티·할 일·기록의 메인 목록과 상세 연결 제목은 상세 링크이며, 미리보기 펼침은 제목 왼쪽의 독립 화살표로 제공한다. 기존 혼합 검색도 상세 링크를 유지한다. 제목 오른쪽의 빈 공간·메타데이터·카드 테두리는 펼침이나 이동을 실행하지 않으며 제목 자체의 최소 터치 높이는 유지한다. 제목을 길게 선택·복사할 수 있다.

새 할 일 작성의 참고 자료 선택은 제목 검색 → 검색 결과 → 선택한 엔터티 순서다. 선택한 항목은 표준 연결 목록과 같은 제목 위계를 사용하고 해제 버튼으로 초안에서 제거한다. 검색 입력의 Enter는 검색만 실행하며 상위 폼을 저장하지 않는다. IME 조합 중 Enter도 저장으로 전달하지 않는다.

### 상세 보기의 관계 관리

엔터티↔할 일의 저장된 관계와 태그 연결은 보기 화면에서 관리한다. 할 일 편집은 제목·본문·일정을 수정하고, 연결과 태그는 같은 자리에 읽기 전용으로 유지한다. 편집 저장은 관계·태그 필드를 다시 쓰지 않는다. 연결된 구획의 제목 옆에 새 데이터 작성과 기존 데이터 연결을 구분해 제공한다. 엔터티에서는 현재 할 일 쓰기 권한으로 할 일 작성·할 일 연결을 제공하고, 할 일에서는 참고 자료 연결과 명시적 완료·회차 결과 작성을 제공한다. 참고 자료 선택에는 해당 종류의 현재 읽기 권한을 적용한다. 새 엔터티 작성은 엔터티 탭의 기존 작성 메뉴를 사용한다.

기존 연결은 제목 검색을 펼쳐 현재 사용자에게 접근 가능한 항목을 부분 일치로 찾는다. 빈 입력은 전체 데이터를 나열하지 않는다. 검색 후보와 연결 목록은 같은 평평한 목록 위계를 사용한다. 후보의 제목 링크와 연결 버튼, 연결된 행의 제목 상세 링크·독립 화살표와 해제 버튼은 각각 분리한다. 제목 옆 빈 공간은 클릭 영역으로 확장하지 않는다. 이미 연결된 후보를 중복 선택하지 않으며 긴 연결 목록은 추가 페이지를 제공한다. 양쪽 화면은 할 일의 동일한 관계를 변경하고 별도 양방향 관계를 저장하지 않는다.

후보 상세를 확인하고 이전으로 돌아오면 검색 펼침·검색어·추가 페이지·진입한 제목 초점을 복원한다. `useDetailViewState`는 해당 history entry의 보기 선택만 계정별 provider 메모리에 보관한다. 후보 객체와 버전은 보관하지 않고 현재 권한으로 다시 조회한다. 새로고침·새 탭·계정 전환에 이 임시 검색 상태를 유지한다고 가정하지 않는다. 기록 목록을 갱신할 때도 열려 있는 완료·회차 결과 초안과 초점을 유지한다.

연결·해제는 최신 할 일과 버전을 확인한 뒤 작은 변경 기록 확인 단계에서 기본 메모와 기록 태그를 입력받는다. 원래 보기·편집 영역을 유지한 채 작은 중앙 확인창을 겹치고 실패·미확정 재시도·이동 보호를 유지한다. 취소는 보기로 돌아가며 최신 관계를 다시 확인한다. 버전 충돌을 자동으로 덮어쓰지 않는다. 연결 해제는 해당 관계만 제거하고 엔터티·할 일 원문과 기록의 고정 부모는 유지한다.

할 일의 결과 작성은 완료하고 기록·회차 기록의 명시적 업무 동작으로 수행한다. 결과는 같은 워크스페이스의 해당 할 일 하나에 고정 소속되며 참고 자료 배열·문맥을 복사하지 않는다. 기록의 부모를 고르거나 옮기거나 해제하는 일반 연결 조작은 제공하지 않는다. 메모·문서 작성은 자료 종류로 관리한다.

할 일 삭제는 같은 ID·내용·결과·회차 기록을 보존하는 상태 전환이다. 삭제 상태에서는 일반 수정·완료·회차 작성·중단/재개·참고 자료 및 할 일 태그 연결을 비활성화하고 현재 할 일 쓰기 권한으로 복원을 제공한다. 할 일 읽기 권한을 잃으면 열린 확인창·태그 선택창을 포함한 대상의 제목·본문·선택 개수를 숨기고 권한이 돌아왔을 때 보존된 초안을 복구한다. 읽기만 허용되면 초안과 미확정 요청을 유지한 채 저장을 막는다. 복원과 응답 불명 재시도는 처음 확인한 대상·버전·요청 키·메모·입력을 유지한다. 작성자 표시는 보관된 이름만 사용하고 계정 ID·이메일을 대신 표시하지 않는다.

보기·편집은 shadcn Dialog 하나의 모드 전환이다. 편집 푸터에 취소·저장을 두고 취소는 보기로 돌아간다. 보기 모드의 헤더 ×·Escape는 상세 전체를 닫는다. 편집·실행 확인의 닫기는 [편집과 실행 확인](#편집과-실행-확인)의 단계별 취소 규칙을 따른다. 미저장 초안은 해당 목적지로 이동하기 전 보호하며 폐기를 승인해도 같은 질문을 두 번 하지 않는다. 변경 버리기 확인창은 활동 기록 확인창과 같은 내용 크기의 중앙 디자인을 쓰고 취소하면 초안과 초점을 유지한다.

상세 화면의 일반 편집 수명은 `useDetailEditor`가 소유한다. URL의 편집 의도를 읽고, 저장·취소에서는 편집을 제거한 다음 URL의 `edit`·`edit_from`만 정리해 이동한다. 삭제는 호출자가 정한 목적지로 이동하고, 경로 폐기는 편집만 제거하여 이미 승인한 이동을 다시 실행하지 않는다. 엔터티의 관련 작성과 할 일의 완료·회차·중단/재개는 해당 화면이 소유하며 일반 편집보다 우선한다. 같은 shadcn Dialog·초점·미저장 보호는 `DetailSurface`가 소유한다.

업무 폼과 태그 삭제의 기록 확인 수명은 `useRecordConfirmation`의 공통 implementation을 사용한다. 메모·기록 태그·오류·취소·단계 등록을 함께 처리하며, 저장 시도는 `WriteAttempt`가 같은 실행 내용과 ID/version을 유지한다. 확인 취소는 초안과 메모를 보존하고 미확정 저장 시도를 초기화하지 않는다. 서버의 메모·태그 필드 오류는 해당 입력에 표시한다. 기록 자체 편집·수행 결과의 저장에는 업무 변경 확인 단계를 추가하지 않는다.

### 본문 보조 버튼

작성·연결·해제·검색 닫기는 공식 Button의 ghost·outline 등 역할에 맞는 variant와 Lucide 아이콘으로 제공한다. 주요 저장보다 낮은 위계를 유지하며 실제 조작 영역은 최소 44×44 CSS px이다. 이전 보조 버튼 시안의 크기·배경을 재현하지 않는다.

작성은 +, 연결은 체인, 해제는 끊어진 체인, 검색 닫기는 × 아이콘을 사용한다. 보이는 문구는 `작성 / 연결 / 해제 / 닫기`다. 상세 이동은 대상 제목 링크로 제공한다. 접근성 이름에는 대상과 행동을 포함하고, 검색의 `닫기`는 해당 검색만 접는다고 구분한다. 저장된 목록의 해제는 펼친 행에만 표시한다. 제목 링크의 현재 읽기 권한은 상세 진입 후 재확인하며, 해제는 기존에 허용된 관계 관리 조건과 최신 소유 할 일 확인·변경 확인·서버 권한 검증을 유지한다. 구획의 작성·연결과 검색 후보의 연결, 작성 초안의 선택 해제는 행의 펼침과 독립적인 행동이다.

가이드의 단계별 이동과 첫 사용 안내도 같은 보조 행동을 쓴다. 가이드는 순서가 있는 제목·본문·행동을 여백과 단계 사이 구분선으로 연결하며 단계마다 별도 카드를 만들지 않는다. 빈 연결 목록은 공통 빈 상태와 제목·개수·작성/연결 행동을 남기고 내용 없는 목록 외곽선을 표시하지 않는다. 태그 관리 목록은 부모 작업 카드의 면을 공유한다. 새 태그는 충분한 폭에서 이름 입력과 추가를 한 행에 두고, 편집의 삭제·취소·저장은 아래 행동 행으로 분리한다.

설정의 본문 푸터는 여백으로 입력과 분리하고, 고정 모달 푸터는 기존 면과 상단 경계를 유지한다. 필터의 속성 조건은 번호 없는 연속 목록으로 정렬한다. 좁은 화면은 첫 줄에 속성·비교·삭제, 다음 줄에 값을 두고 충분한 폭에서는 한 줄에 정렬한다. 추가/제거는 해당 목록의 보조 행동이며 적용은 태그 아래의 공통 필터 작업 푸터에서만 제공한다.

### 관계 구획과 기록 작성

관계 구획 제목은 종류와 개수(`할 일 (2개)`, `기록 (0개)`)로 표시하고, 그 안의 행동은 `작성 / 연결`로 줄인다. 접근성 이름은 `할 일 작성 / 할 일 연결 / 회차 기록`처럼 종류를 포함한다. 작성은 새 원문을 만들고 연결은 기존 원문을 선택한다. 초점 복원은 보이는 텍스트 대신 접근성 이름 또는 안정 식별자로 대상을 구분한다.

할 일 신규 작성의 선택적 참고 자료는 제목 검색으로 고른다. 종류·현재 읽을 수 있는 개수 옆의 `연결`로 검색을 펼치고 `닫기`로 접는다. 접어도 선택·검색어를 보존하며 펼침·접기는 초안을 수정하지 않는다. 검색 결과와 선택 목록은 공통 평평한 행과 `연결 / 해제` 보조 버튼을 사용한다. 선택 제목은 정적 텍스트이고 작성 중 다른 원문 편집을 시작하지 않는다. 해제 뒤에는 열린 검색 입력 또는 닫힌 검색 행동으로 초점을 돌린다. 선택은 초안이며 저장 전에는 서버 연결을 바꾸지 않는다. 완료·회차 결과에는 참고 자료나 다른 할 일 선택을 넣지 않는다. 기존 기록 편집은 본문·허용된 시각을 정정하고 실제 고정 부모와 저장된 태그를 읽기 전용으로 유지한다. 수행 결과 태그는 저장 후 보기에서 독립적으로 연결·해제하며 자동 변경 기록의 고정 태그는 이 조작으로 바꾸지 않는다.

태그는 엔터티·할 일·기록별 독립 사전이다. 변경 확인에서 고르는 태그는 원문 태그가 아닌 새 변경 기록의 고정 태그다. API/MCP `scope`는 `entity / task / record`이며 생략은 기록이다. 과거 활동 태그 분리 전환에서는 이름을 두 사전에 보존하고 기록의 태그 ID를 유지하며 할 일에 새 ID를 부여했다. 당시 할 일의 버전을 올려 이전 화면의 쓰기를 막았으며 업무 기록·날짜는 새로 만들지 않았다. 이 전환 이력은 현재 생성·내용 수정에서 초기 태그를 받는 예외가 아니다.

혼합 검색의 태그 사전은 선택한 검색 종류를 따르고 전체 조회에서는 종류를 이름 앞에 표시한다. 사용자가 검색 종류를 바꾸면 이전 태그 조건을 해제한다.

### 상세의 헤더·본문·관계 경계

상세 모달과 오른쪽 상세 패널의 보이는 헤더는 선택한 자료 종류의 현재 이름 또는 `할 일 / 기록`이다. 작성·편집에서도 같은 이름을 유지하며 접근성 이름에는 해당 작업을 포함한다. 짧은 변경 확인창은 수행 행동을 제목으로 유지한다. 오른쪽 탭은 데이터 식별 제목을 유지한다. 보기 본문의 첫 값은 강조한 데이터 제목이며 기록은 제목 속성을 만들거나 본문을 중복하지 않고 원문 자체를 먼저 보여준다.

보기는 제목·본문·속성·사건 정보를 키–값으로 제공하고 데이터 영역 끝에 태그를 둔 뒤 관계 구획을 배치한다. 관계 구획 시작에 공통 1px 경계와 24px 위 여백을 한 번만 사용하고 종류별 목록 사이에는 기존 20px 간격을 둔다. 관계가 없는 화면에 빈 구획을 만들지 않는다. 기존 데이터 편집은 수정 가능한 값·시각을 다루며, 보기의 태그·관계 목록·사건 정보는 같은 위치에 읽기 전용으로 유지한다. 편집 중에는 태그·관계의 검색·연결·해제 조작을 제공하지 않고 편집 저장 요청에서도 해당 관계를 생략해 보존한다. 신규 작성의 초기 관계 선택은 유지한다. 기록 편집은 기존 연결을 저장 요청에서 생략해 보존한다.

관련 상세의 헤더 이전 화살표는 처음 상세로 돌아간다. 오른쪽 상세 탭에서는 처음 탭을 선택하며 현재 탭과 편집 초안을 보존한다. 한 관련 방문에서 링크를 반복해도 출발 탭 하나만 복귀 대상으로 유지한다. 다른 독립 상세에서 기존 탭의 상세 링크를 명시적으로 열면 그 새 출발 상세를 복귀 대상으로 삼으며, 단순한 탭 선택은 복귀 대상을 바꾸지 않는다. 최초 탭을 닫으면 그 복귀 조작을 제거하며 직접 진입·독립 목록 방문의 이전 화면은 추측하지 않는다. 초기 모바일 모달 탐색은 기존 원래 상세·스크롤·초점 복원을 유지한다. 유지된 상세 탭을 모바일 모달로 표시할 때도 같은 복귀 대상과 초안을 사용한다. 저장 중 이동을 막고, 초안을 보존할 수 없는 모바일 경로 이동은 기존 미저장 보호를 거친다.

업무 설정의 저장 단위는 [ADR-0015](../adr/0015-change-record-templates.md), 자료 종류별 불변 자료 번호와 번호 출처·번호 종류는 [ADR-0021](../adr/0021-type-scoped-immutable-identity.md)을 따른다. 기록 자동 완성은 모델·액션·변수 삽입·메모 템플릿·기록 태그만 제공하고 예시 출력은 표시하지 않는다. 실제 변경 확인에는 준비한 메모를 보여준다. 번호 출처 관리는 평평한 펼침 목록을 사용하고, 출처 편집은 출처 이름 옆에 두고, 번호 종류 추가는 소속 번호 목록 헤더에 둔다. 번호 종류의 이름·입력 방식·사용 상태는 한 행에 표시하며, 기존 번호 종류 편집은 해당 행 아래에서 펼친다. 인라인 편집에는 이름·읽기 전용 입력 방식·사용 여부와 기존 번호 보존 설명을 제공하고 삭제는 왼쪽, 취소·저장은 오른쪽에 둔다. 좁은 화면에서는 입력을 세로로 쌓는다. 다른 출처·번호·탭 이동과 접기에는 미저장 확인을 적용하고 진행 중·미확정 요청은 이동을 막는다. 출처 편집·추가와 번호 종류 추가, 자료 종류 안의 보조 편집은 기존 모달 흐름을 유지한다. 번호 종류 이름과 발급 방식이 같은 문구라면 반복하지 않는다. 새 번호 출처의 주요 행동은 `저장하고 번호 추가`다. 첫 저장이 끝나면 `번호 출처를 저장했습니다.`를 표시하고 첫 번호 종류 입력으로 이어진다. 두 쓰기는 별도 작업이므로 `나중에 추가`를 허용하고, 번호 저장 실패·재시도 때문에 번호 출처를 다시 만들지 않는다. 자료 종류에서는 연결된 행마다 `기본` 라디오를 두어 기본 번호 출처를 명시적으로 선택한다. 사용 중지 시 다른 번호 출처를 자동 선택하지 않는다. 연결·번호 출처 추가·번호 종류 추가는 하나의 보조 모달에서 전환하고 이전 선택·부모 초안과 복귀 초점을 유지한다. 사용자 화면에는 `번호 종류`를 쓰고 API의 규칙 식별자와 구분한다. 자료 등록에서 번호 출처 후보가 하나면 선택창 대신 고정 값을 보여주며 앱만 지원하면 번호 출처 선택을 생략한다. 자동 발급 번호는 빈 읽기 전용 입력창 대신 `등록 시 자동 발급`으로 표시한다. 미저장 내용을 버릴 때만 짧은 확인창을 겹친다. 최신 저장값 조회와 미확정 요청 재확인은 해당 충돌·복구 문맥에서 제공한다.

### 조건·선택·숨은 변경의 명확성

검색 조건이 적용된 빈 목록에는 `검색 조건 해제`를 두어 검색어·필터를 풀고 보기 방식은 유지한다. 초기 빈 상태·조회 실패에는 이 행동을 붙이지 않는다. 연결 검색은 이미 선택한 항목·보관 항목을 제외한 실제 후보가 비었는지 확인하고 다음 페이지가 있으면 더 보기를 유지한다. 초안의 선택 목록은 자료 이름·종류·번호 출처와 원본 번호를 사용한다. 내부 복합 키를 사용자 표시로 대신하지 않으며, 조회 실패 시 알려진 이름·초안을 보존하고 재시도를 제공한다.

일회성/반복과 반복 주기처럼 하나를 고르는 입력은 native radio를 칩 문법으로 표현한다. 태그·요일처럼 여러 개를 고르는 조작과 구별하고 방향키·초점·44px 조작 영역을 유지한다. 시간대는 알아볼 수 있는 이름과 IANA 값을 함께 보여주는 공통 선택기를 사용하고 실제 저장 값은 기존 시간대 코드다. 여러 날짜를 쉼표로 입력하는 필드에는 쉼표를 입력할 수 없는 숫자 전용 키보드를 강제하지 않는다. 날짜 배열의 하위 오류도 해당 입력 바로 옆에 표시한다.

기록 자동 완성은 대상별 독립 초안을 유지한다. 같은 대상의 여러 액션을 바꿀 수 있으므로 액션 선택에 미저장·오류를 표시하고 푸터에서 함께 저장·취소할 변경 액션을 보여준다. 오류 항목 보기로 숨겨진 해당 액션을 열고 입력에 초점을 돌린다. 이 표시로 대상별 저장 범위·동시 변경·재시도 계약을 바꾸지 않는다.

### 공통 조작과 읽기 표현의 정합성

체크박스·라디오의 실제 조작 영역은 라벨까지 포함하여 최소 44×44px로 확보한다. 샘플과 실제 폼에 같은 조작 영역 규칙을 사용한다. 확인창의 제목은 dialog-title 역할을 유지하고 본문·헤더·푸터의 좌우 여백을 맞춘다. 버튼은 기본 최소 88px 너비와 44px 높이를 유지하며 긴 문구는 줄바꿈한다. 확대·키보드로 확인창의 가용 폭이 240px 이하가 되면 좌우 여백과 버튼 안쪽 여백을 8px 이하로 줄이고 두 행동을 같은 줄에 유지한다. 이때만 버튼 최소 너비는 44px까지 허용하며 글자 크기와 최소 높이는 줄이지 않는다.

추가 설정·설치 정보 등 업무 목록이 아닌 보조 정보의 Accordion·Collapsible는 키보드 동작을 유지하며 펼침 표시를 마지막 오른쪽 열에 둔다. 제목과 보조 상태가 여러 줄이어도 조작 위치를 유지한다. 업무 데이터 행과 변경·문제 목록은 공통 테이블 규격을 따라 제목 앞의 독립된 조작 열을 사용한다. 설정 메뉴는 기본·자료·태그·기록으로 구성한다. 자료 안에서 자료 종류·연결 설정·번호 설정·일괄 설정을 같은 수준의 탐색 링크로 제공한다. 일괄 설정에서 전체 자료 종류·연결·번호 설정을 가져오거나 내보낸다. 설정 범주 탐색은 주 드로어의 펼친 링크로 제공한다. 현재 자료 설정 하위 화면에서 자료 설정을 누르면 현재 작업을 유지하며 모바일 드로어를 닫는다. 짧은 용어 옆에 의미를 구분하는 한 줄 설명과 실제 예시를 제공한다. 주 드로어는 현재 설정 범주를 배경과 aria-current로 구분하며 Tab으로 링크를 이동한다.

자료의 상세 첫 값은 제목 템플릿으로 계산한 현재 제목으로 강조한다. 그 아래에 제목에 참여한 속성을 포함한 전체 속성을 일반 키–값으로 표시하며 별도 대표 속성을 지정하거나 속성별 강조를 적용하지 않는다. 헤더의 종류 이름은 본문 속성으로 반복하지 않는다. 자료 종류 선택은 조회 범위이며 검색·태그·속성 조건과 구분해 최초 빈 상태를 표시한다. 자동 발급 번호가 비어 있을 때 실행할 수 없는 기존 대상 확인을 제공하지 않는다. 삭제된 대상·종류 없음 등 예외 분기도 앱 내부 탐색과 미저장 보호를 유지한다.

과거 값은 당시 스냅샷으로 읽고 현재 속성 이름으로 임의 재해석하지 않는다. 보존된 사용자 라벨을 우선하며 없으면 안정적인 항목 번호 등 대체 표현을 사용한다. 번호 출처 내부 코드·복합 저장 ID와 사용자 자료 번호 값을 구분하고 0·false·null을 보존한다. 오류는 입력 옆 Field/error-text, 작업 실패 Notice로 표현하며 실제 성공·미확정·재시도 의미를 유지한다.
