# 컴포넌트와 상호작용

[ADR-0012](../adr/0012-current-state-and-unified-records.md)와 [통합 기록 설계](../architecture/unified-record-model.md)가 도메인 계약이다. 엔터티·할 일·원칙·기록 네 탭, 현재 원칙 문서와 추가 로그 없는 기록 편집을 기준으로 화면을 구성한다. 구현과 검증 상태는 관련 GitHub 이슈·PR에서 확인한다.

## 책임과 재사용

각 목록의 늦은 응답은 최신 조건·검색 초안·입력 초점을 되돌리지 않는다. 이전 활동 화면의 두 목록 URL 병합은 호환 전환 검사로 보존하며 새 네 탭에 sibling readiness를 강제하지 않는다. 검색 행과 대체 상태·색인 coverage 안내는 같은 유효 요청이 갱신하며, 무시한 이전 응답이 안내만 덮어쓰지 않게 한다.

[디자인 가이드](guide.md)의 원칙과 [시각 규격](visual-spec.md)의 값을 사용한다. 이 문서는 구조와 행동만 정의한다. 컴포넌트 이름은 배치 예시이며 실제 소비 기능이 생길 때 만든다.

| 공통 표현 | 소유하는 책임 |
| --- | --- |
| PagePanel | 제목·행동·문맥·필터 구획 |
| ModalShell / ConfirmDialog | 초점·스크롤·닫기·미저장 보호의 공통 경로 |
| Field / ReadOnlyField | 라벨·입력·도움말·오류 표현 |
| TagChip | 읽기/선택 표현과 접근성 상태 |
| Timeline | 날짜 그룹·항목 배치 |
| MarkdownContent | 긴 본문의 안전한 표시 |

위 표현은 조회·저장·권한·필터 의미·날짜의 업무 의미를 소유하지 않는다. 기능이 데이터와 상태, 이벤트 처리를 전달한다. 공통 컴포넌트가 서버 업무 규칙을 재구현하거나 범용 폼/CRUD 엔진으로 커지지 않게 한다.

## 페이지와 탐색

상단 패널은 제목과 관련 행동 → 필요한 짧은 문맥·요약 → 필터 또는 문서 본문 순서다. 구획이 없으면 구분선과 여백도 생략한다. 같은 검색·기간·태그 조건은 하나의 필터 구획에 둔다. 꾸미기 위해 모든 페이지에 합계·검색·설명 카드를 추가하지 않는다.

엔터티·활동·원칙의 등록/작성·현재 원칙 편집/보기·해당 태그 관리는 제목 우측 44px 햄버거 작업 메뉴로 제공한다. 현재 원칙 조회 중/실패에는 작성하지 못하며 부재가 확인될 때만 작성한다. 삭제·개별 보기/편집은 상세와 행에서 제공한다. 편집 저장은 해당 편집 영역에 둔다. 메뉴는 선택·바깥 클릭·Escape로 닫히고 키보드로 조작할 수 있어야 한다. 페이지 제목의 시각 크기는 패널형 화면에서 section-title을 쓸 수 있지만 의미상 h1은 유지한다.

탐색 항목·순서·현재 위치 표시는 앱 전역에서 일관되게 관리한다. 모든 폭에서 `[프로필] [엔터티] [할 일] [원칙] [기록] [메뉴]`를 하단에 고정하고 본문 끝 여백과 safe-area를 확보한다. 주요 탭 네 개는 아이콘·글자·현재 위치를 표시하며 상세 URL도 소속된 탭을 표시한다. 기존 /search는 호환 경로로 유지한다. 인증된 작업 화면은 반복 브랜드 헤더를 제거하고 페이지 제목을 문맥으로 사용한다. 로그인·OAuth 동의의 제목은 유지한다.

프로필은 로그인된 계정 이름·이메일·상태와 설정 링크, 메뉴는 사용 가이드·설정 링크를 제공한다. 팝오버는 한 번에 하나만 열며 선택·바깥 클릭·Escape·초점 이탈로 닫는다. 실제 이동은 링크로 제공하고 Tab과 방향키로 보조 항목을 이동한다. Escape와 바깥 클릭은 진입 버튼으로 초점을 돌린다. 프로필/메뉴는 접근성 이름과 44×44px 이상 조작 영역을 제공한다.

설정은 내 계정·고정 SVG 프로필 아이콘·엔터티/활동 태그 관리·연결 안내·로그아웃 순서다. 아이콘의 안정 ID만 Auth metadata workspace_avatar_id에 저장하고 기존 공급자 metadata를 보존한다. 알 수 없는 ID는 기본값으로 표시하고 저장 성공 응답 뒤 하단 아이콘을 반영한다. 실패 초안·미저장 이동/로그아웃 폐기 확인·저장 중 중복 요청과 이동 차단을 제공한다. 계정 변경/로그아웃은 이전 계정 표시와 초안을 지운다. 이름·아이콘 metadata는 권한 근거가 아니다.

같은 계정의 외부 프로필 갱신은 저장값과 하단 표시만 갱신하며 미저장 선택은 유지한다. 깨끗한 선택은 최신 저장값을 따르고, 명시적 변경 취소는 최신값으로 돌아간다. 로컬 저장 성공은 확인한 서버 정본을 선택값으로 채택하고 계정 변경은 설정을 새로 만든다. 프로필 쓰기의 늦은 응답은 provider와 SDK 세션 저장소 양쪽에서 이전 계정을 복원하지 않아야 한다. 장식용 쓰기는 공유 세션과 격리한 SDK 메모리 세션에서 실행한다. 프로필 흐름은 공유 SDK의 세션 조회·refresh·세션 저장을 호출하지 않는다. 표시 정본은 별도 SDK의 명시적 access token 조회로 읽고, 계정 세대·조회 순서와 현재 토큰이 유지될 때 provider의 아이콘 필드만 갱신한다. 저장 후 조회와 외부 hydration은 같은 조회 순서를 사용한다. 오래된 저장 조회의 성공·실패가 더 최신 조회를 덮어쓰거나 무효화하지 않으며, 저장 완료는 진행 중인 최신 조회까지 기다려 확인된 최신값을 설정의 선택값으로 돌려준다. 최신 조회 실패는 오래된 성공값을 채택하지 않고 표시 재조회 실패로 안내한다. SDK 세션 metadata와 표시 정본은 다를 수 있으며 새로고침·재로그인·Auth 이벤트 때도 서버 표시를 조회한다. 다른 탭에는 계정 ID만 알리고 수신 탭이 자기 토큰으로 다시 읽는다. 원본 저장 성공과 표시 재조회 실패는 구분해 알린다. 태그 편집 중 설정으로 이동하는 단계와 설정에서 로그아웃하는 단계도 각각 초안 보호를 따른다.

할 일과 기록은 각각의 탭에서 표시한다. 기록은 일반 자료·수행 결과·로그성 메모의 통합 조회이며 별도 활동 탭은 없다. 이전 /tasks·/records의 혼합 화면은 새 경로 의미와 호환 전환을 검증한 뒤 대체한다. 각 목록의 cursor·더 보기·오류와 조건별 적용 범위를 독립적으로 관리한다. 최초 데이터가 없는 엔터티·할 일·기록은 허용된 작성 행동과 사용 가이드 진입을 제공한다. 조건 결과 없음은 최초 빈 상태와 구분한다.

관련 목록의 `entity_id` URL은 일반 선택 필터와 별개로 기존 관련 조회 범위를 보존한다. 해당 관련 목록과 검색에 같은 범위를 적용하고 owner GET으로 확인한 이름·범위 해제를 짧게 표시한다. 이름을 URL 값으로 신뢰하지 않으며 UUID/조회 실패를 안내한다. 명시 해제 전에는 전역 목록으로 넓히지 않는다. 범위 변경은 해당 cursor·목록 위치를 초기화하고 이전 범위 응답을 무시한다. 검색어·태그·날짜는 해제 후에도 보존한다.

보조 메뉴에서 초안이 있는 화면을 떠나려 하면 확인창이 활성화된 동안 진입 링크를 보존한다. 확인창 안으로 초점을 옮기거나 취소 버튼을 누르는 행동은 메뉴의 일반 바깥 조작으로 취급하지 않는다. 취소하면 같은 메뉴 링크로 초점을 돌리고, 이동을 승인하면 새 경로에서 메뉴를 닫는다.

사용 가이드는 엔터티 → 할 일/기록 → 제품 플러그인 → 검색/원문 → 명시 저장/웹 확인 순서로 제공한다. 엔터티 연결은 선택임을 알리고 MCP OAuth와 제품 스킬 설치를 구분한다. 공개 설정에서 연결 주소와 문서 링크를 생성하고 미설정·복사 실패를 텍스트로 안내한다. 복사가 실패해도 주소를 선택할 수 있다. 클라이언트별 설치는 해당 앱의 검증된 플러그인·배포 문서로 연결하며 웹·desktop·모바일 지원을 추측하지 않는다.

## 필터와 목록

주요 탭은 제목 우측 작업 메뉴 → 검색 입력 → 실제 필터 → 목록 순서다. 검색 버튼과 적용 조건 요약은 없다. 마지막 텍스트 입력/IME 조합 완료 뒤 300ms 자동 반영하며 조합 중 조회하지 않는다. 입력 안 ×로 검색어를 즉시 지우고 입력 초점을 유지한다. 선택·태그·날짜는 즉시 반영하고 입력 지연 중에도 최신 조건을 보존한다. 엔터티는 최신 속성 조회를 사용한다. 기록은 과거 자료 RAG 검색을 사용하고 할 일·원칙의 최신 상태는 해당 도메인 조회로 확인한다. 과거 원칙 근거는 이관된 일반 기록에서 검색한다. 이전 keyword URL도 웹에서는 auto를 사용한다. `/search`는 기존 혼합 검색·방식 선택 호환 화면이다.

필터에는 이름과 적용 범위를 표시한다. 목록에 종속된 요약은 같은 조건을 반영한다. 검색·날짜·태그의 AND/OR, 입력 지연, 적용 시점은 기능 계약으로 정하며 스타일 변경으로 바꾸지 않는다. 잘못된 조건을 조용히 무시해 전체 데이터로 넓히지 않는다.

데이터 행·제목·본문은 선택·복사·스크롤할 수 있게 유지한다. 엔터티·할 일의 제목과 기록의 본문 대표 문구는 보기를 열며 별도의 보기 링크를 반복하지 않고 행 우측에 편집만 제공한다. 연결된 데이터의 제목도 보기를 연다. 일반 기록은 내용 편집, 로그성 기록은 메모 편집을 제공하며 사건 정보는 읽기 전용이다. 원칙은 현재 문서의 조회와 편집을 제공한다. 모달 내부 전환은 button, 실제 URL 이동은 link를 사용하고 접근성 이름에는 행동과 대상을 포함한다.

할 일·원칙은 제목·본문, 기록은 본문 하나를 표시·입력한다. 기록의 대표 문구는 마크다운·개행을 읽기 좋게 정리해 목록·연결에서만 계산한다. 상세 shell 제목은 “기록”이며 원문을 한 번 표시한다. 검색에서는 일치 구간을 미리 보여 준다. 비어 있는 태그·본문에는 빈 구획을 만들지 않는다. 입력 라벨·접근성 구획 이름은 유지하고 연결 당시 출처·시각은 펼치는 보조 정보로 제공한다.

조작 묶음은 제목 뒤 같은 기준선에 이어지고 공간이 부족하면 묶음 전체가 다음 줄로 간다. 터치 영역은 정상 레이아웃 안에 확보하며 투명 영역을 다른 내용 위에 겹치지 않는다. 스크롤을 시작한 터치가 의도하지 않은 상세 열기로 실행되지 않아야 한다. 본문이 이미 펼쳐진 화면에는 불필요한 보기 단계를 추가하지 않는다.

상세를 닫으면 필터·페이지·스크롤·초점을 복원한다. 저장 후 대상이 목록에서 빠지면 다음 유효 항목이나 목록 제목으로 초점을 옮긴다. 더 보기 실패는 기존 목록을 유지하고 실패 구간에서 재시도하게 한다. 소유자/작업 영역 전환 시 이전 대상의 초안과 조회 응답이 섞이지 않게 한다.

긴 자동 복원은 첫 결과·일정 간격·종료 때 누적 행을 표시해 매 응답마다 전체 행의 렌더를 반복하지 않는다. 실패 시에는 아직 화면에 반영하지 않은 묶음까지 정상 수신한 모든 행을 표시하고, 취소·범위 전환 뒤 응답은 무시한다. 요청 cursor 순서·자동 250페이지 상한·그 이후 수동 추가·상세 복귀 초점은 그대로 유지한다.

## 읽기·편집과 모달

| 상황 | 기본 패턴 |
| --- | --- |
| 한 대상의 읽기/편집 | 하나의 1차 모달에서 모드 전환 |
| 일반 편집의 작은 화면 | 전체 화면, 본문 스크롤과 하단 액션 |
| 일반 편집의 넓은 화면 | 중앙 모달, 규격에 따른 폭과 화면 내 높이 |
| 짧은 삭제·변경 버리기 확인 | 모바일에서도 내용 크기의 중앙 확인창 |
| 필수 열 비교를 위한 표 편집 | 명시적인 전체 화면 편집 |

헤더에는 제목과 닫기, 본문에는 현재 대상, 하단에는 취소/저장을 둔다. 조회 전용에 빈 저장 footer를 만들지 않는다. 같은 대상의 속성마다 편집 모달이나 저장 버튼을 따로 만들지 않는다.

등록·보기·편집은 640px 미만 전체 화면, 이상 중앙 최대 42rem의 같은 shell을 쓴다. 헤더와 footer는 surface 안에 고정하고 본문만 스크롤한다. 짧은 확인창은 모든 폭에서 중앙 최대 28rem이다. 동적 viewport·키보드에 따라 가용 높이를 계산하고 safe-area 여백을 둔다. 읽기와 편집은 한 native dialog를 유지하며 모드만 바꾼다. URL의 `create`와 `edit` 상태를 새로고침·직접 링크·뒤로가기·앞으로가기에 반영한다. 엔터티의 관련 할 일/기록 작성도 이 shell의 작성 모드로 전환한다. 일반 취소·폐기 승인으로 닫으면 작성 query를 제거해 새로고침이 취소된 폼을 다시 열지 않게 하며 기존 상세 조건을 유지한다.

상세 보기는 기본 정보·본문·관련 정보를 제목, 여백, 구분선으로 나누어 읽는다. 짧은 속성은 항목명과 값을 정렬하고 태그는 작은 칩, 연결된 데이터는 제목 중심의 목록으로 표시한다. 엔터티 보기는 속성과 태그, 관련 할 일·기록을 제공한다. 관련 작성은 해당 구획에, 반복 회차 기록과 기간 이동은 회차 목록에 둔다. 일회성 완료·반복 중단/재개는 보기 푸터에 둔다. 편집은 입력과 저장에 집중하며 삭제는 편집 푸터 왼쪽, 저장 진행 버튼은 오른쪽에 둔다. 헤더는 제목과 공통 닫기를 제공하고, 이전 상세 또는 검색 결과에서 이동한 보기에는 왼쪽 이전을 제공한다. 보기에서 편집에 진입하면 닫기·저장 후 보기로, 목록의 편집으로 진입하면 목록의 조건·페이지·스크롤·초점으로 돌아간다. URL과 브라우저 뒤로가기·앞으로가기도 이 진입 문맥을 유지한다. 편집 제거를 반영한 뒤 이동해 미저장 보호와 충돌하지 않게 한다.

### 상세 탐색의 이전과 닫기

엔터티·할 일·기록·원칙과 앞으로 추가하는 상세 화면은 **상세 모달 하나에서 경로를 바꾸며 탐색**한다. 연결 대상을 새 상세 모달로 겹쳐 열지 않는다.

| 행동 | 결과 |
| --- | --- |
| 왼쪽 `←` 아이콘 | 직전 상세 또는 검색 결과로 한 단계 복귀하며 스크롤과 눌렀던 항목 초점을 복원. 접근성 이름에는 이전 대상 포함 |
| 오른쪽 `×` 아이콘 / Escape | 현재 데이터가 속한 탭의 목록으로 탐색 종료. 같은 목록의 조건·페이지·위치가 있으면 유지. 접근성 이름은 닫기 |
| 브라우저 뒤로가기·앞으로가기 | 실제 경로 이력의 이전·다음 단계 |
| 목록에서 연 첫 상세 / 이력이 없는 직접 링크 | 이전을 만들지 않고 닫기만 제공 |
| 보기에서 연 편집의 닫기·저장 | 같은 보기로 복귀하며 상세 탐색 이력을 유지 |
| 삭제·미저장 확인의 취소 | 아래 화면과 초안·초점 유지 |

엔터티 A → 할 일 B → 기록 C에서 이전은 C → B → A이며, C의 닫기는 기록 목록이다. 검색 → 기록에서도 이전은 검색 결과, 닫기는 기록 목록이다. 데이터 종류에 따라 복귀 의미를 바꾸지 않는다. 이전 화면의 항목이 사라진 경우 유효한 제목·화면 위치로 복귀한다. 저장 중 이동은 차단하고 미저장 입력의 이동은 기존 폐기 확인을 거친다.

구현 정본은 `src/lib/detail-exploration.tsx`다. `DetailLink`가 브라우저 history entry의 경로 스택에 출발 화면을 추가하고 `DetailSurface`가 이전을 표시한다. `useDetailNavigate`는 같은 상세의 편집·작성 모드 변경을 같은 entry에 반영하고 문맥을 보존하며, 상세 종료는 현재 entry를 목록으로 교체한다. 따라서 닫기 직후 뒤로가기에서 방금 닫은 상세를 다시 여는 entry를 추가하지 않는다. 이력에는 계정 범위를 붙여 다른 계정의 스택을 표시·복원·목록 복귀에서 무시한다. 스택에는 경로·제목·스크롤·초점 위치만 저장하고 데이터 객체·폼 초안·dialog DOM을 저장하지 않는다. DB·localStorage·별도 전역 라우터를 만들지 않는다. 계정별 provider는 위치 복원만 지원하며 세션 전환 시 폐기된다.

새 상세 경로는 공통 상세 경로 판별에 등록하고, 연결 상세와 검색 결과의 링크는 `DetailLink`, 상세 안의 모드/종료 이동은 `useDetailNavigate`, 화면은 `DetailSurface`를 사용한다. 같은 대상을 가리키는 링크가 여러 개면 역할별 `restoreKey`를 지정해 실제 진입한 링크를 식별한다. 화면별로 이력 스택·닫기 버튼·복귀 정책을 다시 구현하지 않는다. 실제 경로 이력을 공유하므로 이전은 확인된 앱 내 출발 경로가 있을 때만 제공한다. 새 탭의 직접 링크는 이전을 추측하지 않는다.

읽기에서 편집으로 바꿀 때 두 편집 모달을 겹치지 않는다. 편집 완료/취소 후에는 진입한 읽기 또는 목록으로 돌아간다. 삭제는 별도 모달 없이 해당 버튼 첫 클릭에서 설명·선택 이유·취소와 함께 `삭제 확인` 상태로 전환하고, 두 번째 클릭에서 요청한다. 확인 중 편집 저장과 내용 변경, 요청 중 이동·중복 실행을 막는다. 실패 시 입력과 확인 상태를 유지하며 응답 미확정은 같은 입력·버전으로 재시도한다. 일반 편집 위의 2차 모달은 미저장 폐기 의사 확인에 한정한다. 태그 관리·관련 대상 탐색 같은 일반 폼을 2차에 넣지 않으며 3차 모달은 만들지 않는다. 평범한 저장마다 추가 확인을 강제하지 않는다.

기록 상세는 본문 → 사건 종류·출처·수행 시각과 대상 → 연결 항목 → 펼치는 저장 정보 순서로 읽는다. 본문은 일반 본문 크기와 대비를 사용하며 종류·시각은 작은 보조 글자, 연결 제목은 명확한 링크로 구분한다. 포괄적인 ‘관련 정보’ 제목과 중복 시각을 반복하지 않는다. 생성·수정 시각과 기록 편집의 효과 설명은 저장 정보 안에 둔다. 빈 연결 구획은 만들지 않는다.

최상위 대화상자 하나만 키보드와 접근성 트리에서 활성화한다. 뒤 화면은 inert 처리하고 초안·스크롤을 보존한다. Escape·닫기·뒤로가기는 같은 미저장 보호를 거치며 배경 클릭으로 초안을 버리지 않는다. 확인 취소는 원래 초점과 초안으로 돌아간다.

앱은 지원되는 data router를 사용하고 편집 영역의 `useBlocker`로 링크·브라우저 뒤로가기 등 경로 이동도 같은 초안 보호에 연결한다. 로그아웃은 먼저 보호 가능한 경로 이동을 거친 뒤 인증 세션을 해제하며 직접 세션 해제로 초안을 제거하지 않는다. 새로고침·탭 닫기는 `beforeunload`로 보호하되 브라우저가 허용하는 기본 확인창과 사용자 상호작용 조건에 의존하므로 앱 확인창과 같은 표시를 보장하지 않는다.

경로의 검색 조건 변경·뒤로가기·앞으로가기도 초안이 있으면 같은 확인을 거친다. 확인 취소는 현재 URL·초안·초점을 유지한다. 열린 1차 편집 영역이 blocker를 소유하며 닫힌 모달·그 위의 짧은 확인창은 추가 blocker를 등록하지 않는다. 일반 shell 없이 목록에서 실행하는 단독 삭제는 요청의 pending ref를 읽는 busy guard 하나로 경로·POP·beforeunload를 보호한다. 이 guard는 요청 완료 전 이동을 취소하며 초안 폐기 확인을 만들지 않는다. 저장 중 경로 이동 시도는 취소해 저장이 끝난 뒤 이전 이동 의도가 실행되지 않게 한다. 저장 성공과 확인된 취소 뒤의 의도된 이동은 편집 영역이 제거된 다음 실행하며 사용자 이동 보호를 우회하는 공개 상태 플래그를 만들지 않는다.

경로 이동의 폐기 확인은 같은 컴포넌트를 재사용하는 검색 조건 변경에서도 편집 영역을 닫거나 초안을 초기화한 뒤 의도된 경로로 진행한다. `onRouteDiscard`는 편집 영역만 닫는 콜백이며 별도 이동을 실행하지 않는다. 일반 `onClose`가 목록 복귀를 예약하는 화면은 순수 닫기 콜백을 반드시 별도로 제공해 폐기 확인의 목적지와 경쟁하지 않게 한다. 이동이 없는 단순 닫기만 `onClose`를 공용으로 쓴다.

복귀는 공통 header의 이전·닫기 규칙으로 제공하고 `← 목록`·`목록으로`·폼 footer 취소 같은 중복 복귀 조작을 만들지 않는다. 저장·삭제 확인·미저장 확인 취소 등 업무 조작은 유지한다. 닫기는 `ModalShell`의 보호된 요청을 사용하며 기능의 `onClose`를 직접 호출해 미저장 보호를 우회하지 않는다. 조건부 렌더링으로 모달을 제거할 때도 닫기 정리와 진입 버튼 초점 복귀를 수행한다. 확인창은 숨긴 읽기 영역과 별개로 표시하고 취소하면 편집 초안과 원래 버튼 초점으로 돌아간다. 연결 작성 뒤 엔터티 보기를 다시 준비할 때는 준비가 끝난 뒤 원래 작성 버튼에 초점을 돌린다.

모달 본문의 바깥 panel/card 테두리·배경·그림자는 제거하고 입력 경계와 코드/표 영역만 유지한다. 모든 scrollbar 표시를 숨기되 overflow의 실제 스크롤은 유지한다. 세로 wheel·PageDown·터치와 긴 코드/GFM 표의 내부 가로 스크롤을 제공하며 페이지 전체 넘침을 숨기지 않는다. MarkdownContent는 GFM 표·읽기 전용 체크리스트를 지원하고 raw HTML 실행·위험 URL·외부 이미지 자동 요청을 차단한다.

저장 중에는 중복 제출과 안전하지 않은 닫기를 막고 진행 상태를 보인다. 실패 시 초안을 유지한다. 응답 유실·시간 초과는 성공 여부 미확정 상태를 다룰 수 있어야 하며 영구적으로 화면을 잠그지 않는다. 재조회·재시도는 서버 멱등성 계약을 따른다. 네트워크 취소가 서버 rollback을 뜻한다고 표시하지 않는다.

엔터티 상세는 속성·태그·연결된 할 일/기록과 `할 일 작성`·`기록 작성`만 제공한다. 전체 목록 링크, 저장/작성 성공 안내, 엔터티 수정 시각과 장식 구분선은 반복하지 않는다. 조회/저장 오류와 재시도는 유지한다.

## 폼

작성은 종류(필요한 경우) → 할 일·원칙의 제목·본문 또는 기록 본문 → 연결 대상·태그·일정 순서이며 한 초안·한 저장을 유지한다. 라벨 → 값 → 오류 순서다. 글자 수·숫자 범위·비우면 미지정 같은 상시 부연 설명은 제거하고 검증 실패 시 해당 필드에 안내한다. 필요한 예시는 placeholder로 제공한다. placeholder로 라벨을 대신하지 않는다. 짧은 읽기 전용 속성도 같은 라벨·높이·정렬을 사용하되 읽기 전용 상태를 알리고 선택·복사를 허용한다. disabled는 일시적 조작 불가와 구분한다. 긴 기록·설명은 입력칸 모양으로 감싸지 않고 본문으로 읽힌다. 업무 변경 메모는 편집 마지막의 선택 입력으로 둔다. 단일 저장 버튼으로 제출하며 삭제 의사 확인·미저장 보호·불확실한 응답의 같은 시도 재전송을 유지한다.

할 일·기록의 엔터티 연결은 제목 검색 후 선택한다. 입력 전에는 전체 목록을 읽지 않고 대소문자를 구분하지 않는 부분 일치로 후보를 찾는다. 300ms 지연과 IME 조합 처리를 적용하고 결과를 페이지 단위로 추가한다. 이미 선택한 엔터티는 검색어·결과·조회 실패와 독립적으로 표시·해제한다. 기존 연결의 저장된 제목을 보존하고 이름이 없는 선택 ID만 따로 조회한다. 오래된 검색 응답이 현재 후보를 바꾸지 않게 한다.

오류는 해당 필드 또는 폼 가까이 표시하고 label/aria-describedby로 연결한다. 필수 입력은 바로 보이게 한다. 선택 영역을 접었다면 값과 오류의 존재를 알리고 검증 실패 시 펼쳐 접근할 수 있게 한다. 늦은 조회나 저장 실패가 사용자의 입력을 덮어쓰지 않게 한다.

업무 변경의 기본 메모는 저장 전에 자동 완성하고 사용자/에이전트가 보충·수정한 최종 메모와 업무 변경을 함께 저장한다. 일반 기록과 로그 메모 편집은 추가 로그를 만들지 않는다. 메모 길이 등 입력 한도는 새 서버 계약과 함께 확인하며 임의로 축소하지 않는다. 현재 원칙 저장은 최신 값 갱신이다. 응답 유실 뒤에는 제출한 초안을 고정하고 같은 내용·요청 키로 재시도한다. 버전 충돌은 초안을 유지하고 명시적으로 폐기한 뒤 최신 원문을 읽는다.

위험 행동은 일반 저장과 구분하며 확인창에 대상과 실제 영향을 적는다. 버튼 이름은 `확인`만 쓰기보다 `삭제`, `변경 버리기`처럼 결과를 표현한다.

## 태그

엔터티 태그와 활동 태그는 서로 다른 사전이다. 같은 이름이 두 범위에 있어도 ID·선택·필터를 혼용하지 않는다. 관리 URL은 `/tags/entity`, `/tags/activity`이며 기존 `/tags`는 활동 범위 호환 경로다. 원칙에는 태그를 제공하지 않는다.

읽기 정보, 선택/필터, 사전 관리를 구분한다. 읽기 칩은 조작 버튼처럼 보이지 않게 하고 누른다고 임의로 필터를 바꾸지 않는다. 행의 주 대상 이름이라면 작은 칩 대신 제목 역할을 사용한다.

선택 칩은 고정 곡률과 줄바꿈 배치로 표현한다. 단일/다중 선택은 기능 계약을 따르고 aria-pressed 또는 적절한 선택 의미, 그룹 이름, 키보드 초점을 제공한다. 선택은 테두리·배경으로 표시하며 상태 변화 때문에 빈 아이콘 자리나 새 상단 행이 생기지 않게 한다. 활동 필터 태그는 최대 10개 복수 OR이며 재클릭으로 해제하고 별도 모두 포함/선택 해제 조작은 없다. 10개 선택 시 미선택 칩만 비활성화하고 해제 가능한 선택 칩과 한도 안내를 유지한다. 초과한 기존 URL은 처음 조회부터 10개만 적용하고 URL을 정규화하며 변경 사실을 안내한다. 엔터티 필터는 기존 단일 선택이며 폼 연결 선택의 최대 10개·전체 해제는 유지한다.

목록은 최초 태그 사전 응답 뒤 읽기 위치를 복원하고, 실패 재시도 중 기존 행을 유지한다. 목록 사전 오류와 재시도는 필터 구획에서 안내하고 행에는 짧은 읽기 상태만 표시한다. 응답으로 이름 줄바꿈이 바뀌면 현재 읽던 행의 화면 위치와 초점을 유지한다.

ID로 선택을 유지하고 이름 변경으로 선택을 잃지 않는다. 긴 이름은 줄바꿈하며 tooltip만으로 전체 이름을 제공하지 않는다. 연결 선택은 부모 초안에 반영하고, 태그 생성·이름 변경·삭제는 별도의 1차 관리 화면에서 다룬다. 버튼 안에 삭제 버튼을 중첩하지 않는다. 검색이나 대량 탐색이 필요한지는 실제 태그 수와 사용 흐름으로 결정한다.

태그 관리는 공통 모달 shell 하나로 열고 닫기·Escape는 진입한 목록/설정의 조건·읽기 위치·초점으로 돌아간다. 직접 URL 진입은 엔터티 태그는 엔터티 목록, 활동 태그는 할 일 목록으로 닫는다. 새 태그 입력란에서 바로 추가하고 선택한 행에서 이름을 변경한다. 별도 보기·등록·이름 변경 모달은 만들지 않고 한 초안·한 저장을 유지한다. 선택 전환·취소는 미저장 보호를 공유하고 삭제는 현재 화면 안에서 두 단계로 확인한다. 삭제 실패 후에는 확인 상태·입력·버전을 유지하며 자동 목록 재조회로 실패한 행을 제거하지 않는다. 불확정 생성은 같은 내용과 요청 ID로 재시도하며 확인 전 입력 변경을 막는다. 이름 변경의 불확정 응답은 ID로 최신 목록을 확인하고 충돌에는 초안을 유지한다. 저장 성공과 후속 목록 조회 실패를 별도로 표시하며 조회 실패가 저장 성공을 실패로 바꾸거나 기존 목록을 지우지 않게 한다.

중복 이름과 버전 변경은 같은 오류 코드라도 구분한다. 중복 이름은 이름을 정정한 뒤 같은 초안에서 저장할 수 있으며 버전이 실제로 달라졌을 때만 최신 태그를 다시 선택하게 한다. 저장·삭제 뒤 재조회가 시작되면 이전 더 보기 응답은 취소하거나 무시해 새 정렬 경계·커서를 덮지 않게 한다.

## 현재 원칙과 활동 기록

원칙은 계정 전체의 현재 문서 0개 또는 1개다. 현재 값의 등록·편집·삭제를 제공하고 과거 변경은 통합 기록에서 확인한다. 삭제 시 이전 원칙을 자동 승격하지 않는다. 원칙을 판단에 참고한 설명은 정말 필요할 때 기록 본문에 쓰며 적용 원칙 키/snapshot 선택 UI를 요구하지 않는다.

기록 화면에서 일반 자료·수행 결과·로그성 메모를 읽고 검색하며 작성·편집은 같은 탭의 폼/모달로 진행한다. 메모에는 필요한 전체 내용 또는 변경점을 같은 형식으로 작성한다. 일반 기록 내용과 로그 메모는 편집 가능하고 편집 로그는 생성하지 않는다. 로그의 사건 시각·대상·행동은 읽기 전용이며 원래 업무 상태를 되돌리지 않는다. 수정된 내용은 검색에도 반영한다.

변경 기록의 저장된 경로는 당시 정보이며 현재 대상의 존재를 보증하지 않는다. 상세에서 종류·ID의 정본 GET이 성공했을 때만 원문 링크를 제공한다. 404 not_found는 삭제와 권한에 따른 비공개를 구분하지 않고 “삭제된 대상 또는 접근할 수 없는 대상”으로 표시한다. 다른 조회 실패는 현재 상태를 확인하지 못했다고 알리고 GET 재시도를 제공하며 삭제로 단정하지 않는다. 당시 제목·전후·출처·메모·경로는 이 조회로 수정하지 않는다. 목록은 대상별 추가 조회 없이 당시 행동만 표시하며 상세의 늦은 응답은 다음 대상에 반영하지 않는다.

## 타임라인과 긴 본문

시간순 기록에만 날짜 그룹을 사용한다. 검색 결과·할 일 목록을 모두 타임라인으로 강제하지 않는다. 날짜 제목 아래 기록을 얇은 구분선과 여백으로 나누고 카드 중첩을 만들지 않는다. 각 기록은 본문 대표 문구 → 검색 일치 구간(검색 결과일 때) → 종류·시각·관련 정보·태그 순서로 읽으며 편집 링크 위치를 통일한다. 전문은 상세에서 읽는다. 날짜·시각·제목·미리보기·조작 위치를 일관되게 둔다. 장식 점과 선은 aria-hidden으로 처리한다.

그룹 날짜와 시각은 업무 시간대로 표시하며 서버의 안정 정렬을 유지한다. 템플릿 기록에는 별도 시간대 필드가 없으므로 기존 웹 시각 표시와 같은 브라우저 시간대를 쓰고 목록에 그 기준을 명시한다. 연결된 반복 할 일의 시간대는 그 할 일의 회차 날짜만 결정하며 기록 그룹에 적용하지 않는다. 페이지가 같은 날짜로 이어지면 기존 그룹에 합치고 항목 중복·접힘 초기화를 방지한다. 일부만 받은 그룹의 개수를 전체 건수처럼 표시하지 않는다. 날짜 그룹은 항상 펼쳐 표시하고 날짜 접기 조작은 제공하지 않는다. 검색은 관련도 기반으로 페이지를 회수하고 회수한 항목만 발생/저장 날짜별로 표시한다. 화면의 날짜 정렬이 검색 전체를 날짜순으로 회수한다는 뜻은 아니다.

마크다운은 공통 렌더러로 문단·제목·목록·인용·링크·표·코드를 표시한다. raw HTML과 실행 가능한 URL을 실행하지 않는다. 초기 기본은 외부 이미지를 자동 로딩하지 않고 대체 텍스트/안전한 링크로 제공한다. 코드와 넓은 표만 내부 가로 스크롤을 허용한다. 줄임은 목록 미리보기에 한정하고 원문 자체는 변경하지 않는다.

## 상태 표현

| 상태 | 표현과 복귀 |
| --- | --- |
| 최초 로딩 | 로딩 안내, 빈 데이터로 단정하지 않음 |
| 데이터 없음 | 무엇을 만들 수 있는지와 허용된 첫 행동 |
| 필터 결과 없음 | 조건을 유지하고 해제/변경 제공 |
| 조회 실패 | 원인 범주의 짧은 안내와 재시도. 기존 자료가 있으면 유지 |
| 저장 중/실패 | 진행·오류와 초안 유지. 중복 실행 제어 |
| 비동기 접수/처리/완료/실패 | 실제 서버 상태에 맞는 문구와 가능한 재시도 |
| 검색 지연/장애 | 색인 미반영 또는 대체 검색 여부를 표시 |

원본 저장 성공 뒤 최신 조회가 실패하면 저장 완료와 조회 실패를 함께 알리고 조회만 재시도한다. 이전 자료는 유지하며 재조회 응답이 편집 초안이나 더 최신의 저장 결과를 덮어쓰지 않게 한다.

일시 알림만으로 중요한 실패나 삭제 영향을 전달하지 않는다. 상태 문구의 크기는 시각 규격을 따르고 기능별로 임의의 배지 색·로딩 패턴을 만들지 않는다.
